# 个人站点

一个静态个人网站：文章 + 手记 + 标签 + 归档 + 关于 + 友链。
用 [Astro](https://astro.build) 构建，托管在 GitHub Pages 上，**完全免费，没有服务器，没有数据库**。

所有内容都是仓库里的 Markdown 文件——你写的每一个字都在自己手里。

---

## 一、日常怎么用

装好之后，你平时只需要双击根目录下的**一个**文件：

**`花娅陌质流.cmd`**

双击后会弹出一个蒸汽波风格的小窗口，用鼠标点就行：

```
   花娅陌质流
   ──────────────────────────────────────────────────────

   依赖 ● 已就绪     备份 ● 已连接

   ──────────────────────────────────────────────────────

     ┌──────────────┐   ┌──────────────┐
     │   写 文 章    │   │   看 效 果    │
     │ 打开编辑器…   │   │ 在浏览器里…   │
     └──────────────┘   └──────────────┘
     ┌──────────────┐   ┌──────────────┐
     │   发布上线    │   │   首次设置    │
     │ 提交并推送…   │   │ 检查环境…     │
     └──────────────┘   └──────────────┘
```

**写文章**　打开可视化编辑器，在浏览器里写文章、传图片（`http://localhost:4322`）。
**看效果**　在浏览器里看站点真实效果（`http://localhost:4321`）。
**发布上线**　提交并推送到 GitHub，一两分钟后线上更新。
**首次设置**　**只跑一次**。检查环境、安装依赖。

窗口顶部两盏小灯显示当前状态：依赖装没装、有没有连上 GitHub。
没装依赖就点前三个，它会提醒你先做首次设置。

按钮点下去之后会切到一个日志页，命令的输出实时显示在那里，
左上角「返回」回主界面，右上角「停止」可以中断（比如关掉预览服务）。
按 `Esc` 也能退出。

> 第一次用之前，需要先装 **Node.js LTS**（<https://nodejs.org/>）、
> **Git**（<https://git-scm.com/>）和 **Python 3**（<https://www.python.org/downloads/>，
> 安装时**必须勾上 `tcl/tk and IDLE`**，否则画不出窗口）。都是一路点「下一步」。
> 装完再双击 `花娅陌质流.cmd`，点「首次设置」。

如果你更喜欢命令行，对应的命令是：

```bash
pnpm install      # 安装依赖
pnpm editor       # 打开编辑器
pnpm dev          # 本地预览
pnpm build        # 手动构建到 dist/
pnpm preview      # 预览构建结果
```

窗口里的每个动作也能单独从命令行跑（万一图形界面起不来）：

```bash
node tools/menu.mjs setup      # 等同于「首次设置」
node tools/menu.mjs publish    # 等同于「发布上线」
```

> 界面是用 Python 自带 tkinter 手绘的（`tools/studio/studio.py`），
> 不依赖任何第三方库。配色取自一张参考图，逐带采样得到。

## 三、改美术：只改一个文件

打开 `src/styles/tokens.css`，里面全是变量，含义都有中文注释。改完保存，本地预览会立刻刷新。

最常改的几个：

```css
--c-accent: #b4532a;   /* 强调色，整站唯一的彩色 */
--c-bg: #fbfaf8;       /* 页面底色 */
--c-text: #1f1d1a;     /* 正文颜色 */
--font-display: ...;   /* 标题字体 */
--w-prose: 42rem;      /* 正文宽度，写小说可以调窄一点 */
--r-md: 8px;           /* 圆角，想要方块感就改成 0 */
--shadow-md: ...;      /* 阴影，想要完全扁平就改成 none */
```

暗色主题在同一个文件下方的 `:root[data-theme='dark']` 区块里。

**暗色不是靠系统设置切换的**，而是靠 `<html>` 上的 `data-theme` 属性——右上角那个按钮可以在
「自动 → 亮色 → 暗色」之间循环，选完记在浏览器本地。所以：

- 想改暗色配色：改 `:root[data-theme='dark']` 里那些值，别去改媒体查询
- 只想要亮色：删掉整个 `:root[data-theme='dark']` 区块，再删掉页头的主题按钮

### 改颜色时的两个坑

**1. `--c-text-faint` 不能随便调亮。** 它是全站最弱的文字（日期、栏目标题、页脚版权），
需要同时满足在 `--c-bg` 和 `--c-bg-sunken` 两种底色上都达到 WCAG AA 的 4.5:1。
当前值在两种底色上都是 4.6:1，已经贴着下限了。调亮一点就会不达标。

**2. 代码高亮同时配了两套主题。** 见 `astro.config.mjs` 里的 `shikiConfig`：

```js
themes: {
  light: 'github-light-default',
  dark: 'github-dark-default',
}
```

只配一套的话，在另一种主题下 token 颜色会和代码块背景撞在一起——浅色的字配浅色的底，
几乎看不见。这是构建期发现不了的，必须真的渲染出来才知道。

配色规则写在 `global.css` 的「代码高亮双主题取色」那段，按 `data-theme` 选用
shiki 输出的 `--shiki-light` / `--shiki-dark` 变量。如果换了主题名，那段里针对
注释色的那条规则（`--shiki-light:#6e7781`）可能就失效了，需要重新核对对比度。

想放自己的字体：把字体文件丢进 `public/fonts/`，然后在 `global.css` 顶上加一段 `@font-face`。

### 卡片和标题上的字放不下时怎么办

**不要用省略号截断：先换行，再不行就缩字号。** 这条对以后新加的组件一样算数。

子版块卡片的标题原来写的是：

```css
overflow: hidden;
text-overflow: ellipsis;
white-space: nowrap;
```

窄栏里就截成「龙历院花娅…」。卡片名字本身就是导航，截了等于没写 ——
点进去之前根本不知道是哪一张。现在换成：

```css
overflow-wrap: anywhere;   /* 换行；顺便管住一长串没空格的英文/数字 */
text-wrap: balance;        /* 折成两行时断得均匀些，老浏览器忽略即可 */
```

还不够就缩字号，而且要用**容器查询**按卡片自己的宽度缩，不要用 `vw`：

```css
.card { container-type: inline-size; }
@container (max-width: 150px) { .card .card__label { font-size: 0.86rem; } }
```

为什么不用 `vw`：同一张卡在宽栏里占满一行、在窄栏里只剩一百来像素，
视口多宽对它没有意义，只有「这张卡自己多宽」问得准。
阈值要定得偏小 —— `@container` 量的是**内容盒**，定高了会把本来放得下的字
也缩小，观感白白变差。换行才是主力手段，缩字号只是兜底。
实现在 `SubCard.astro` 的 `.card__label`，面板清单（`NodeView`）、
竖排大卡、子页面块（`PageContent`）三处共用同一套。

两个具体的坑：

1. **`white-space: nowrap` 配上 `flex: 1` 的兄弟元素，结果是「溢出」不是「裁掉」。**
   页面内容里的「分隔线」块就是两边各一条线、中间夹一句话：字太长时两条线先缩到 0，
   然后再没得缩，整句话被顶到容器外面去。所以那里也去掉了 `nowrap`。
2. **日期、时长这类定长字段该留 `nowrap` 就留着**，别跟着一起改 ——
   `2026 年 9 月 14 日` 折成两行比省掉更难读。

### 首页背景的动效在哪改

首页那片蒸汽波背景是**分层**的，每层各自动。样式都在 `src/pages/index.astro`
的 `<style>` 里，塔吊单独在 `src/components/HomeCranes.astro`：

| 层 | 在动什么 | 想调就找 |
| --- | --- | --- |
| 天空 | 色带缓慢上下流动、染色慢慢明灭 | `@keyframes sky-flow` / `sky-tint` |
| 落日 | 条纹微微上下游移、辉光呼吸、整体缓缓浮动 | `sun-stripes` / `sun-halo` / `sun-float` |
| 扫描线 | 8×32 硬边贴图按一个周期往下滚（CRT） | `scan-roll`；线宽/快慢改 `.vapor` 里的 `--scan-period` / `--scan-speed` |
| 塔吊 | 三台各自回转横臂（2026-09-18 调快调大过，见下） | `crane-slew`；快慢改每台的 `--dur` |
| 鸟群 | 每隔十几秒有一群鸟飞过天空（见下一节） | `src/components/HomeBirds.astro` |
| 水面 | 倒影被切成横向条带左右错动、碎金闪、岸线明灭 | `reflect-chop` / `glitter-a` `glitter-b` / `shore-glow` |
| 天际线 | 页面滚动时整片轻微上移（CSS 滚动驱动，无 JS） | `.vapor__sea` 那段 `is:inline` 样式 |

> 塔吊的回转在 2026-09-18 按用户要求调快了：周期 36/50/30s → **20/28/17s**，
> 幅度按同一比例放大（旋转 ±2.4° → **±4.6°**，横臂 `scaleX` 最短 0.906 → **0.821**）。
> 「原来几乎看不出在动」是当时的反馈，所以两项是等比放大的，节奏关系没变。

### 天空里的鸟群 —— **现在关着**（代码一行没删）

用户 2026-09 的原话：

> 鸟群出现有点突兀 还是需要优化 但是暂时没有想好设计 所以你先把首页出现鸟群这一点
> 关掉吧 注意只是关掉这个功能先不要删掉它们的代码！！

所以现在的状态是「关掉、不删」：

- 总开关是 `src/components/HomeBirds.astro` 里的 **`FLOCKS_ENABLED = false`**，
  改回 `true` 就完全恢复原样 —— 调度、队形、飞行带、点击兜底那套代码**一行没删**。
- 组件照样挂在 `index.astro` 里（DOM 保留），运行时在根节点写 `data-flocks="off"`，
  核对脚本就是读这个值。
- **`?birds=1` 这个调试口不受开关影响**：想单独看鸟群、或者给新设计挑参数时照放一群；
  正常访问（不带参数）一只都不放 —— `home-statue-check` 等 9 秒确认 `flock 0 / bird 0`
  （老行为是首屏 3~7 秒就该来一群，等 9 秒足够说明问题），同一脚本还会验 `?birds=1`
  仍然放得出鸟，证明**关掉的只是默认行为，代码是活的**。

下面是它关掉之前的样子，要开回来时看这段。

首页天上每隔 **12~26 秒**会飞过一群鸟，随机挑一种、一群 3~7 只，从左往右或从右往左。
四种鸟按**飞行剪影**的特征画成 SVG（一个 body 加上下两个翅膀姿势，靠 opacity 步进切换扇翅）：

| 鸟 | 飞行时的辨识特征 |
| --- | --- |
| 夜鹭 | 粗胖、驼背缩颈，嘴长而尖，宽圆翅扇得慢，脚短往后拖 |
| 白头鹎 | 最小最圆胖，短圆翅，中等尾，飞起来一波一波 |
| 八哥 | 流线型、尖翅、短方尾，额前一小撮冠羽 |
| 喜鹊 | 长尾约占全长一半，宽翅，初级飞羽末端分开像手指 |

鸟和楼群、塔吊用的是**同一支墨**（`var(--ink)` = `#08020c`），所以从楼后穿过时是同一片黑。
它们画在 `.vapor__sea` 的第一层：先于楼群绘制（会被楼挡住），又是 `.vapor__sea` 的子节点，
所以在跟着那片一起做滚动视差。飞行带是 `.vapor__sea` 高度的 **-46%~46%**：
**负数是飞到天际线容器顶边以上**（所以 `.birds` 不能加 `overflow:hidden`，
裁了就只能在天际线那一小条里飞）—— 屏幕上半部分因此也看得到鸟。

**手机竖屏要单独算飞行高度**（用户反馈"手机端鸟飞得非常低，几乎在城市里面甚至最底下"）：
鸟群容器 `.birds` 其实铺在**水面那一层**上，`--y` 是那层高度的百分比。桌面上水面层在
视口 48% 处、有 465px 高，那条 `[-46, 46]` 的带子正好落在天空里；手机竖屏（390×844）
水面层被压到视口 **76.8%**、只有 **196px** 高，同一条带子等于把鸟按在 67%~78% ——
正好压在城市剪影（76.8% 起）上。窄屏（≤720px）改成**按天空实际高度算**：
取天空高度的 12%~45% 再换算回水面层的百分比（桌面一像素未动）。

几个实现上的坑，写在这儿免得以后重踩：

- **那张图的棋盘格是画进像素里的，没有 alpha 通道**，得自己抠。而且判据不能是
  「等于棋盘两色之一」：生物身体是白的，和亮格同色，洪泛一漏进身体，整块白体都会被当成背景
  （实测前景只剩 15% 的线稿）。正确做法是用**棋盘的周期规律**（36px 周期、18px 方块、
  相位 (6,6)，算得出每个像素该是亮格还是暗格）判背景，再把"非棋盘"膨胀 2px 把 1px 线稿的缝
  封住、从边界洪泛、取补集 —— 得到完整实心剪影（实心占比 54% 正常）。
- **抠图必须在原分辨率上做**：先缩图会把棋盘重采样成 248/200 这类过渡色，
  严格的图案判据当场失效（实测非棋盘像素从 20% 涨到 73%，整张图都被当前景）。
- **`sharp.resize()` 会把单通道灰度提升成 3 通道**：照 1 字节/像素去索引就会整体错位，
  表现是横条纹（150×238 里有 75 行全空、0/非空跳变 111 次，翅膀那张甚至整张全空）。
  现在按 `info.channels` 索引。
- **翅膀和身体在剪影里是连成一片的**，没法用连通域分，最后是按「画在原图上、肉眼核对过」
  的六边形切的（`tools/egg/build-sprite.mjs` 里的 `WING_POLY`）。换图重跑：
  `node tools/egg/build-sprite.mjs --preview`（源图在 `tools/egg/source.png`）。
- **鸟群容器必须用 `is:global` 写样式**：`.flock` / `.bird` 这些节点是脚本现造的，
  身上没有 Astro 的作用域标记，普通 `<style>` 编译成 `.flock[data-astro-cid-xxx]`
  永远命不中（第一版就是这么翻车的：`position:absolute` 全没生效，一群鸟竖着排成
  一列把页面撑到 2000 多像素高）。

### 彩蛋：藏在城市剪影里的雕像（点进 `/secret/xianbao/`）

用户 2026-09 的要求：

> 隐秘页面的雕像的出现改为每次进入首页都会让一个雕像随机刷新在和城市影重合的位置
> 看不出来 然后雕像会偶尔探头出来 引导用户点击。连续点击回到顶部塔吊五次改为会让
> 雕像轮廓微微发光

（在这之前它是"混在鸟群里飞、10% 概率出现"，那条路现在关着，见上一节。）

**一句话机制**：雕像和楼群**同一支墨**（`--ink` = `#08020c`）、画在楼群**前面**，
每次进页面从量好的 37 个位置里随机挑一格站定 —— 那一格是算出来的「整个剪影都压在
楼群的实墨里」的位置，所以静止时它和楼群是一片黑，看不出任何东西。偶尔抬起来一截
（**盒高的 5%**，其中有 1% 是安全余量），上半身探到楼顶以上，天上才出现它的形状；
这时候点它就进隐秘页。连点「回到顶部」五次，它会在**原地**微微发光 ——
那是给用户的提示：它就在那片楼里。

代码在 `src/components/HomeStatue.astro`，取位数据由 `tools/egg/fit-statue.mjs` 生成。

#### 为什么"看不出来"是硬保证，不是"差不多看不见"

- 雕像是 `background: var(--ink)` + `mask-image: statue-full.png` —— 用**遮罩**而不是
  直接 `<img>`，是为了让它身上每一个像素的颜色**逐位等于**楼群那支墨（原图是抠出来的
  铅笔稿剪影，边缘难免带一点别的灰；当遮罩用就没这个问题，颜色全由 `background` 给）。
- 于是"同一颜色叠在同一颜色上"在数学上等于什么都没画，抗锯齿的软边也一样
  （半透明的墨叠在墨上还是墨）。
- 证据在 `home-statue-check`：把**全部 37 个可用格**逐个摆上去，和「这一层不画」
  的同区域截图逐像素比 —— **雕像自己身上变的像素是 0 个**（桌面和手机各验一遍）。

#### 取位数据是怎么算出来的（`node tools/egg/fit-statue.mjs`）

要藏的格子必须满足「整个剪影都落在渲染出来是**纯墨**的地方」，判据用**四条剖面**：

| 剖面 | 为什么要它 |
| --- | --- |
| `skyline.png`（母本） | 原图 |
| `opt/home/skyline-1600.webp` | 页面真正画的是这一档；nearest 重采样会**丢列**（实测和母本屋面最大差 **37.7% 盒高**） |
| 浏览器实测 @1440、@390 | 缩放会把比核还细的天线抹成**半透明的墨**（实测 390 宽时 p95 差 **12.5% 盒高**）；源图上明明是实心的地方，渲染出来不是 |

每条剖面都按**列**切成「不透明区间」的列表 —— 不能只存一根"屋面线"：楼与楼之间有通到
天际的缝、楼身上还有洞（实测某列：46%~50% 有墨、52% 半透明、58%~74% 整段是天空、
76% 以下才有墨），雕像比楼矮，可它**下半截**正好悬在洞里，只按屋面线判就会放它过去。
算法是：对剪影每一列，允许的 `rest` 是若干区间，逐列求交、取最小的那个（站得最高 =
探头最容易露出来），再往下让 1% 的余量；最后数"抬升 5% 之后露出多少剪影像素"，
只留下露出 12%~50%、而且露出来的确实是上半身的位置。

⚠ 换了 `skyline.png` / `statue*.png`，或者改了 `.vapor__skyline` 的尺寸写法，
都要重跑一遍，把末尾那两行 `data-peek` / `data-rests` 抄回组件（脚本会直接打印出来）。
实测剖面缓存在 `.tmp/roof-rendered-<宽>.json`，加 `--remeasure` 强制重测。

#### 为什么尺寸写百分比而不是 px

`.vapor__skyline` 是 `aspect-ratio:1773/526` + `background-size:100% 100%`，
图像坐标到盒子坐标是线性的、和视口无关。雕像高写成**盒高的 11%**，于是"雕像占多宽"
"楼顶在盒高百分之几"全是常数比例 —— 桌面量出来的安全位手机上照样安全（窄屏上
`max-height:62vh` 把盒子压得更矮，脚印占比只会更小，更保守）。写成 px 的话，
窄屏上雕像会相对楼群越变越大，量好的位置当场失效。

#### 探头 / 发光 / 点击

- **探头**：第一次进页面 5~10 秒（先让人看两眼城市），之后每 9~20 秒一次，每次探
  1.6~2.6 秒，三成概率连探两下；标签页在后台、或者城市被卡片盖住（`body.is-cards`）
  时这一轮跳过 —— 不白探。
- **发光**：连点「回到顶部」五下（两次间隔不超过 3 秒），轮廓亮 7 秒。
  发光必须画在**外层**元素上，不能和 `mask` 写在同一个元素上：`mask` 在 `filter`
  之后应用，写在同一个元素上的话 `drop-shadow` 看到的是**没被遮罩的整块矩形**，
  会糊出一个方块光晕。写在外层，滤镜拿到的是子元素遮罩之后的形状，光晕才贴着轮廓走。
  实测：光晕 99% 落在雕像周围 30px 内，剪影**内部**（腐蚀 4px 的核心）**一个像素都没亮**。
- **点击**：雕像画在 `.vapor` 里（`z-index:-1`，在内容后面），所以它正上方多半压着
  `.home` 这类**什么都没画、却照样吃点击**的包裹 div —— 点击根本落不到 `<a>` 上，
  文档上补了一层判断（点了就 `location.assign`）。两条自我约束：**绝不抢链接/按钮的点击**，
  以及**只有这一刻看得见它才算数**（探头中 / 发光中 / 刚缩回去 0.8 秒内 / 鼠标已经压在它
  上面）—— 静止时那一块是纯黑的楼群，闭着眼睛点一下不该有反应。
- **鼠标小手**：`.statue__fig` 上的 `cursor:pointer` 和 `:hover` 都是**死规则**（同一层
  原因），所以脚本用 130ms 的定时器算指针在不在雕像矩形里，命中就换小手、并让这一轮
  探头先别缩回去（鼠标压在它身上时它就一直举着，点起来不费劲）。静止态定时器是关着的。

#### 这一轮被像素比对逮出来的两个坑

- **`translate: -50% 0` 被 Lightning CSS 丢掉了。** 产物 CSS 里那条声明直接不见，

改的时候有两条约定，破了会很难受：

1. **动效只碰 `transform` 和 `opacity`。** 这两个属性走合成层，不重绘画面。
   换成动 `background-position`、`filter`、`width` 这类，整屏就会每帧重画。
   唯一的例外是扫描线，它必须动 `background-position`：那层靠
   `image-rendering: pixelated` 才有硬边，而位移一旦交给合成层，
   贴图会被按双线性重采样，硬边当场糊掉。所以宁愿每帧重画那张
   153 字节的贴图，也别把它改回 `translateY`。
2. **「减少动效」偏好下所有背景动画会整体停掉**（`prefers-reduced-motion`）。
   新加的动画请一并放进 `index.astro` 末尾那段 `@media (prefers-reduced-motion: reduce)`，
   组件里的放在组件自己的 `<style>` 里 —— Astro 的作用域选择器跨不进组件内部。

塔吊的站位不是随手摆的：它按「两张板块卡片之间那道缝」量出来，
而缝的位置取决于 `src/data/layout.json` 里 `home.boards` 的偏移。
在编辑器里挪过板块之后，跑一次本机的核对脚本
（`_setup/home-motion-check.mjs`，不在仓库里）会打印每台塔吊的可见高度和横臂朝向。

### 大板块页的版式（一块块的面板）

大板块页（比如「花娅陌域」）把**子版块**排成一块块的框。版面由数据里的
`layout` 字段决定，编辑器「板块」里每一行都有**「版式」下拉**可以直接改：

- **默认（不写 `layout`）→ 竖排**：子页面一条一条占满整行，就是宽幅大卡
  （图铺满、名字居中，见下）。带多个子页面的页面统一是这个样子。
- **`layout: "region"` → 三列分区**：左列上下两块、中间和右边各一块跨两行
  （列宽比 2.44 : 1 : 1，三列底边齐平）。这是给花娅陌域专门设计的，
  只在子版块**够 4 个**时才启用 —— 不够就用竖排，否则会空出一整列。

每一条都只有名字，压在正中，没有右箭头（整块本来就是链接）：

- **传了封面图**（编辑器的「板块」里逐个上传，存在 `image` 字段）→ 图铺满整块，
  微微半透明（`opacity: .82`），名字居中压在上面，还垫一层淡暗底保证认得清。
- **没传封面图** → 不摆空图位，就是一条扁平的名字条。

**有下级的框整块可点**：点标题、标题右边的「进入 ›」、或者框里条目之间的空白，
都是进**这一页自己的页面**；点清单里的条目则进那个条目自己的页面。
（整块可点靠一小段内联脚本：它绕开卡片、滚动条和正在选文字的点击，
排版模式下也不会乱跳。）

## 页面：像写文章一样改一个页面

编辑器顶栏那个**「页面」**按钮，是改页面的地方。打开后是三栏：

- **左栏**：整棵版块树上的**每一页**（缩进显示层级和地址），点一下切过去；
  上面有搜索框，版块多了也能翻。
- **中栏**：这一页现在长这样是由什么决定的 ——
  名称 / 副标题 / 地址 / 版式 / 封面图，下面是「这一页的内容」块列表，
  再下面是「这一页的子版块」（改名、传封面、单张卡的比例大小、上下换顺序、
  当场加一个新的子页面）。
- **右栏**：这一页的真实预览（构建出来的那个页面）。「重新构建」随时刷新，
  「新标签打开」用整屏看。

底下的「保存并重新构建」＝ 写进 `src/data/home-boards.json` + 跑一次构建，
点完右边立刻就是最新效果。

> 「排版」模式（顶栏另一个按钮）只能挪**已经有**的东西。
> **要加新的字、图、子页面，用「页面」。**

## 页面内容：自己写这一页

「这一页的内容」就是这一页从上到下的排版。点那些 **＋ 按钮**就能加，
十种块随便拼：

| 块 | 写什么 |
| --- | --- |
| **文字** | Markdown：段落、`**粗体**`、`[链接](地址)`、`- 列表`、`## 小标题`、`![图](路径)` |
| **图片** | 传一张图，宽度分 全宽 / 宽 / 半宽 / 窄 四档（**「窄」会并排**，见下） |
| **链接** | 一句文字 + 一个地址（站内写 `/huaya`，站外写 `https://…`） |
| **分隔线** | 一条横线，中间可以带一句话，用来分段 |
| **两栏** | 左右各写一段 Markdown（窄屏自动上下叠起来） |
| **视频** | 视频文件直链（`.mp4` / `.webm`…）直接播；B 站或 YouTube 链接自动换成播放器 |
| **文章** | 把归到这一页的文章 / 手记列出来；插了这一块，页面底部就不再自动列一遍 |
| **目录** | 自动把这一页的 `##` / `###` 收成一份带编号的目录，能跳转、能逐组折起来 |
| **地图** | 一张能缩放拖动的地图，上面钉塔吊地标（见下一节） |
| **子页面** | 把这一页的子版块铺在**这里**，卡片的横竖比例（横 16:3 / 方 1:1 / 竖 3:4）和大小（大/中/小）都能选 |

块可以上移下移。**写了内容，这一页就不再自动铺开子版块** —— 子页面要靠
「子页面」块自己插到想要的位置。没写内容的页面一切照旧。

#### 图片四档宽度，以及「窄」为什么是并排的

| 档 | 宽度 | 排法 |
| --- | --- | --- |
| 全宽 | 100% | 一行 |
| 宽 | `min(100%, 44rem)` | 一行 |
| 半宽 | `min(100%, 30rem)` | 一行 |
| **窄** | 一格（`min(20rem,100%)` 起、最多均分） | **连着几张就横着排开，排满一行再换行** |

用户原话（2026-09-21）：

> 修改页面中图片的排列 如果图片选择大小为窄 那么不要让右边留出那么多空
> 选择为窄的图片会优先横着排开然后再换行继续排

以前每张图都是一个 `.pblock`、`.page` 又是「一列往下排」，所以「窄」图永远一张占一整行、
右边空掉四分之三。现在（`PageContent.astro`）：

- 宽屏（≥720px）把 `.page` 从「flex 一列」换成 **栅格**
  `repeat(auto-fill, minmax(min(20rem, 100%), 1fr))`；
- 普通块 `grid-column: 1 / -1` **横跨整行**（文字、宽图、地图、时间轴……和以前一样）；
- 宽档是「窄」的图片块多一个 `.pblock--flow`，`grid-column: span 1` → 只占一格，
  于是**连着的窄图自动并排、排满一行再换行**，空位只留在最后一行末尾；
- 格子里再让图占满那一格（`.pblock--flow .pfigure { width: 100% }`），
  否则格子比图宽，图与图之间又会空出一条；
- 手机上（<720px）一列放不下两张，**不套栅格**，还是老样子一张一行；
- 窄图的 `sizes` 也跟着改成 `(max-width:719px) 100vw, (max-width:1100px) 45vw, 360px`：
  并排以后它只占行宽 1/3，不用再按 760px 去挑大图。

实测（`board-image-flow-check.mjs`，那两页窄图在 `/huaya/years/fenhu/xichenxuhome/`，
1440 视口、正文列 1040px）：两张窄图同一行、**193~522 / 548~877**、各 **330px**、
右边只剩 **356px（34.2%）**（以前一张一行时是 ~75%）；DOM 里塞到 6 张 → **3 + 3 两行**；
文字块和宽图照旧 1040px 整行、宽图仍 704px；手机 390 上仍是一张一行、各 320px、0 横向溢出。

大小在「子页面」块里是**六列栅格**：大占一整行、中两张一行、小叁张一行，
大中小在版面上就真的看得出区别。想某一张跟别人不一样，就在中栏最下面
「这一页的子版块」里单独给它选比例、档位，或者**直接填像素宽高**
（`420 × 90` 这样）—— 这些设置写在**子版块自己身上**
（`cardShape` / `cardSize` / `cardW` / `cardH`），
换顺序、挪到别的块或别的页面都还跟着走。

> 「大小」那一档（大/中/小）只在**「子页面」块**里看得出区别（那是六列栅格）；
> 面板清单里的卡片整行铺满，档位对它没作用。**要精确改大小，用旁边的「尺寸」填像素**。
> 填了像素以后，面板里的卡片、竖排的大卡、面板自己（有下级的那种框）都按这个尺寸渲染。

每个块在「排版」模式里还能微调位置和大小（锚点是 `pg-<块id>`）：选「大板块页」→
「哪个板块」挑到那一页。块 id 全站唯一，在哪一页调都不会串到别的页去。

数据存在节点的 `page` 数组里（`src/data/home-boards.json`），编辑器负责读写。

### 「更新日志」那一页：一天一个栏目（`/huaya/memory/update`）

用户的要求（2026-09-21）：

> 从这次任务开始 你每次完成会话的时候 都生成一段简短易读的更新日志 发到
> /huaya/memory/update 也就是更新页面里面 像我一样每一天为一个栏目 上下用分割线
> 隔开 今天的工作内容就发在一个栏里 明天新写一个日期然后发新的内容这样操作

所以**每轮做完活**都要往那一页补一段。它就是普通页面数据（节点 `href` 写死为
`/huaya/memory/update`，`page` 数组里一个 `text` 块 = 一天，块与块之间夹一个
`divider`），格式照用户自己那份：

```
{ "id": "huaya-r1-1-pmu…", "type": "text",    "text": "2026.9.21\n第一段…\n\n第二段…" }
{ "id": "huaya-r1-1-pmu…", "type": "divider" }   ← 只有它前面那条不是分割线时才补
```

用 `tools/memory/append-log.mjs` 写，别手改 JSON：

```
node tools/memory/append-log.mjs 2026.9.21 .tmp/log-2026-09-21.md   # 先写成文件
node tools/memory/append-log.mjs 2026.9.21 .tmp/log-2026-09-21.md --dry   # 只看不写
```

- **同一天只保留一个栏目**：今天已经写过（又开了一轮会话）就**就地覆盖**那一条，
  不会堆出三个 `2026.9.21`；第二天日期一变，才在尾部新补「分割线 + 新栏目」。
- 正文是 Markdown，**空行分段**（`\n\n`）→ 页面上就是一段一段的；
  只写一个 `\n` 会被当成空格（用户自己 9.14 那条就是这样）。
- 脚本写回时用和编辑器同一套序列化（`JSON.stringify(data, null, 2) + '\n'`），
  并且**先逐字节核对**盘上那份是不是也长这样 —— 对不上就拒绝写，
  免得为了加一段日志把用户整份 `home-boards.json` 重排（diff 会糊成一片）。

### 静态站没有后端，所以索引是构建期做的

所有能跳的地方在构建时摊成一张索引，写到 `dist/search.json`；浏览器拿它**本地过滤**，
敲字那一下就有结果，不用每敲一个字请求一次网络。

索引由 `tools/search/index.mjs`（一个 Astro 集成，注册在 `astro.config.mjs` 里）
在 `astro:build:done` 里生成 —— 只有那时候才知道站点到底生成了哪些页面。
写这份文档时是 **1042 条**（每加一条内容这些数字都会变，以构建日志里那行 `[search] 搜索索引：…` 为准）：

| 种类 `k` | 条数 | 地址长什么样 |
| --- | --- | --- |
| `page` | 42 | `/salon/` —— 构建出来的**每一个**页面，标题直接读那页的 `<title>` |
| `anchor` | 117 | `/huaya/years/#xxx` —— 页面里的标题 / 图片 / 段落 |
| `essence` | 784 | `/salon/#e0001` —— 冰室精华的**每一条**（用户点名要的那条） |
| `post` / `note` | 6 / 2 | 文章、手记（标题来自 frontmatter） |
| `nav` | 2 | 导航库里带链接的条目（站外的标 `ext`） |
| `ice` | 88 | 冰山图的条目 |
| `point` | 1 | 时间轴上**带链接**的时间点 |

每条 = `{ t 标题, s 搜索正文, h 地址, k 种类, sub 副标题, ext? 站外 }`。

- `s` 是给小写化后做子串匹配用的正文（精华能到 400 字，再长索引就太大了）。
- **站外链接**（导航库里收藏的 bilibili / 维基 / 网易云）标 `ext: 1`：它们在产物里没有
  对应页面，搜索结果里显示成「外链」徽章、点了新开标签页。
- 地图图钉那 32 个里只有 2 个填了链接，而它们的「地址 + 标题」和对应板块页完全一样，
  最后一步去重时并进了 `page` 那两条 —— 所以 `map` 这一类的计数是 0，不是漏了。
- 首页（`/`）也在里面：`astro:build:done` 给的 `pages[].pathname` 里，**首页是空字符串**，
  第一版 `if (!pathname) continue` 把它跳过去了，是验收脚本里那条
  「构建出来的每个页面都在索引里」抓住的。
- `public/secret/xianbao/`（首页那座雕像点进去的 Spine 演示页）**故意不进索引**：
  它是手写的独立页面，不经过 BaseLayout，没有站点头尾和控件，也不该被随机跳到。

### 打字的时候（顶栏那个下拉）

- 打完第一个字就去取 `/search.json`（鼠标一进搜索框就先取上，等真敲字时不用等网络），
  之后全在内存里过滤。一次请求 308KB，**不进首页的首屏**。
- **打分档位**（`src/search/core.js` 的 `scoreOf`）：标题一模一样 120 › 标题以它开头 100 ›
  标题里有 82 › 正文里有 56 › 地址里有 40 › 标题里按顺序散落 34 › 正文里散落 16。
  散落那两档是给中文兜底的（「冰精」能命中「冰室精华」），分给得很低，只在别的都没命中时才露头。
- 查询词用空格分开时是 **AND**：每个词都要命中，取各自分数的平均，多一个词加一点。
- 排序是**确定的**：分数 → 标题短的在前 → 地址字母序。少了最后那一档，
  同分条目的先后会随引擎实现变，顶栏下拉和中转页就可能对不上。
- 键盘：↓/↑ 在候选里走一圈、回车打开选中的那条、Esc 收起；点别处也收起。
- 下拉页脚那行是这个功能唯一的「说明书」，写着**回车会去哪儿**：
  「回车：直接打开「xxx」」或者「回车：看全部 N 条结果」。

### 回车：直达还是进中转页

判据在 `core.js` 的 `direct()` 里，两条常量（`STRONG = 100`、`GAP = 16`）：

- 头一条必须够强：标题**以查询开头**（100 分）或**一模一样**（120 分）；
- 还得甩开第二名 16 分以上 —— 并列说明「有好几个都像」，那就该给中转页让人挑；
- 另一条：整个站只有一条结果、且分数 ≥ 56（不是靠散落字符蒙上的）→ 也算直达。

`/search/`（`src/pages/search.astro`）是**中转页**，页面本身静态、查询词跟着地址走
（`?q=…`，能刷新能分享），过滤同样在浏览器里。它做了几件事：

- 结果**按种类分组**，但组的先后不是写死的：**哪一组里出现了排在最前面的那条，哪一组就在最上面**
  （写死顺序的话，明明精华那条分最高却被「页面/文章」压到下面，而且顶栏下拉的第一条
  会和中转页的第一条对不上 —— 这两处必须是同一套排序的下游）。
- 每组先铺 50 条，剩下点「再显示 N 条」。
- 不带查询词打开就是一张**全站目录**（42 个整页，按地址排），当「随便逛逛」用。
- 标了 `noindex`，也不在 `sitemap.xml` 里：它没有自己的内容，只是一堆过滤结果。

### 随机跳转

- 图标 `#random-jump` 是手画的 SVG：侧视、从兔子洞里探出上半身。
  头 / 耳朵 / 洞口近沿都填**按钮自己的底色**，靠「盖住后面的线」做前后关系
  （耳朵 → 头 → 洞口近沿三层），所以深色页面（首页 / 板块页）上那三块的填充色要跟着换成
  `rgba(38,4,52,.72)`，见 `src/styles/search.css` 末尾 —— 不换的话亮块会浮在深紫按钮上。
- 点了随机进**本站任意一个页面**：抽签池 = 索引里所有 `page / post / note`（48 个整页），
  排除 `/search/` 自己、排除当前这一页、也排除**上一次刚去过的那一页**（连抽两次同一页
  会让人觉得这功能没在动）。
- 悬停 / 键盘聚焦时浮出一张卡片写着「随机跳转」；**回到顶部那颗按钮的悬停提示也换成了同一套卡片**
  （原来是浏览器自带的 `title`，样式跟站点不搭，现在那个属性也删了）。

### 为什么样式单独放一个文件

`src/styles/search.css` 没写在组件里，是因为**搜索结果那堆 DOM 是脚本生成的**，
拿不到 Astro 给组件样式打的作用域标记 —— 组件里的选择器一律够不着它们。
抽屉里那棵树是用 `:global()` 绕过去的，但搜索结果的选择器有几十条，全写 `:global()`
不如单独放一个全局样式表（`global.css` 顶部 `@import` 进来）。

### 实测

`node tools/checks/search-random-check.mjs`（48 项，全过）：

- **产物里能静态查的**：索引里每一条站内地址都能在 `dist` 里找到真文件；
  每一条带 `#` 的（锚点 + 精华，共 900 多条）目标页里**真的有那个 id**；
  构建出来的 50 个 `index.html` 全在索引里；51 个页面每个都挂着搜索框和随机跳转。
- **浏览器里量的**（真鼠标移动、真按键、真点击）：控件顺序 / 同高 / 不撑出横向滚动条；
  两张悬停卡片（文字、底色、圆角、阴影，以及移开之后收回去）；
  输入即出下拉；弱匹配回车 → `/search/?q=…` 且中转页第一条 = 下拉第一条、下拉 8 条全在其中转页里；
  强匹配回车 → 直接进那一页（不经过中转页）；
  搜到单独一条精华 → 点它 → 落在 `/salon/#e0002`，**那一条在视口里**（`top=147`，
  页面顶部那条会是 0 上下）；从中转页点精华那条同样落到那一条；
  随机跳转连点 5 次 → 每次都真的跳了、至少 3 个不同页面、没有一次落在搜索页或 404。

### 踩过的坑（都留在这儿）

1. **`astro:build:done` 给的 `dir` 是 file URL**（`/D:/repo/dist`），
   `path.resolve('/D:/…')` 在 Windows 上会拼成 `D:\D:\…`。用 `fileURLToPath()`。
2. **`pages[].pathname` 是站点相对路由**（`about/`、`posts/xxx/`），没有 `index.html`、
   没有开头的斜杠，**首页是空字符串**。按 `xxx/index.html` 去匹配的话 50 个页面一个都进不来。
3. **`hidden` 属性会被作者写的 `display: flex` 压过去** —— 下拉收起时属性设上了、
   面板照样摊在那儿（还挡着底下的东西）。`.srch__pop[hidden] { display: none }` 这一条不能省。
   同一页里 `.vol[hidden]` 踩的是同一个坑。
4. **内联脚本里的 `<` 会让 `tools/memlink` 的 HTML 扫描器翻车**（这一条最凶）：
   扫描器是「遇到 `<` 就找下一个 `>` 当标签」，内联脚本里 `i < list.length` 这种比较
   会被当成标签的开头一路吞；只要把 `</script>` 也吞进去，script 这一层就永远弹不出来，
   **它后面的整个 `<body>` 都被当成「还在脚本里」跳过** —— 构建日志写着
   「成员名自动链接：0 个页面、共 0 处」，页面上明明全是名字，`member-link-check` 一条条全红。
   修法是让扫描器按规范把 `<script>` / `<style>` 当**原始文本元素**：整段原样拷贝，
   直接跳到它们自己的结束标签（`tools/memlink/index.mjs` 的 `RAW_TEXT`）。
5. **精华页落地时会自己滚一次**（进页面 600ms + `document.fonts.ready`），
   验收脚本量完坐标它再滚一下，鼠标就落在空处 —— 卡片当然不出来。
   所以「量坐标之前先等滚动停住」，`member-link-check` 里那段挪名字的断言
   就是被这条 race 折腾了好几轮（同一份代码有时候过、有时候报 `count:0`）。
6. 验收脚本里挑测试词**不能自己重写一遍打分**：`core.js` 除了「包含」还有一条
   「字符按顺序散落也算命中」，粗算「0001」只命中 1 条、真跑起来 409 条。
   现在的做法是：Node 侧粗挑候选，**唯一性交给页面里那个真的 `HuayaSearch.search()` 判**。

## 地图：在图上钉塔吊地标

「＋ 地图」加一块。地图是**分页**的：上面一排页签切页，每一页都有自己的
图、图钉、划分线和简介（翻页箭头在地图下面）。

一页填这些：

1. **选这一页的地图图**（走的是和图片块同一套上传 + 压缩）。
   旁边那格是**图片说明**（就是 `<img alt>`）—— 只在图片加载失败或者读屏时用，
   **页面上不显示**。想在地图下面写一行字，用下面那个**简介**，别填这个。
2. **写这一页的简介**（可留空）。它是真会显示在地图**下方**的一行小字：
   比正文小一号、颜色淡一点、左边有一道粉线，一眼看出是给上面那张图做注的。
   每页各自一句，翻页时跟着换。
3. **在图上点一下就钉一个图钉**，先在上面「在这里放：」里挑放什么：

   | 放什么 | 长什么样 |
   | --- | --- |
   | **建筑图钉** | 粉色的塔吊：格子条纹的头里画着一台简约塔吊，下面一个小箭头 |
   | **区域图钉** | 蒸汽波落日那套橙黄，头是圆的（就是那颗落日），同样带小箭头 |
   | **区域划分线** | 在图上**按住拖一下**画一条线。它不显示名字、也点不动，只是把地图划成几块。**颜色随便挑**，见下 |

   **划分线是可以一条一个颜色的。** 「在这里放：」那一排末尾有个**线色**：
   左边一个取色块（点开就是浏览器自带的调色板，本来就是按 RGB 调的），
   右边三个 **R / G / B** 数字框（知道 `#1e90ff` 长什么样、不想在色轮上摸的时候用）。
   两边双向同步 —— 色块一动数字就变，数字一填色块就变。
   **先挑色、再拖线**，新线就是这个颜色；画完了想改，每条线在下面的清单里
   也各有一个自己的取色块，改完图上那根线立刻就变（不用整块重画，焦点也不会丢）。

   线在页面上的画法和图钉是**同一套语言**：底下垫一根半透明的同色带，
   上面压一根同色虚线，虚线的空档横着切过色带 —— 就是图钉头上那种扫描线，
   只不过随着线的走向转了角度。所以它和图钉摆在一起是一家的，不是两种风格。

3. **图钉可以直接按住拖动挪位置** —— 点歪了拖回来就行，不用删掉重新点。
4. 下面的**图钉清单**填名字（鼠标移上去显示的就是它）和跳转地址
   （写 `/huaya/xxx`；这一栏有整棵版块树的候选，敲两个字就补全。留空就只显示名字、
   点不动）。清单里还能**改类型**（建筑 ↔ 区域）；**划分线清单**能改颜色和删除。

页面上的效果：

- 图钉**悬停**（或键盘 Tab 过去）浮出名字，**点击**跳到那一页。
  名字默认浮在钉子上方；**贴着地图上边缘的那几颗会自动翻到钉子下方** ——
  地图框是 `overflow:hidden` 的，不翻的话名字会被裁掉，鼠标移上去什么都看不见。
  翻不翻是**指上去那一刻现量的**（缩放、拖动都会改变钉子在屏幕上的高度），
  不是按数据里的坐标猜的。
- 图右边竖着五个按钮：**＋ / －** 缩放，以及 **建筑 / 区域 / 划线** 三个开关 ——
  图钉多了会盖住地图，哪一类碍事就把哪一类单独收掉（只是藏起来，不删数据）。
- **滚轮直接缩放**；已经缩到头了再滚就把滚动还给页面，不会把长页面卡住。
  地图可以**拖着看**，边缘拖不出框。想回到全图点左下角的**复位**。
- 地图下面一对 **‹ ›** 翻页，中间显示「第几页 / 共几页」；再下面是这一页的**简介**。

**位置存的是百分比**（相对图片宽高的 `0~100`），不是像素。所以放大、拖动、
换屏幕宽度、甚至换一张同比例的大图，图钉和线都还在原来那个位置。
图钉做了反向缩放，地图放大 6 倍图钉还是原来那么大；划分线用 SVG 的
`non-scaling-stroke`，放大多少倍线还是那么粗，条纹的疏密也一直不变。
线的颜色只认 `#rrggbb`（三位简写会补全），存进 JSON 前由编辑器服务端卡一遍格式 ——
认不出来的一律丢掉、渲染时回落到默认橙，免得一个手滑把非法字符串塞进 SVG 的样式里。

手机上图里竖着划是滚页面、横着划才是拖地图（`touch-action: pan-y`）——
全禁掉的话整页就没法滚了。

手机上点图钉**先亮名字卡、再点一下才跳**（免得"只是想看看这个地方叫什么"就被带走），
见 [手机端：点一下先看信息，再点一下才跳](#手机端点一下先看信息再点一下才跳)。

## 点图放大（wiki 那种灯箱）

用户要求（2026-09-22）：

> 「新功能：放大看图功能 只有编辑器里由页面→+图片上传的图片 以及冰室精华页面内的

**只认标了 `data-zoom` 的图**，不是"全站所有 `img`"：

| 哪些图能点 | 在哪儿标的 |
| --- | --- |
| 页面正文里用「＋图片」放进来的图 | `PageContent.astro` 的 image 块（`Img` 组件把 `data-zoom` / `data-full` 透传到 `<img>`） |

`data-zoom` 291 个 = 截图 291 张，头像 0 个）。

- 灯箱在 `src/components/ImageZoom.astro`（挂在 `BaseLayout` 里，全站一份）：
  固定层 `z-index: 90`（高过页头 20、目录抽屉、冰山那层失真 30）、背景 `rgb(10 2 16 / .86)` + 模糊；
- **给的是原图**：优先 `data-full`，没有就取包着它的 `<a href>`（精华页那层链接本来就指原图），
  再退回 `currentSrc`。精华页那些是聊天截图，放大就是为了看清字，给压缩过的那档没意义 ——

  开着的时候 `html.is-zoomed` 把底下的页面冻住，关掉之后焦点回到原来那张图；
- **没 JS 时一分钱功能都没少**：框一直 `hidden`，正文的图照旧点不动、精华页那层 `<a>`

> （`closest('img[data-zoom]')` 不行就再看 `closest('a')` 里有没有）。验收脚本量到了这条。

## 地图图钉的名字卡不再被别的图钉挡住

用户原话（2026-09-22）：

> 「修复一个小问题：地图中 鼠标移到图钉上时浮现的文字卡片会被别的地图图钉挡住
>  请保证鼠标移上去显示出来的文字卡片始终在最高图层不会被挡住」

原因很直接：图钉们都是 `position: absolute` 且**没有 z-index**，而名字卡（`.pmap__pinName`）
是钉子的子元素 —— 于是 DOM 里靠后的钉子会盖住前面那颗的卡片。修法是一行：

```css
.pmap__pin:hover,
.pmap__pin:focus-visible,
.pmap__pin.is-open { z-index: 60; }
```

（钉子之间只需要比大小，抬一层就够；`is-open` 那条是手机端"点一下先看名字"的状态。）

**验收是做对照实验量出来的**，不是"碰运气找一对重叠的钉子"：把后面那颗钉子的头
**搬到**前面那颗的卡片正中（造一个必然重叠的局面），然后只改一处 —— 被指着那颗的 z-index：

| 状态 | 卡片正中那个坐标上命中谁 |
| --- | --- |
| 有这条规则（`z-index: 60`） | `SPAN.pmap__pinName` —— **就是那张卡片自己** ✓ |
| 把这条规则去掉（行内 `z-index: auto`） | `SPAN.pmap__pinArt` —— 被后面那颗钉子的头挡住了 ✗ |

> 量这个还得先给卡片打开 `pointer-events`（它平时是 `none`，鼠标端只是"看着的"，
> 所以 `elementFromPoint` 永远命不中它）—— 验收脚本里临时注入一条 `pointer-events: auto`
> 只改这一项，不动 z-index 和绘制顺序。

## 导航表：分类先建一次，页面里整块引用

页面底部那种「分类索引 + 一张张分类表」的导航（大分类可以整节收起/展开，
里面一行一个子分类，条目是**小图标 + 文字**，点文字跳到它填的地址）。
它和**时间轴是同一套思路**：数据在 `src/data/navs.json` 里单独存着，
页面里**只写分类 id**，不存条目内容。

为什么非这么设计：同一个大分类常常要出现在好几个页面上（页面 A 是「甲+乙」、
页面 B 是「甲+丙」），甲里可能几十条条目 —— 要是每个页面各录一遍，
以后改一条就得挨个页面改。现在只在**「导航」面板**里维护分类，
页面那边勾一下要哪几个分类就行；**改一次分类，所有引用它的页面一起变**
（保存时会重新构建，所以线上也跟着变）。

### 数据结构

### 顶栏那个分类名点它去哪（`link`，2026-09-22 加的）

用户原话：

> 「我说的是这个导航二字旁边的纷湖 为什么可以点 点了根本没反应
>  要么加可以写链接的接口要么删掉」

顶上那行是 `导航 · 纷湖` 这种样子：`导航` 是块自己的字（`text`），`纷湖` 是分类名。
**分类名原来一律渲染成链接**，指向 `#<块id>-<分类id>` —— 那是给「一块里挂了好几个分类」
当跳转索引用。可一块里只挂一个分类时，那一节就在紧下面，点它等于什么都没发生：
看着能点、点了没反应，就是用户报的这个。

现在分三种：

| 情况 | 渲染成什么 |
| --- | --- |
| 分类上填了 `link`（站内 `/路径`、`http(s)`、`mailto:`、`tel:`、`#锚点`） | **真链接**，就是填的地址；外链自动 `target="_blank" rel="noopener"` |
| 没填、这一块里**只有这一个**分类 | **一行字**（`<span class="navblk__barHere">`，没有虚线底、hover 不变色、`cursor: default`）—— 不装作能点 |
| 没填、这一块里**有好几个**分类 | 页内锚点链接（老行为，跳上跳下真有用） |

编辑器在顶栏「**导航**」面板：选中分类 → 字段里多一项「**顶栏点它去哪**」
（留空 = 跳到下面那一节；只有一个分类时不做成链接）。

**实测**（`node tools/checks/editor-panels-e2e.mjs` → **107 项全过**，其中这一段 7 项）：
从产物里自己挑一页有导航块的（这次挑到 `/huaya/years/fenhu/hoshihome/`，顶栏「导航」+ 纷湖）：
默认那一行是 `navblk__barHere` 纯文字、**一个链接都没有** ✓；
`POST /api/navs` 填上 `link=/salon/` 再重建 → 变成 `<a class="navblk__barLink" href="/salon/">` ✓；
填成 `https://example.com/nav` → 外链 + `target=_blank` + `rel=noopener` ✓，盘上 `navs.json` 里也带着；
再把那一块挂成**两个**分类 → 顶上两个名字都变成 `#锚点`，而且锚点真指到下面那两节 ✓。
编辑器那一侧（`editor-ui-check.mjs` → **64 项全过**）：面板里有「顶栏点它去哪」这一项，
**填一个值按下保存 → 盘上的 `navs.json` 里那个分类真带上了 `link`**。

```json```json
{
  "categories": [
    { "id": "navcat-xxxx", "title": "实体", "note": "可选的一句说明",
      "groups": [
        { "id": "g1", "title": "友好生物", "items": [],
          "subgroups": [
            { "id": "s1", "title": "无伤害能力",
              "items": [
                { "id": "i1", "text": "悦灵", "href": "/huaya/xxx",

              ] }
          ] }
      ] }
  ]
}
```

- **大分类 → 子分类 →（细分类）→ 条目**：三个层级的数组顺序就是页面上的显示顺序。
  细分类是可选的 —— 子分类可以直接挂条目，也可以再分一层（例图里「友好生物」下面再分
  「无伤害能力 / 无攻击行为 / 攻击非玩家 / 条件敌对」就是这一层）。两种同时存在时，
  页面上先铺直接挂的条目、再铺细分类；最左边「友好生物」那个名字纵跨整组
  （实测两列并排：父级 136px、细分类 112px，层次一眼看得出来）。
- 页面上是一个内容块：`{ "type": "nav", "cats": ["分类id…"], "text": "顶栏那行字" }`。
  `cats` 的顺序说了算 —— 同一个分类在 A 页排前面、在 B 页排后面都行。
- 条目 `href` 站内站外都认（站外自动新标签打开）；留空就只是个名字，点不动。
  条目指向哪一页都行，**包括「独立页面」那种只能靠链接点进来的页**。
  站内地址还能带上「跳到这一页的哪儿」（`/huaya/bingshi#桑芙`），见下面
  [跳到页面里的具体位置](#跳到页面里的具体位置不只是跳到页面还要落到那一段)。
- **空的分类照样存得下**：只建了大分类、条目还没写的也能保存 —— 按用户的工作流，
  经常是"先把分类想好，条目以后再补"，以前这种保存会被服务端当成空壳丢掉。
  现在只有**结构非法**的才丢（不是对象、没 `id`、没标题、`id` 撞了），空的照原样留着。
  页面上引用到一个还没条目的分类时**整节不出现**（`navCatsFor` 会跳过"一共 0 条"的分类），
  免得正文里留一个空壳看着像坏了；条目补上自然就有了。分类本身在编辑器列表里一直看得见。

| 检查 | 结果 |
| --- | --- |

### 条目之间的小塔吊

条目一排好几个，原来两条之间只隔 2px，字看着黏成一团。现在**每两条之间插一个小塔吊**
（和站点别处同一个 path：时间轴、地图图钉、首页天际线），它在 `.navblk__pair` 这一层，
**不在条目本身里**——条目悬停会整块染底色，塔吊放里面会被那个圆角底色一起吞掉，左右看着不对称。
每一对「塔吊 + 条目」包成一个小盒子，所以窄屏换行只会发生在"对"之间，
不会出现某一行末尾孤零零吊着一个塔吊（实测手机 390px 下 10 条排成 3 行，行尾都是条目）。

> ⚠ 改这块样式时的坑：**谁渲染元素，样式就写在谁那儿**。Astro 的 scoped 样式认的是
> "给调用者模板里的元素盖 cid"，而子组件的**根元素**拿到的是**调用者**的 cid
> （实测：`<Img class="site-brand__logo">` 出来的 `<img>` 带的是 SiteHeader 的 cid）。
> 所以中间一旦多插一层组件，里层元素身上的 cid 就换了名字，**原来那份样式会静默失效** ——
> 页面不报错，只是那一块变成没样式的裸标签。`NavItem`（条目）和 `NavItems`（塔吊+条目）
> 因此各自带着自己的 `<style>`；`NavBlock` 里只留它自己模板里的那几个类。

> 样式走站点自己的粉底 + 落日色强调，没照搬例图那个维基蓝 ——
> 例图给的是**结构**（顶栏索引 / 可折叠大分类 / 子分类一行 / 图标+文字 / 点文字跳转），
> 这些一个不少，皮还是花涧堂的。

## 时间轴：右侧那条落日弧线

一条蒸汽波落日配色的弧线竖在网页最右边，向左边微微凸出；**弧顶（最突出的那一点）
永远是「当前」刻度**。没打开的页面只在右边沿露一个**书签**，点它才展开。

书签上写的是**这条时间轴自己的名字**（比如「花娅年代记」），不是「时间轴」三个字 ——
一个页面挂着哪条轴，光看书签就该知道，不用点开。

面板的颜色分两套：**外框**（底、边框、标题、页脚、书签、事件文字）走站点的粉色，
和右侧抽屉是同一套（深紫底 + 粉边 + `#ffd9ef` 的字）；**只有轴本身**（弧线、刻度尺、
时间段带子、塔吊、弧顶那颗点）保留蒸汽波落日渐变。粉的框配落日的轴。

### 先做一条时间轴

顶栏 **「时间轴」** → 「＋ 新建时间轴」。一条轴要填三样：

1. **名字**，以及**左右两侧各叫什么历** —— 比如左边「花娅历」、右边「冰室历」。
   同一个刻度上两边各挂一个事件，就是**双线叙事**。
2. **时间点**：选左/右、选**时刻还是事件**、填日期、填事件名。
   轴会**自动按日期把它们排到轴上**。

   **时间点分两种，功能一模一样，只是大小和颜色不同：**

   | | 图标 | 文字 | 拿来记什么 |
   | --- | --- | --- | --- |
   | **时刻** | 大一些的落日色塔吊（26px） | 0.8rem | 真正的大事 |
   | **事件** | **小一号的樱花粉塔吊**（18px，`#ffb7c5`） | 0.68rem | 同一天里那些零碎的记录 |

   两种点的功能完全相同（左右、日期、名字、链接、合并规则都共用一套），
   差别只在图标和字号。合并也**只在同类之间**发生 —— 混着并成一摞的话，
   那点大小和颜色的区别就没了。老数据没写类别的，一律当「时刻」。

3. **时间段**（可选）：挑两个时间点，给中间那段起个名（比如「XX 年代」），
   再选它**挂在哪一侧**（左 / 右 / 两侧都有）。年代名在页面上有个**胶囊外框**
   （粉边 + 半透明深底），比旁边那些没框的名字显眼得多 —— 它标的是「一段」，
   本来就该比「一个点」站得更靠前。

**同一段年月，两边各有各的叫法怎么办？** 加两条时间段，起点终点填成一样的、
各选一侧就行 —— 比如花娅历这边叫「纷湖年代」、冰室历那边叫「纯良年代」，
它就是同一段区间上的两个名字，各自出现在轴的一侧。要是两边叫法一样，
一条选「两侧都有」就够了，名字会两边各出现一次。

**时间点和时间段都能挂链接。** 那一栏填 `/huaya/xxx`（站内）或者 `https://…`（站外，
自动开新窗口），页面上这两个名字就变成能点的：鼠标移上去有下划线，点一下跳过去 ——
以后想给每个事件配一页介绍，把链接填上就行。留空就是纯文字。
填了不合规的地址（比如 `javascript:`）编辑器会当场把框标红，服务端也会兜底丢掉。

**日期可以直接打数字。** 不用点开日历一层层翻：敲 `20230110`，
打到哪儿横杠自动补到哪儿；`2023-1-10`、`2023/1/10`、`2023.1.10`、
`2023年1月10日` 粘贴进去也认（全角数字也认）。右边那个 📅 还是能开系统日历，
两条路改的是同一个值。真的读不出来（或者日子不存在，比如 `2023-02-30`）
就把框标红、**不写进数据**，不会悄悄存一个坏日期。

**日期右边还有个「实时」开关。** 打开之后这一个时间点的日期就不是固定的了 ——
**永远显示今天，每天自动变**：比如「服务器开放至今」这种一直往后走的事，标成实时就不用管了。
它存进 JSON 的是哨兵值 `today`，不是某个具体日期。

这个站是**静态**的（构建产物躺在 GitHub Pages 上），所以实时是这么实现的：
构建时先按**构建那天**算一遍位置（保证没有 JS 时也不离谱），
打开页面时再由脚本按**访问者当天**的日期把整条轴重排一遍 ——
实时点往后的同时，整条轴的范围会跟着拉长，所有点、所有时间段带子的位置一起重算。
页面开着跨过零点的话，每 10 分钟看一眼日期变没变，变了就再排一次。
时间段的端点如果指向一个实时点，那一段的长度也跟着走。

编辑器里「时间轴」那个弹窗的保存按钮是**「保存并重新构建」**：存完直接跑一遍构建，
不用再去别处点一次。存的时候如果服务端丢掉了什么（没日期的点、端点不在了的段），
会**明确弹出来告诉你丢了几个**，而不是悄悄少一条。

**右边是实时预览。** 改一个字段就跟着重画，不用先存盘、重新构建、再打开页面看：
弧线、刻度、时间段带子、哪个点和哪个点会合并成一个塔吊、文字排成什么样，
全都在那儿。它按**页面打开时的默认比例尺**画（1 格 ≈ 19 天），
合并结果和文字间距跟页面上完全一致；区别只是这里**一次把整条轴画完** ——
编辑的时候要的是全貌，页面上那种滚一屏看一段的节奏不适合校对。

时间轴是**独立的一份数据**（`src/data/timelines.json`），不和页面混在一起 ——
一条轴可以被好几个页面共用，一个页面也能换用别的轴。

### 再把它挂到页面上

「页面」工作台里有两个新东西：

- **「时间轴」下拉**：这一页用哪条轴。不选就是没有，右边沿不会出现书签。
- **每个块的「对应时间」**，以及**每个子版块的「时间」**：认领一个时间点或时间段。

认领之后，页面和轴就联动起来了：

- 滚到认领了**时间点 A** 的那段文字，右侧时间轴就停到 A；
  滚到认领了**时间点 B** 的视频，就停到 B。
- 滚到认领了**时间段「XX 年代」**的子版块卡片时，轴停在那一**年代的中点**；
  点进那个子页面，时间轴打开时也默认停在中点。

### 页面上的样子

- 弧线上的**图钉是垂直于弧线长出来的塔吊**（不是贴上去的），旁边**常驻显示事件名**，
  鼠标移上去补一个日期（有链接的还会提示「点开看看」）。
- 左边的事件朝左长、右边的朝右长，所以同一天的两件事会出现在**同一个刻度的左右两侧**。
- **时间段（年代）也分左右**：带子贴着弧线往自己那一侧让开 8px，名字排在那一侧
  —— 一眼就看得出这段年月属于哪本历。一条时间段可以**两侧都有**，那样左右各一条带子、
  各一个名字。时间段的名字比事件名**大一档**（0.92rem vs 0.8rem）：
  事件是「点」，年代是「段」，段的名字站得更靠前才合理。
- **同一侧重合的年代会自动错开、各用各的颜色。** 两段年月在时间上叠着又挂在同一侧时
  （比如「北大年代」和「花娅年代」在右边叠了四分之一条轴），
  原来它们画在同一个偏移上、用同一套落日色，看起来就是一条压着另一条，根本分不清。
  现在按区间的重叠关系分层：第 0 层照旧（落日渐变 + 粉色名字），
  往外的层各自再让开 11px、换成紫 / 青 / 薄荷这一套**明显不一样的渲染色**，
  名字的边框和字色也跟着自己那一层走 —— 重合的那一段能看到两条并排的带子，
  哪条叫什么一眼对得上。只错开真正重叠的那些，不重叠的仍然都在第 0 层。
- **名字就是链接**（填了链接的话）：鼠标移上去有下划线、点一下跳过去；
  塔吊本身也能点。用的是真 `<a>`，所以中键开新窗口、键盘 Tab、右键复制地址都照常。
- **时间点分三类**：**时刻**（`moment`，大号落日色塔吊，老数据没写 `kind` 的默认就是它）、
  **事件**（`event`，小一号樱花粉塔吊）、**难以考据具体时间**（`fuzzy`，见下）。
- **「难以考据具体时间」的点没有日期。** 现实里有些往事查不到确切日期，只知道大概时期，
  填不出 `yyyy-mm-dd`；这种点就在编辑器里选成这一档：
  表单里**日期输入、日历、实时开关全部消失**，位置改由**在预览里用鼠标拖那颗塔吊**来定，
  存进数据的不是日期而是一个比例 `at`（0 = 最早、1 = 最晚）。
  轴上它的塔吊罩着一层**电视雪花屏**：描边被 SVG 滤镜（`feTurbulence` + `feDisplacementMap`）
  推得歪歪扭扭，上面再盖一层碎噪点 + 一条条横向扫线（整体 `screen` 叠上去、缓慢滚动），
  一眼就知道"这儿的年代是糊的"。鼠标移上去那个小面板里，事件名右边写的是「**难以考据的时间**」。
  实现上有三个坑值得记：① `rangeOf` 只统计**有日期**的点，所以加多少个难考据的点都不会
  把整条轴拉长（实测：三个有日期的点仍在 0.0536 / 0.9464，两个难考据的点正好在 0.5 / 0.62）；
  ② 这类点**从不参与合并**，否则它会被并进旁边那个塔吊、雪花效果就没了；
  ③ 页面上「按今天重排整条轴」的那段脚本会**跳开**它们 —— 它们的位置是拖出来的比例，
  重排一次就跑掉了。塔吊和文字**按「事件」那一档的尺寸**（小一号：塔吊 18px、名字 0.68rem，
  比时刻的小）—— 用户特意要求过这一档，因为这种点也是"零碎记录"，不该跟大事一样大；
  它跟着底下「事件名」开关一起藏/显（不为它单开第七个开关，那会打破那排开关的左右对称）。
- 弧线区**最下面、花娅历那一行横杠的上面**有**六个开关**：
  左边三个管左侧、右边三个管右侧，各是「年代 / 时刻 / 事件」。
  点一下就藏 / 显示那一侧的**那一类文字**：时刻名藏了大塔吊还在、
  事件名藏了小塔吊还在（它们标着那天在轴上的位置），年代名藏了带子和它的颜色还在
  （它标着那段年月有多长）—— 只藏字，不藏位置。
  **打开时间轴时「时刻」是关着的**（轴上一大堆大字最碍眼的就是它们），
  先看到的是干净的轴 + 年代 + 事件；想看见时刻名，点一下下面那两个「时刻」。
  关掉的那几个会压暗、描边变虚（和地图上「建筑 / 区域 / 划线」那几个开关一个语言）。
  状态记在 sessionStorage 里、带上是哪条时间轴 —— 连着翻几页用同一条轴，一直是收着的；
  自己点开过「时刻」之后，那份状态会覆盖默认值。
- **挤在一起的时间点会自动合并**：同一侧、同一类、在屏幕上相距不到 22px 的两个点（同一天
  当然是 0px）共用一个塔吊，几条名字在旁边上下错开 18px 排开 —— 以前「桑芙加入冰室」
  和「SSW加入冰室」只差一天，两行字是直接糊在一起的。
  判据用**屏幕距离**而不是「差几天」：一年跨度和十年跨度下，「差两天」的严重程度完全不同，
  只有屏幕上的距离才说明读不读得出来。左侧和右侧不互相合并 —— 左右本来就是两条历法，
  同一天各挂一件、两个塔吊朝相反方向长，文字也各在一边，合成一个反而丢信息。
  **合并之后鼠标移上去，提示框会把这一组的名字按时间顺序全列出来**（早的在上、晚的在下，
  和旁边文字错开的方向一致）—— 以前只显示组头那一条，另外几条就查不到了；
  没合并的点仍然是原来那种「名字 + 日期」的单行提示。
  **手机端**点一下是"先看提示卡"，对着卡片里的字再点一下才跳 ——
  见 [手机端：点一下先看信息，再点一下才跳](#手机端点一下先看信息再点一下才跳)。
- **滚轮在面板里滚就是滚刻度**（往上滚 = 往更早的时间走）；手机上可以直接拖。
- 面板底部是**时间轴比例**：一根横着的刻度尺，上面那颗塔吊就是滑块，左右拖就改比例尺。
  最左是「一刻度 = 一天」（放得最大），最右是「一刻度 = 一年」（缩到能一眼看完），
  中间**连续无级**，不是跳档。拖的时候**以弧顶那天为轴心**缩放 —— 当前日期一直钉在弧顶上，
  前后的事件向两边散开或收拢。右边那个「1 格 ≈ N 天」是当前读数的实时显示。
  它是个正经的 `role="slider"`，方向键 / Home / End 也能用（按住 Shift 步子大一点）。
- **每条时间轴可以有自己的默认比例尺**（数据里的 `tickDays`，一刻度多少天，1~365）。
  为什么需要：跨度差太远了 —— 一条从 2022 排到 2026，另一条只跨两个月（比如「纷湖」），
  都按文件里那个全局默认（19 天/格）打开的话，后者整条轴只有三格、缩在面板中间一小截，
  读者每次打开都得自己放大一次。现在在编辑器里给这条轴填一个合适的值就行：
  实测同一个「两个月」的跨度，默认档下三个点在 600px 高的面板里只铺开 **79px**，
  把 `tickDays` 填成 2.5 之后铺开 **586px（7.4 倍）**，一打开就是铺满的。
  不填这个字段 = 沿用默认的 19 天/格，**老数据行为一模一样**；填了非法值（越界、非数字）
  也当作没填。它换算成滑块位置用的是同一套对数插值（`t = ln(tickDays) / ln(365)`），
  所以数据里的天数和面板上那根尺子的位置永远对得上。
  优先级：数据里的 `tickDays` → 覆盖不了访客**自己拖过**的值（那份记在 sessionStorage 里、
  带上是哪条轴，用户手动调过就听用户的；换标签页回来就回到数据里的默认）。
- 开关面板**不影响**比例尺位置。位置和「面板要不要常驻开着」是一套逻辑：记在
  sessionStorage 里、带上是**哪条时间轴**。所以连着翻几页用同一条轴，位置一直在
  （哪怕中间把面板收起来过）；翻到用别的轴（或没有轴）的页面并且在那儿动过滑块之后，
  再回来就是默认的正中间。
- 关掉只能手动关。**开合状态按「哪条时间轴」记**：连着翻几页用同一条轴，
  它一直开着；进了用别的轴（或没有轴）的页面，自然就是关着的。

弧线是一段**圆弧**：圆心在面板右侧，弧顶落在竖直正中，半径由「想凸出多少」反推。
位置只存 **0~1 的参数**（在这条轴的时间范围里的相对位置），屏幕上的横纵坐标由脚本按弧长算 ——
所以面板高度一变，弧线和事件一起重排，数据一个字都不用改。

比例尺改的是「整条轴有多少像素」：刻度固定 26px 一个，于是
`整条轴像素 = 26 × 总天数 ÷ 一刻度多少天`。滑块位置到天数是**等比**换算的
（先取对数再线性插值），不是直接线性 —— 直接线性的话，一天到一年这趟行程里
前 10% 就走完了所有看得出区别的档位，剩下 90% 全是「糊成一团」；
等比换算下每滑同样一格，比例尺乘同样的倍数，从一天到一年处处都用得上。


顶栏「排版」里选中一个元素之后，可以做三件事：

1. **拖本体** —— 改位置。每一块版块、每一张子页面卡都是**独立**的，
   拖其中一张，旁边的纹丝不动（以前点空白处容易选中整个网格，看起来就像「全黏在一起」）。
2. **拖右下角的小方块** —— **自由改宽高**（像 PS 的变换框）：往右往下变宽变高，
   宽高各自独立，**左上角不动**。
3. **在数字面板里填** —— 中心点 X / Y（这一页左上角算起的像素坐标）、宽、高、缩放，
   改完立刻生效；反过来拖动时数字也会跟着更新，两种方式始终对得上。

存下来的东西分两种：**位置是相对位移（百分比）**，所以手机上仍按原版式排、不会跑到屏幕外；
**宽高是像素**，因为「改成 300 像素宽」只有像素说得清，而且不像缩放那样把字也缩小。

## 跳到页面里的具体位置：不只是跳到页面，还要落到那一段

站内跳转以前只能跳到「页」（`/huaya/bingshi`），点进去永远停在页面顶部。
现在地址可以带一段锚点，直接落到那一页的**某个小标题 / 某张图 / 某一段**上 ——
比如时间轴上「桑芙加入冰室」那个点，点下去直接停在冰室页的「桑芙」小标题。

地址就写在原来那个 `href` 字段里：`/huaya/bingshi#桑芙`（正文链接、地图图钉、
时间点 / 时间段、导航条目这几处都通用）。

锚点有两种，算法都收在 `src/utils/anchors.ts` 里（页面渲染和导出用**同一套**，
不能各算各的 —— 否则编辑器里选出来的锚点和页面上真有的 id 对不上，点了等于跳到顶部）：

- **小标题**：`## 桑芙` 渲染成 `<h2 id="桑芙">`。id 由标题文字算：中文原样留着、
  空格变连字符、其余符号去掉；同一页里重名依次加 `-2`、`-3`。
  **每一页都会给标题补 id** —— 以前只有放了目录块的页面才补，现在是"能跳"的基本条件。
- **内容块**：每个块外面那层壳上带 `id="blk-<块 id>"`。图片、段落、分隔线、地图、时间轴、
  导航表这些没有标题的块靠它跳；块 id 是编辑器分配的，全站唯一。

跳过去之后还有两件事，不然"跳是跳了，不知道跳到哪"：

- **不被吸顶页头压住**：标题和块都带 `scroll-margin-top: 5.5rem`（和目录用的是同一个值）。
- **落点闪一下**：1.8 秒的淡出高亮（`@keyframes pblockHit`）。

编辑器里所有能填地址的地方都多了一个「**选位置…**」按钮：正文的链接块、地图图钉、时间点、
时间段、导航条目 —— 左边选页面（带搜索）、右边选这一页的锚点（标题就显示标题文字，
块显示「（图片）」这种 + 类型角标）。清单来自构建产物 `dist/anchors.json`
（由 `src/pages/anchors.json.ts` 导出，6 页共 53 个锚点），
所以**刚改过页面内容的话要先保存并重新构建一次**再来选。

| --- | --- |
| 标题锚点真的在页面上 | ✔ 冰室页有 `<h3 id="桑芙">`（`id="桑芙"` 1 处、带 id 的 h2/h3 共 22 个、块壳 8 个） |
| 落点位置 | ✔ 打开 `/huaya/bingshi#桑芙`，桑芙标题 `top = 88px`（页头下方、也在视口里） |
| 块锚点 | ✔ `/huaya/bingshi#blk-huaya-hishitsu-pmu2l5iyf1` 同样落在 `top = 88px` |
| 高亮 | ✔ 两个落点的 `animation-name` 都是 `pblockHit` |
| 手机端真跳过去 | ✔ 时间轴上对着「桑芙加入冰室」的提示卡再点一下，地址变成 `/huaya/bingshi#桑芙` |

> 已经接上的一处例子：花娅年代记里「桑芙加入冰室」这个点的 `href` 写成了
> `/huaya/bingshi#桑芙`。其余的时间点和图钉还没填链接，在编辑器里点「选位置…」照样接得上。

## 手机端：点一下先看信息，再点一下才跳

鼠标端照旧**一次点走**（指哪去哪）；手机端不行 —— 手指那一下很可能是"想看看这是哪儿"，
直接跳走就回不来了。所以触屏上（`@media (hover: none)`）改成两下：

- **时间轴**：点时间点的名字 / 塔吊 → 底边弹出一张提示卡（名字 + 日期；几个点合并成一根塔吊时
  把整组按时间列出来），**不跳**；对着卡片里那行字再点一下 → 才真的走。
- **地图图钉**：点图钉 → 名字卡亮出来（有链接的还多一行「打开 ›」），**不跳**；
  对着名字卡再点一下 → 才走。

第二下走的是**浏览器默认行为**：卡片里那行字本身是个真链接（`<a class="tl__tipOpen">`），
图钉本来就是个 `<a>`，卡片是它的子元素 —— 所以右键复制地址、中键开新窗口那一套照旧能用，
不用自己改 `location`。

几个只有真机上才踩得到的坑，都实测过：

| 坑 | 怎么处理的 |
| --- | --- |
| 卡片盖住面板底部那排开关和比例尺 | 卡片的"贴底多高"是**量出来的**（面板底 − 开关那一行的顶 + 8px，写进 `--tl-card-gap`），所以它正好停在开关上面：实测 `card.bottom = 732`、`toggles.top = 740` |
| 卡片被"浮在塔吊上方"那行行内样式挪走 | 那个位置是脚本写进 `style` 的，行内样式压不过普通规则 —— 手机上用 `transform: none !important` 盖掉。实测没盖之前卡片偏到 `left: -176`（跑到屏幕外去了） |
| 名字卡是 `pointer-events: none`，点不到 | 手机端**开着**的卡片恢复 `pointer-events: auto`；卡片是图钉的子元素，点到它就等于点到图钉 |
| 合并成一大组时卡片太长 | 手机上卡片 `max-height: 70vh`，太高就自己滚 |
| 怎么判断"这是手机" | 用 `(hover: none)`（没有任何悬停能力的设备），不是只看 `pointerType` —— 真机上 `pointerType` 不一定报 `touch`，而桌面（有鼠标）本来就该一次点走 |

桌面端也一起量了：`(hover: none)` 不成立 → 点名字 / 图钉都是 `defaultPrevented = false`
（一次点走），也不会给元素加 `is-open`；「打开 ›」那行在桌面上是 `display: none`。
手机上「第一下被拦住（`defaultPrevented = true`）+ 卡片可见」也逐条量过。

## 子版块自己有下级时
- 在**竖排**页面上：它仍然渲染成一个**面板**（标题 + 里面可独立滚动的清单），
  这样在这一层就看得到它下面有什么。
- 在**分区**页面上：它就是一个「框」，框里竖着铺下级；没有下级的则是一整张大封面。

面板里的清单是独立滚动区：右侧有一根能拖的滚动条，鼠标滚轮也能滚，
条目多了不会把整页撑长。

框的排版微调走编辑器「排版」模式（选「大板块页」→「哪个板块」挑到那一页，再拖框）。
子树本身（谁在谁下面、叫什么、地址是什么）在 `src/data/home-boards.json`，
用编辑器的「页面」工作台或「子版块」按钮图形化编辑，不用手改 JSON。

## 链接版块：有名字有封面，但点了跳走

子版块有两种：普通子版块（点了进它自己的页面）和**链接版块**（点了打开一个网址）。
在「页面」工作台最下面的「这一页的子版块」里有两个按钮：

- **＋ 加子版块** —— 普通的那种，站里会给它生成一页
- **＋ 加链接版块** —— 新的一行，填**名字**、**封面图**和**链接**就行

链接版块在页面上和普通版块长得**一模一样**（有名字、有封面图，
单张卡的比例大小照样能单独调），区别只有两处：

1. 点它是**新标签页打开你填的那个网址**，不进站里的页面；
2. 站里**不再为它生成页面**，编辑器左边的页面清单里也不列它
   —— 它不是一页，是一个入口。

**网址只存在数据里，页面上不显示**，卡片上只有名字。填 `example.com` 这种没写协议的，
编辑器会自动补成 `https://example.com`；`javascript:` 这类会被丢掉（服务端和构建时都挡一遍）。

它是**叶子**：链接版块下面不能再挂子版块（挂了也不会渲染），所以「＋下级」和
「移动到…」里都把它排除掉了。右上角目录里它也会出现，同样是新标签打开。

## 独立页面：不挂在任何版块下，只能靠链接点进来

有时候要的是"就放在那儿给人看的一页"——文章那套（frontmatter、列表页、标签、归档）
管得太多，而普通页面又必须挂在某个版块下面才生得出来。**独立页面**补的就是这个缺口：

- 它和两大板块一样躺在 `src/data/home-boards.json` 的顶层数组里，只是多一个
  `"standalone": true`；
- **页面照旧生成**，地址还是推导出来的 `/<id>`（或者你填的 `href`）；
- **不被任何列表收录**：首页那两张卡片、右上角目录树、任何页面的「子版块」区域、
  `sitemap.xml` 全都滤掉它。想让人看见，就在**别处给它挂一个链接** ——
  正文里的链接、时间轴上某个点的跳转地址、地图图钉、友链……填上它的地址就行。
  编辑器里那一条会直接把地址显示出来给你复制。

实测（在项目副本里塞了两个这种节点、跑一遍构建）：

| 检查 | 结果 |
| --- | --- |
| 自己的页面生成了吗 | ✔ `/dsh-standalone/index.html`、树里那个 `/huaya/dsh-nested/index.html` 都在，标题与正文都渲染了 |
| 首页板块卡片 | ✔ 搜不到它；真板块（甬城晴雨 / 花娅陌域）照旧在 |
| 右上角目录树 | ✔ 搜不到它；真板块照旧在 |
| 页面的「子版块」列表 | ✔ 挂在 huaya 底下那个也不出现在 huaya 页里 |
| `sitemap.xml` | ✔ 两个都不收；真板块照旧收录 |

### 地址可以填得很深（`href` 想写几段写几段）

独立页面是把节点平铺在**顶层数组**里，但它那个 `href` 可以是一个深地址 ——
常见用法是"地址上属于某个页、但不挂进那个页的列表"，比如 `/huaya/years/fenhu/xichenxu`。

**路由是按地址段数分工的，不是按树的层级**（这一点以前写错过，整个构建会崩）：

| 地址 | 谁生成页面 |
| --- | --- |
| 一段（`/yongshen`） | `src/pages/[board]/index.astro` |
| 两段以上（`/huaya/years/fenhu`、`/huaya/years/fenhu/xichenxu`） | `src/pages/[board]/[...path].astro` |

以前 `[board]/index.astro` 的筛选条件是 `depth === 0`（树里在最顶层），
于是独立页面那种"顶层 + 深地址"的节点被塞进只认一段的路由里，
参数值里带着斜杠，构建直接死在 `Missing parameter: board`（退出码 3221226505）。
现在两个路由都只看 `urlSegs(f.url).length`；同一段地址被两个节点占了，
**只生成先出现的那个，并在构建日志里喊一声**（悄悄少一页比构建失败更难查）。

面包屑和「返回」也**按地址算**（`urlTrail`）：这种页面结构上没有上一级，
地址上却有 —— `/huaya/years/fenhu/xichenxu` 的上级依次是
`/huaya/years/fenhu`（纷湖）、`/huaya/years`、`/huaya`，
所以面包屑会显示 `花娅陌域 › 花娅编年史 › 纷湖 › 新独立页面`，「返回」回纷湖，
而不是只剩它自己 + 返回首页。

实测（用户真建的那一页 `/huaya/years/fenhu/xichenxu`，真浏览器）：

| 检查 | 结果 |
| --- | --- |
| 构建 | ✔ 48 页全过，`dist/huaya/years/fenhu/xichenxu/index.html` 生成 |
| 打开 | ✔ 标题「新独立页面 · 花涧堂」，地址就是填的那 4 段，0 console error，手机端无横向溢出 |
| 面包屑 | ✔ `花娅陌域 › 花娅编年史 › 纷湖 › 新独立页面`，每一级都点得回去 |
| 返回 | ✔ `← 返回 纷湖` → `/huaya/years/fenhu` |
| 还是不被收录 | ✔ `sitemap.xml` 里搜不到；首页卡片 / 目录树 / 纷湖页的子版块列表里都没有 |
| 能被别处链过来 | ✔ 它出现在 `dist/anchors.json` 里（7 页 67 个锚点），编辑器「选位置…」能选到它 |

### 上方那行位置链接跳到哪：`crumbHref`（2026-09-22 加的）

用户原话：

> 「注意到导航栏若是选择了纷湖 上方会有可以点击的纷湖二字 如果预留了点击位
>  那么请加入可以编辑点击跳转到的链接的接口」

子页面正文上方那行位置链接（面包屑，`花娅陌域 › 花娅编年史 › 纷湖 › 当前页`）里，
**每一个祖先都是能点的**，默认点它回它自己那一页（`/huaya/years/fenhu`）。
现在版块节点上多了一个可选字段 `crumbHref`：填了就从这一项点过去的时候改去那个地址，
**hero 里那个「← 返回 纷湖」也一起跟着变**（两处标的是同一件事，不该各指一个地方）。

编辑口子有两个（填的都是同一个字段）：

| 在哪儿 | 长什么样 |
| --- | --- |
| 顶栏「子版块」面板 | 每个版块第二排多一个输入框「上方位置链接（留空 = 回它自己那页）」（一共 25 个） |
| 顶栏「页面」工作台 | 字段清单里「地址」下面多一项「上方位置链接」，说明会写出**默认值是哪个地址** |

- 地址规则和「链接版块」那套一样（`cleanLink`）：站内 `/路径`、`http(s)`、`mailto:`、`tel:`、`#锚点`；
  认不出来的值直接丢掉（退回默认），不让一个错字符把整行面包屑变成死链；
- 填外链时渲染端会自动加 `target="_blank" rel="noopener"`；
- 没填的节点行为一个字没变（默认回自己那页）。

**实测**（`node tools/checks/editor-panels-e2e.mjs` → **107 项全过**，其中这一段 8 项）：
从构建产物里**自己挑**一页面包屑里有两个以上可点祖先的页面（这次挑到 `/huaya/farland/...`，
最后那个可点祖先是「花娅远位面」→ `/huaya/farland`），
然后像用户那样 `POST /api/boards` 填上 `crumbHref = /salon/` 再 `POST /api/build`：
构建产物里那个面包屑链接变成 `/salon/`、hero 的「← 返回」也变成 `/salon/`、
**别的祖先照旧指回自己那页**、盘上的 `home-boards.json` 里那个节点真带着 `crumbHref`；
再填成 `https://example.com/fenhu` → 链接就是外链而且带上 `target=_blank` + `rel=noopener`。
编辑器 UI 那一侧（`editor-ui-check.mjs` → **64 项全过**）量的是：子版块面板里 25 个
「上方位置链接」输入框都在、**在面板里填一个值按下「保存」→ 盘上那个节点真的带上了 `crumbHref`**、
页面工作台里也有这一项而且说明里写着「留空 = …」。

实现上只有一条规矩：**所有"列出版块"的地方都要先过滤**。过滤函数收在
`src/utils/boards.ts`（`isStandalone` / `visibleBoards` / `visibleChildren`），
用到的四处是首页卡片、右上角目录树、`utils/boardPage.ts` 里装配子列表那两处、以及 sitemap。
**地址推导与页面生成不参与过滤** —— 它照样要有自己的页面。

> 它只是"不被列表收录"，不是"不公开"：地址知道就能打开，也没加 `noindex`。
> 真要藏着，只能靠"不把地址给出去"。

### 时间轴：一共跨了多少天 + 年代各有多少天（2026-09-22）

用户原话：

> 「1.在时间轴的比例尺条UI的上方新增一段话：xxxxx 【xx天】，这个【xx天】是显示这条时间轴
>  一共跨越了多少天的 如果有实时时间点也会实时更新。前面的xxxxxx可以通过编辑器写入自定义的话……
>  2.给年代也加上时间统计功能 当鼠标指针移到写有年代名字的卡片上时 卡片会微微放大并在年代名字
>  下面写出xx天 也就是这个年代总共有几天 鼠标移开后变回原样。」

**① 时间轴底部那句「{编辑器里写的话} N 天」**（在比例尺条**上方**、两个历名下面）

- 数据：timelines.json 每条轴多一个可选字段 totalLabel（编辑器「时间轴」面板里的

- **有「实时」时间点（date 写的是哨兵 today）时它会自己涨**：构建期先按构建那天算，
  页面脚本 relayoutLive() 再用访问者当天重算一遍并改写那个数字。

实测：花娅年代记（2023-01-10 → today）显示「冰室成立至今已经 **1352** 天」，

| 现象 | 根因（都量过） |
| --- | --- |
| **名字出框严重** | 时间轴每一行那个名字格子 `.tl__name` 是 `overflow:hidden` 的小盒子。名片一挂进去，格子内部立刻多出 **66px 横向 / 55px 纵向**的溢出，而且名片本身还被那个 hidden 裁掉一半 |
| **想移过去点名字/看放大头像，框立刻消失** | 纯 CSS 的写法只能靠 `:`hover` 维持：名字和名片之间隔着 10px 空隙，鼠标一移进去就落空 |

现在的做法：名片平时 **`display:none`**（完全不参与布局、不给任何容器增加滚动区），鼠标移到名字上时由 `src/components/MemberCard.astro` 那段脚本把它**搬进 `.memlayer`（`position:fixed` 的浮层）**再显示：

- 固定定位的浮层不受任何祖先 `overflow` 影响 → 不会被裁，也不撑出框（实测静止态**全页 0 个** `scrollWidth > clientWidth` 的容器，整页横向滚动 0）；
- 位置由脚本算：默认贴在名字上方 10px，上面放不下就翻到下面，左右夹在视口里（手机上也不会出屏）；
- 收起有 **180ms 宽限**：只要指针还在名字或名片上就一直开着 —— 于是"名字 → 名片 → 头像 → 放大框"这条路线走得通；
- 收起时名片**搬回原来的名字里**（标记回到"每个名字自己带一张卡"的形状，不会越堆越多）；
- 键盘 Tab 到名字上也浮出来，Esc 收起；**没有 JS 时名片永不显示**，名字还是普通链接，页面毫无影响。

**实测**（真浏览器、真鼠标事件）：静止态 `display:none` + 0 个溢出容器；悬停后名片在浮层里、贴着名字、整个在视口里；
把鼠标**挪到名片上** → 还在；**挪到头像上** → 放大框出来（260×260、`contain`）；**挪到放大框上** → 两个都还开着；
移开 → 收回去并搬回原地；手机 390 宽下名片 126×57、没出屏。

### 左边那条时间轴：选站点里已有的一条，**原样**放上去

用户的要求（原话）：

> 「可以在编辑器里选一个时间轴放在那个位置，例如花娅编年史，放上去以后
> **不要做任何改动！！！不要加减删改东西！！！** 时间轴在冰室精华页面需要额外承担的功能只有一个：
> 点击时间轴上的刻度，就跳转到那个刻度对应的精华附近（点刻度即可，或是点时间轴上原本就有的塔吊图标）。
> 时间轴更新了也同理冰室精华旁边的同步更新。」

所以现在的做法就两句话：

1. **只存一个 id**：编辑器「精华」面板顶上那个「左边那条时间轴」下拉，写进 `salon.json` 的
   `timelineId`（空串 = 不放，页面上给一句提示）。页面这边 `getTimeline(timelineId)` 把那条轴
   **原样**渲染 —— 点、段、塔吊图标、比例尺、左右两侧、"难以考据"点的雪花屏全是它自己的，
   **一个都不加、不删、不改**。轴改了（改名 / 挪日期 / 加点）这里跟着变，因为读的是同一份
   `src/data/timelines.json`；重跑导入脚本也**不会**把这个 id 冲掉（`tools/salon/import.mjs`
   会原样带过来）。默认放的是「花娅年代记」（`tl-mu6e19cb793`，57 点 / 16 段）。
2. **唯一多出来的行为**：点轴上的刻度（或它自带的那个塔吊）→ 滚到**离这个刻度最近**的那条精华。
   怎么算"最近"：每个刻度带 `data-param`（它在这条轴上的位置 0~1），每条精华带 `data-tl-param`
   （同一套 `paramOf()` 算出来的位置），取差值最小的那条。比位置而不是比日期，好处是
   **没有日期的「难以考据」点也能跳**。
   页面脚本在左栏上用**捕获阶段**接管这一下（`preventDefault` 掉轴自己的 href 跳转），
   滚过去 + 闪一下 + 把地址栏 hash 换成那条精华的 id；平滑滚动会被打断，所以 1.2 秒后
   检查一次，没到位就直接落过去（不留"点了却停在半路"）。
   手机上仍是原来的"点两下"（第一下弹提示卡、第二下点卡片里那行字才跳）—— 那是用户之前明确要的；
   桌面鼠标一下就走。

> ⚠ 以前这里是**自己按精华日期生成**一条轴（431→450 个点），还写死 `tickDays: 2` 把轴拉到
> 17 万像素 —— 又卡又完全超出用户要求（用户要的是"放一条现成的、别动它"）。这套生成逻辑现在
> 已经删了（`salonTimeline()` 不存在），页面上也不该再出现 `salon-YYYY-MM-DD` 这种点 id。

两个额外决定（都是这一轮顺手定的，改起来都是一行）：

- **`/salon/` 不进 sitemap**。它是 784 条群聊原话，性质是"首页点得进去、知道地址就能看"，
  不该主动推给搜索引擎（`/about-me`、`/iceberg` 那两个新页面是收录的）。
  想让它被搜到：把 `/salon/` 加进 `src/pages/sitemap.xml.ts` 的 `staticPages`。
- **图片全走站点的图片管线**：精华里的 291 张（以及头像 / 冰山图）都用 `variantUrl()`
  取压过的那一档（它查不到清单时会退回原图，所以没跑过管线也不会挂）。
  实测清单 **317 张在册**（复用 20 / 新编 190 / 小图跳过 107），变体 459 个。

> ⚠ 本地验图有个坑：`utils/images.ts` 读图片清单用的是 **`process.cwd()`**，
> 而 `node node_modules/astro/bin/astro.mjs build --root <项目>` 这种写法如果在别处执行，
> cwd 不是项目根 —— 清单读不到，所有图就**静默退回原图**（页面照常、只是没优化）。
> 本地想看优化后的效果，要么用 `pnpm build`，要么先 `cd` 到项目根再跑。
>
> 另外试过给精华列表加 `content-visibility: auto`（跳过屏幕外渲染，确实省），
> 但屏幕外的条目只剩估算高度，左边时间轴按实际位置算"当前滚到哪一段"就会偏
> —— 实测轴上日期比列表里正看的那条**早 3 天**。这件事比省渲染重要，所以撤了。
> 现在用的是 `contain: content`：它**不改元素的位置和大小**，只是让每条成为独立盒子
> （布局/绘制/样式都不外溢），所以轴按位置联动照样准。

> ⚠ 常驻模式有个必须给死的东西：轴体的高度。弧线的几何是按 `.tl__body` 的**实际高度**算的
> （脚本里的 `measure()`），靠 `flex:1` 在一个没有固定高度的容器里会算成 0 —— 整条轴会塌成一个点。
> 现在这个高度**由页面给**：`<Timeline pinned fill />` 时面板高度读 CSS 变量 `--tl-panel-h`，
> 轴体用 flex 吃掉剩下的（面板高减去标题条和页脚）。冰室精华页写的是
> `calc(100dvh - 页头让位 - 说明行 - 8px)` —— "一屏几乎占满"这件事只需要页面写一个高度，
> 不用把标题条/页脚的高度也一起估进去。

### 这一轮修的五件事

用户的原话（第 N+2 次反馈，五条一起来）：

> 「1.现在网页还是非常非常卡 几乎无法正常下翻 请你找出原因并优化。
> 2.时间轴在电脑端太短了下面有一块大空缺特别难受，需要延长到适配屏幕比例，在所有屏幕比例里几乎都占满。
> 在手机端下翻看精华时又无法显示，应当在手机端始终保持在屏幕上半部分。同时搜索栏应当也在电脑端和
> 手机端都可以无论怎么翻都随时保持在屏幕内。3.点击刻度跳转精华功能似乎无法使用，请你检查是因为
> 页面太卡还是出了bug。4.时间轴和地图图钉等处的文字不应该被电脑或手机端的选取文字功能框柱，
> 会在鼠标和手指拖动时造成困扰。5.精华页面的整体风格不对，不应该使用文章风格的配色，
> 而应该用页面风格，例如纷湖下的页面隰辰煦家那样的网站整体风格」

#### ① 卡：根因是"每滚一下就量 784 条"，加上 291 张图没留位

不是感觉，是先量出来的（`tools/checks/salon-perf-check.mjs` 就是这一轮的体检报告）：

| 量到的东西 | 修之前 | 修之后 |
| --- | --- | --- |
| 滚 24 下期间 `getBoundingClientRect` 调用次数 | **18816**（784 × 24，每一下都强制同步布局） | **0 次**（偶尔 784 次 = 1 遍：正好有字体分片下来、布局真的变了才会重量一遍） |
| 291 张截图里写了 `width`/`height` 的张数 | **0 / 291** | **291 / 291** |
| CPU 降速 6 倍滚 30 下，主线程空闲占比 | 49.1% | **61.3%** |
| 累计布局偏移 CLS / 掉帧 / 长任务 | 0.0041 / 0 / 0（但页面一边滚一边长高 170561→175593px） | 0.0049 / 0 / 0（高度稳定 299527px） |

两处根因、两处修法：

1. **时间轴的"跟着页面滚"那段联动**（`Timeline.astro` 的 `syncFromPage`）：它要找出
   "最靠近视口中线的那条带 `data-tl-param` 的成分"，原来每收到一个 `scroll` 事件就把
   页面上**所有**这种成分量一遍 rect。冰室精华页有 784 条，于是每滚一下就是 784 次
   强制同步布局 —— 这是那页"卡到几乎翻不动"的头号原因。
   现在改成**位置索引 + 二分**：位置只在"布局真的变了"的时候重量一次（首次、改窗口、
   字体到位、容器实际高度变了、页面自己喊一声 `tl:reindex`），滚动时只在缓存数组上二分，
   **一次布局都不碰**；顺带把同步节流成"一帧最多一次"（滚一下常来好几个事件）。
   - 位置缓存怎么保新鲜：这些成分都是按文档顺序排的，位置单调不减，所以能二分；
     图（写了宽高的）到位**不会**改布局，就不监听；真正会改布局的三件事各挂一条保险 ——
     `resize`、`document.fonts.ready`、以及**盯住容器实际高度的 `ResizeObserver`**。
     最后这条是必需的：本站那种按需分片的 CJK 字体，往下滚时新字形才下下来、
     字号度量一变每行高度就变一点，几百行攒起来能差一整天（实测轴上的日期比列表里
     正看的那条早 1 天，就是它干的；加上这条保险后两边完全对上了）。
2. **图片没留位**：图片管线对小于 20KB 的图是"原样发、不生成变体"，而清单里
   连尺寸都没记（`w/h: null`）→ 页面拿不到宽高 → 一张图下载完就把下面几百条顶下去。
   两处一起改：管线里给这类图**只读一次尺寸**（`dimsOf()`，不编码），页面上加了
   `imageDims()` 把它取出来写进 `<img width height>`（配 `height:auto` 保持比例）。
   另外给每条精华加了 `contain: content`：让它成为一个独立盒子，
   布局/绘制/样式都不外溢（这**不会**改元素位置，所以轴按位置联动照样准 ——
   之前撤掉的 `content-visibility: auto` 才是会改位置的那个）。

#### ② 时间轴撑满 / 手机端一条细栏钉在屏幕左边 / 搜索栏两端吸顶

- 电脑端：轴的起点紧贴页头（`.salon` 的上边距给 0，留白改加在右栏），
  `.salon__tl { --tl-panel-h: calc(100dvh - 页头让位 - 1.4rem - 8px) }`
  → 视口 746px 时轴 **643px = 86.1%**，轴底离屏幕底 **30px**（以前是 566px = 75.8%，下面空一大块）。
  那个 `1.4rem` 原来是"轴下面那行小字"占的高度：**字删了，位置留着** ——
  轴再长这 22px，一进页面（还没滚的时候）底下那根比例尺就被顶出屏幕外
  （实测短窗口上 `salon-timeline-scale` 拖滑块的鼠标点会整个落空）。
- 手机端（≤880px）：**和电脑端同一套结构** —— 一条细栏钉在屏幕左边（`position: fixed`，
  屏幕左边 0 起），正文用 `padding-left` 让开它，不再"轴横在头顶占掉半屏"。
  栏宽 `--salon-rail-w: clamp(64px, 18vw, 96px)`：390px 手机上 **70px = 屏宽 17.9%**，
  正文还剩 **265px = 67.9%**（实测；320px 小屏 64px / 正文 62.8%）。
- 搜索栏从页头里挪出来、单独一层 `position: sticky`：电脑端吸在页头下面，
  手机端也吸在**轴的上沿那一档**（两边都用 `--salon-top`）→ 实测两顶边差 **0px**，
  也就是「搜索栏始终停在时间轴 UI 顶部」。滚到 4000px 两端都还在视口里。
- "跳过去落在哪"也跟着改：`scroll-margin-top` 和滚动目标都用脚本量出来的
  `--salon-jump-gap`。手机端轴已经挪到**左边**、不再压在正文上方，所以这一项现在
  两端一样，只有「页头 + 搜索栏」（以前手机上还要再加一整条轴的高度）。
- 用户原话（2026-09-21）：
  > 请调整手机端的冰室精华 UI。手机端最好像电脑端一样时间轴固定在屏幕左侧，
  > 可以让时间轴更细一点以防止占用太多正文空间，搜索栏就始终停留在时间轴 UI 顶部

#### ②b 手机端这么窄的栏，轴是怎么活下来的（`Timeline` 的窄栏模式）

栏只有 60~90px 宽，而时间轴上的名字是**横着写的一整串**（`.tl__name` 最宽 8.5rem、
挂在弧线两侧各 40px 外；年代名还要更宽）。这些在窄栏里只会被 `overflow: hidden`
裁成半个字 —— 那比不显示更糟。所以 `Timeline` 加了一个 `rail` 开关
（页面传 `rail={true}` → 根元素多一个 `.tl.is-rail`），880px 以下：

| 收起来 | 留下 |
| --- | --- |
| 事件名 / 年代名 / 顶上那六个「年代·时刻·事件」开关（它们管的就是名字） | 弧线、刻度尺、塔吊、弧顶那颗点、底部比例尺 + 左右两个历名 |

想知道哪根塔吊是什么，**点它** —— 手机端那张提示卡本来就贴在屏幕底部（`position: fixed`），
和栏的宽窄无关；点一下「桑芙加入冰室」实测弹出 `l=79, r=381, t=689, b=790`（整条在屏幕里）。
卡片还特意只盖正文那一栏（`left: calc(var(--tl-rail-w) + 0.55rem)`），不压住左边的比例尺。

为了让「轴本身」在细栏里放得下，窄栏模式把三个几何参数交给页面用 CSS 变量定
（组件里都有默认值，不传就是老样子）：

| 变量 | 默认 | 窄栏 | 为什么 |
| --- | --- | --- | --- |
| `--tl-apex` | `0.62` | `0.5` | 0.62 是"左边给名字留一大片"的前提；名字收起来后弧顶居中更好看 |
| `--tl-bulge` | `30px` | `12px` | 弧线横向凸出量。凸 30px 时「塔吊一半 + 凸出 + 塔吊一半」超过 90px，一栏 62px 装不下 → 实测最狠被裁掉 8px |
| `--tl-crane-rot` | 转 | `0` | 塔吊本来顺着半径转向（=横着朝外伸 26px）。窄栏里不转 → 竖着立在锚点上只占 ±13px，两根对向的都放得下，点击区域还是完整一根 |

另外两处小修：弧顶那天的日期改成**竖着写**（横着有 59px 宽，而它挂在弧顶左边，
实测往左溢出 22px 被裁掉一截）；年代带子的分层偏移从 11px 一档收到 5px。

顺手修掉一个真 bug：`--tl-card-gap`（手机端提示卡贴底让开多少）是拿
「面板底 − 开关那一行的顶」量出来的，而窄栏里那排开关是 `display: none` ——
隐藏元素量出来是 0，于是 gap 变成整个面板的高度，卡片被顶到屏幕外面
（实测 `top = -104px`，整张卡看不见）。现在量不到就退回 CSS 默认值 `3.4rem`。

#### ③ 点刻度不能跳：是真的有 bug —— 刻度根本不是"一个个元素"

时间轴上的刻度是**一整条 SVG path**（几十根刻线合在一根 `d` 字符串里画的），
点上去没有"哪一个刻度"可言、也没有 `data-param`。上一版只接管了事件点/塔吊（`.tl__item`），
所以点刻度什么都不会发生。

修法：组件自己按坐标反推 —— 把点击位置投影到弧上，算出它在这条轴上的参数 `t`（0~1），
广播一个 `tl:pick` 事件（`detail = {param, date}`）；页面接住它，找 `data-tl-param` 最近的
那条精华跳过去。组件只管"点到了哪一点"，拿它干什么由页面决定（别的页面不监听就没事）。
顺手做的两件小事：拖轴滚动过（位移 > 6px）的那一下不算"点刻度"；点链接/开关/比例尺滑块不抢。

实测（`salon-perf-check.mjs` ③）：在轴上偏上处点一下 → `#e0001`（2023-01-10）；
偏下处点一下 → `#e0006`（2023-07-10）—— 点哪儿跳哪儿，而且都落在视口里、hash 都变了。

#### ④ 轴和地图图钉上的字不能被框选

`.tl`（整条时间轴，含刻度、名字、提示卡、页脚）与 `.pmap__frame / .pmap__stage /
.pmap__pin`（地图取景框、跟着 transform 走的那层、图钉）都加了
`user-select: none` + `-webkit-touch-callout: none`（手机长按不再弹复制菜单）。
地图是按住拖动的一层，拖的时候把划过的字选中是最烦的。

### 编辑器：「工作台 → 冰山图」

三栏，一栏一件事：

- **A 栏**　这一页（大标题 + 介绍）· **分类**（取色器选颜色 + 「显示 / 隐藏」开关 + 删）·
  **标签**（改名 / 看有几条在用 / 删，底部一个输入框回车即加）
- **B 栏**　**层级**（＋新建、↑↓ 调顺序、✕ 删、点一行选中）+
  选中那一层的四样东西（标题 / 副标题 / 背景图 / 头图 —— 图走和别处一样的拖拽 / 粘贴上传口）
- **C 栏**　选中那一层的**条目**（搜索、＋新增、改 / ↑↓ / ✕），
  每一行显示：分类色点 · 名字 · 归在哪一类 + 勾了哪些标签 + 有没有链接 · **完备 / 缺描述**
- 条目表单：名字 / 分类下拉 / 标签勾选框 / 详细描述 / 链接（带「选位置…」）
  —— 描述一边写，下面那行提示就一边从「还没写详细描述」变成「已有详细描述 → 页面上会有完备标识」

改动都先落在内存草稿里（切走再切回来还在），按「保存并重新构建」才写盘。
服务端（`tools/editor/server.mjs` 的 `cleanIceberg`）**按白名单写回**：

- 名字空的分类 / 标签 / 条目**直接丢掉**，丢了几条在面板上报数；
- id 缺了或撞了就补一个（`c01` / `t01` / `l01` / `i01`），
  分类 / 标签的 id 补完还会**对齐条目上的引用**，不会留下指向空气的引用；
- 引用了不存在的分类 / 标签 → 清成空（页面上那一条落回默认灰紫 `#b9a6c9`），并报数；
- `updated` 由服务端盖章（不给人手填，填错了页面上的日期就是假的）。

### 页面上的几个行为

- **分类小眼睛**：数据里 `hidden: true` 的那一类，页面上默认就是收着的（眼睛带一道斜杠、`aria-pressed=false`）；
  点一下整类条目一起翻面，再点一下放回来。只给"真有条目"的分类出色块 ——
  一个点了没反应的开关比没有更让人困惑。
- **悬停卡片**：鼠标移上去（或键盘 Tab 到条目）出卡片，顶部是勾上的标签、下面是详细描述；
  卡片用 `position: fixed` 跟着条目跑，上下左右都夹在视口里，顶不下就翻到条目下方。
  **既没标签又没描述的条目不会弹卡片**（不弹一个空框）。
- **手机**：没有 hover 的设备上点一下先出卡片，卡片已经开着再点同一个才跟着链接走。
- **链接**：填了 `href` 的条目渲染成 `<a>`（站内自动加 base，站外自动 `target=_blank`），点一下真的跳过去。
- **空图退回**：一条层级都没有时，这一页退回显示「冰室冰山」面板里传的那张大图 + 介绍 + 「继续看」链接
  （也就是这一页以前的样子），不会摆一张空页面出来。首页那块卡的链接现在默认指到 `/iceberg/`。

>  保证以后冰山变长了也是越往深特效越明显」

（前半句是「整体风格改成和其他页面一样 背景加上运动的栅格线」，后来用户纠正：参照物是
**冰室精华那一页**、线是**首页背景上那种**。第一版做成了浅色 + 方格线，整个改掉。）

**① 观感 = `/salon/` 那一套（深紫底）+ 首页那条扫描线（方向反过来）**

- 底色 `#1e0730`、`body` 带 `is-board` —— 页头页脚和 `/salon/` 同一套（它自己又是从「隰辰煦家」量出来的）；
- 层级卡片 = 那页的「深紫渐变玻璃块」：`linear-gradient(rgba(46,8,70,.78), rgba(20,3,34,.78))`
  + `1px solid rgba(255,120,190,.42)` + 左边 3px 粉线 + 14px 圆角，大标题纯白 + 粉色外发光；
- 背景那层线**就是首页 `.vapor__scan` 那张 8×32 的内联 PNG**（暗线 `rgba(0,0,0,.22)`，每 4 CSS px 一条）、
  同样的周期 16px 与速度 1.1s、同样 `image-rendering: pixelated`，只把方向反过来：
  首页 `background-position-y` 走 `0 → +16px`（往下），这里走 `0 → -16px`（**往上**）。
  实测 14.5px/s，连续 8 次采样 y 每次都更小；
- 动 `background-position` 而不是 `translateY`：位移交给合成层会被双线性重采样、硬边糊掉
  （首页那段注释里写过，照抄）；底下多留一格（`inset: 0 0 -16px 0`）所以循环处不露白边。

**这条"像不像"是量出来的**：验收脚本会去 `/salon/` 把那一套数值取回来逐项比 ——
底色、玻璃块渐变串、粉边两色与宽度、圆角、标题色与发光 —— 全部**逐字节相等**才算过。

**② 条目文字色：分类色本身，有标识的按标识底微调**

深紫底上分类色本身就读得清（亮色压在深底上），所以没有标识的条目**直接用分类色**。
有标识的那条，字压在「分类色的半透明覆盖」上（比卡片亮），构建期就按那个底把亮度提一点点 ——
两个方向都只推亮度（HSL 里二分，色相和饱和度原样保留）。实测 88 条全部 ≥ 4.5:1（最差 4.55:1），
色相最大只偏 **0.2°**，调过的那些看起来还是那一类的颜色（例：花娅奇闻 #ff5fb0 → #ff68b4）。

> 为什么不混色：混色会把色相带跑 —— 灰蓝 #9aa7c7 混深棕之后偏了 **53°**（实测过），
> 看起来就不再是那一类了（第一版就是这么写的，被验收脚本量出来）。

**③ 完备标识 = 地图上那颗「区域图钉」的头**

地图上的图钉（`PageContent.astro` 的 `.pmap__pin--region`）是「24×24 的圆头 + 横向格栅 +
竖向渐变 + 下面一个小箭头」。完备标识就是**把那颗头单独拿出来**：

| 图钉（地图） | 完备标识（冰山图） |
| --- | --- |
| `mask: repeating-linear-gradient(180deg, #000 0 2px, transparent 2px 3.2px)` 横向格栅 | `repeating-linear-gradient(180deg, rgb(255 255 255 / .22) 0 1px, transparent 1px 3.6px)` 同款横向格栅 |
| 固定的落日渐变（黄→橙→红） | **跟着分类色**：`color-mix(in srgb, var(--cat) 12%/26%, transparent)` 两段 |
| 下面有一个指向地图的小箭头（`::after` 三角） | **没有**（`::after` 不存在，实测 `content=none`、边框 0） |
| 24×24 的方头 / 圆头 | **拉长成圆角矩形**：比条目左右各宽 11px，实测 251×33px、圆角 9px、宽高比 7.61 |
| 实心 | **微微半透明**：`opacity: .85`（两段本身也是带 alpha 的 `color-mix`） |

`color-mix` 用的是 **`in srgb` + `transparent`**（不是混白）：色相一点不偏，而且和构建期
`utils/iceberg.ts` 的 `overColor()` 是同一个合成公式 —— 两边对得上，不会
「CSS 画一个色、算文字色时按另一个色」。实测 5 个有标识的分类，标识底色色相与各自分类色的偏差都是 **0°**。
标识底**故意取淡**（真实压在卡片上的量 = 26% × 0.85 ≈ 22%）：底越实，压在上面的字就得提得越亮，
条目就不再是分类色了。这一档下文字几乎不动，标识本身仍看得出是那一类的颜色（还有白栅格与一圈光晕）。

**④ 电视信号失真那一层（VHS）**

用户要的第三个效果：「屏幕上会偶尔隐隐出现类似电视信号失真的雪花屏 彩色格 扭曲等
随着页面下翻越到冰山深处的条目 这种特效越明显」。四层叠在内容**上面**（`z-index:30`、`pointer-events:none`）：

| 层 | 是什么 | 怎么做的 |
| --- | --- | --- |
| 雪花屏 | 真噪点（不是一块灰） | 一张 293 字节的 SVG `feTurbulence` 内联成 base64 当背景贴图（220×220 平铺），`mix-blend-mode: screen` |
| 彩色格 | RGB 子像素那种竖条纹 + 细横格 | 两条 `repeating-linear-gradient`（红/绿/蓝各 1px 一段、周期 4px）+ `screen` |
| 扭曲 | 三条横向撕裂带 | 每条 `backdrop-filter: blur(2px) saturate(1.7) hue-rotate(8deg)` —— 真的把底下的画面糊掉；`steps(2)` 的左右抖动动画，三条错开高度（实测 top 189 / 477 / 693px） |
| 亮带 | 老电视那条 hum bar | 22vh 的白色渐变，7.3s 从下往上滚一遍 |

强度 = `--ibk-deep` ×（0.16 常驻 + 0.84 偶发爆发）：

- `--ibk-deep` = 滚到哪了 / 还能滚多少（0 → 1），**按页面比例算，不是按像素**。
  以后冰山图加层加条目，同一屏位置对应的深度不变 —— 验收脚本把 6 层复制一份（页面高从 1368px 变 3127px），
  滚到新的 50% 处 `--ibk-deep` 还是 **0.5**（按像素算只会是 0.25）；
- 爆发是随机的：深处间隔 ≈1.5s、浅处 ≈5s，幅度 `0.35 + 0.65 × deep`，停留 120~700ms。
  实测一进页面（深度 0）它**一直是 0**（4 秒采样 38 次全是 0），滚到最深处 9 秒里捕到 **23 次**爆发、
  最大 opacity **0.88**；
- `prefers-reduced-motion` 时脚本根本不排爆发（扫描线那条动效则被 global.css 的总规则收掉）。

**⑤ 又两处细节（用户接着提的）**

> 「1.冰室冰山页面的大标题冰室冰山四个字看不清 改成适合一点的颜色
>  2.让花娅奇闻 冰室怪谈等分类卡片在屏幕往下滚动时始终保持在屏幕上方 方便点击开关显示」

- **大标题**：深紫底上站里默认那套 `.page-header__title` 用的是 `--c-text`（深琥珀 `#46280f`），
  实测压在 `#1e0730` 上只有 **1.39:1**（等于看不见）。换成和 `/salon/` 大标题同一套：
  纯白 + `0 0 18px rgba(255,79,163,.55)` 的粉光 → **18.6:1**。同一页那行介绍、
  以及"图还是空的时候"的退回文案也一起从深琥珀换成了浅粉白。
- **分类那排吸顶**：`position: sticky`，让开的高度**不写死** —— 站点页头是 sticky 的，
  高度随字号、语言、窗口宽度变（窄到一定程度导航会换行），所以脚本量出来写进 `--ibk-top`
  （桌面 71px、手机 69px，都是"页头高 + 8px"），自己再垫一层
  `rgba(30,7,48,.82)` + `backdrop-filter: blur(10px)` 的药丸底 —— 吸顶时下面压着条目，
  不垫的话字会和条目糊在一起。实测滚到 60% 处它离页头下沿正好 8px、**那个坐标上的元素就是
  小眼睛本身**（`elementFromPoint` 验过没被卡片或 VHS 挡住）、点一下真的能开关那一类（52 条一起翻）。

### 这一轮踩到的十个坑（都记下来）

1. **Astro 的 `class={数组}` 会变成 `class="a,b"`**（不是 `class:list`）。第一版条目的 class 渲染成
   `class="ibk__item,is-done"`，`querySelector('.ibk__item')` 直接查不到 ——
   是验收脚本第 4 条断言把它逮出来的（页面看起来"没错"，但 CSS 的 `.is-done` 全都没生效）。
2. **`<Img>` 外面包了一层 `<picture>`**（`display: contents`）。量头图时 `img.parentElement`
   拿到的是那个 `<picture>`，矩形恒为 0×0 —— 手机上"头图在标题上面"那条断言因此变成了假通过。
   改成量 `.ibk__headImg` 容器才对（340×146）。
3. **构建产物里 `<img>` 的属性顺序是 `src` 在前、`class` 在后**，所以
   `/ibk__bgimg[^>]*src="…"/` 这种正则永远匹配不到。先抠出整个 `<img …>` 标签再取 `src` 才稳。
4. **编辑器「保存并重新构建」有个并发漏洞（这一轮修掉的，也是被验收逼出来的）**：
   保存这条路由的规矩是「先写盘、再构建」，而构建做了去重（「同时只允许一次构建，后来的请求等同一个
   promise」）。于是**十几秒内连着保存两次**时，第二次的请求会并到第一次那轮构建上 ——
   而那轮构建是在第二次写盘**之前**开始的，产物里没有第二次的改动，面板却照样说
   「已保存并重新构建」。表现就是「我明明改了、也提示成功了，刷新页面还是旧的」。
   改法：后来者**排队**（等当前这轮跑完，再跑一轮读得到新数据的），同一个排队里的多个请求共用那一轮。
   复验：`editor-panels-e2e` 里加了「连着两次保存 → 第二次的改动也在产物里」这条断言
   （第一轮 5356ms、第二轮 5324ms，产物里两次的改动都在）；改完 `editor-ui-check` 的
   「面板保存 → 落盘 → 产物里出现新条目」也从"看运气"变成稳定通过。
5. **全站的「成员名自动链接」会钻进冰山图里搞事（已经把 `/iceberg/` 加进跳过名单）**。
   条目名里本来就有成员名（Raw、虹星、隰辰煦、吉吉 —— 9 条），构建期那一步会把这些名字
   包成「悬停浮出名片」的小块。量出来的后果：
   · 层标题的**文字被拆开**：`Raw的纯净服…？这是哪儿` 的 `textContent` 变成
     `RawRaw冰室之主的纯净服…？`（名片那坨 DOM 也进了 `<h2>`，页面上看不见，但纯文本 / 复制 /
     读数全不对 —— 验收脚本第一条就红在这里）；
   · 名字上会**同时冒两张浮层**（成员名片 + 这条的详情卡）；
   · 条目本身是链接时（如「双开门福瑞爸爸狅草」），名片里的链接会**套在条目链接里** ——
     HTML 不允许 `<a>` 套 `<a>`，解析器会把结构拆坏。
   所以 `astro.config.mjs` 里改成 `memlink({ skip: ['/salon/', '/iceberg/'] })`
   （冰室精华页早就是跳过的，理由一样）。想让成员名在冰山图里也能点，把那一项删掉即可 ——
   但上面三条会一起回来。
6. **`getComputedStyle` 里的 `color-mix()` 不是 `rgb()`**。改美术时标识底色用
   `color-mix(in oklab, var(--cat) 34%, #fff)`，取回来一看是 `oklab(0.903 0.070 -0.009)`；
   换成 `in srgb` 之后又变成 `color(srgb 1 0.786667 0.894667)`（0~1 的小数）。
   验收脚本第一版只认 `rgb(\d+, …)`，于是「标识颜色跟着分类走」和「文字读得清」两条断言
   读到的其实是栅格那层的白线和透明黑（`rgba(0,0,0,0)`），色相差 153°、对比度 1.88:1 ——
   全是误报。现在 `parseColor()` 两种写法都认，并且只取**最后一层 `linear-gradient` 的色标**
   （跳过栅格那层的白线 / 透明）。
   顺带：`linear-gradient(180deg, …)` 是默认方向，Chromium 序列化时会把 `180deg` 省掉 ——
   用正则去匹配它必然匹配不到（第一版又栽在这儿）。
7. **「往深里混」会把色相带跑，「只降亮度」不会**。浅底上分类色读不清，第一版是把分类色
   往深棕里混到 4.5:1 —— 亮粉 / 亮蓝还行，灰蓝 `#9aa7c7` 的色相直接偏了 **53°**（量出来的），
   看起来就不再是「我所在之城的怪事」那一类了。改成在 HSL 里只压 L（H/S 原样二分），
   色相最大偏差 **0.9°**，对比度照样全部达标。
   还有一个更隐蔽的：`badgeBg()` 的"混多少白"和 CSS 里那条渐变**写反了**
   （JS 按"混 72% 白"算文字色，CSS 是"72% 分类色"）—— 文字看起来没问题，
   实际只有 3.47:1，也是被对比度这条断言逮出来的。
8. **Astro 编译后那条 `> *` 的权重比单类名高**。VHS 那三条撕裂带我写成
   `.ibk__vhsTear { inset: auto 0 }` + `.ibk__vhsTear--a { top: 21% }`（0-2-0），
   而父规则 `.ibk__vhs > *` 编译成 `.ibk__vhs[data-astro-cid] > [data-astro-cid]`（0-3-0），
   里面的 `inset: 0` 直接把三条带子的 `top` 全压成 0 —— 三条叠在屏幕顶上。
   验收脚本量到三个 top 都是 `0px` 才发现。改成 `.ibk__vhs > .ibk__vhsTear--a`（0-4-0）就好了。
9. **`overColor()` 那个方向差点又写反**。标识底是「分类色 26% 盖在卡片上」，
   而 `mixColor(cat, card, 0.22)` 是「22% 的卡片色」—— 第一版写成后者，
   标识底几乎全是分类色，文字被迫提亮成**纯白**（色相都没了）。
   现在两个函数名字就分开：`mixColor`（线性插值）/ `overColor`（按 alpha 铺在底色上）。
10. **算文字色要按"最不利的那一头"取底色**。卡片是渐变，条目可能落在层的最上面
   （最亮那一档）—— 第一版 `CARD_BG` 取的是渐变中段，弹设往事那条算出来压在真底上只有 **4.26:1**。
    另外验收脚本里量滚动位置必须用 `behavior: 'instant'`：全站 `scroll-behavior: smooth`，
    平滑滚动时"滚完立刻读"读到的是**上一格**的值（实测 0/25/50/75/100% 读成 0/0.18/0.38/0.58/0.85）。

用户最早提的死条件是**不要挤压或挪动原来已有的首页元素**，后来又加了这一轮的要求（原话）：

> 冰室冰山的左侧对齐花娅陌域的左侧 每日精华的右侧对齐花娅陌域的右侧

> 花涧堂logo 没有下方这些可以点击的卡片 在屏幕下方加小字：点击进入花涧堂

两条要求合起来的意思：**上边那屏（页头 / 徽记 / 落日 / 天际线）一个像素都不许动**，

这条边界是量出来的，一条命令能重跑（它自己从 `git` 现场导出"改动前"的源码、单独构建再逐项对比）：

```

```

### 封面 + 大翻页（`#home-cover` / `#home-boards`）

- **封面**：`.cover` 自己撑满"一屏减去封面顶边"再多伸 40px（`--cover-top` 由页面脚本量，
  没脚本时 `7rem` 兜底）。徽记还在原来的位置，多出来的是一片背景 —— 所以第一屏只有
  落日城市 + 花涧堂徽记，**五张卡片全在折线以下**（实测最近的一张顶边在 951px，视口 900px）。
- **底部小字**「点击进入花涧堂」：`position: sticky; bottom: 1.3rem`，所以封面在屏幕里
  它就贴着屏幕下沿，封面滚过去自己消失 —— 这个行为**不需要 JS**。它本身是个 `<a href="#home-boards">`，
  没 JS 时就是普通页内锚点（照样能进），有 JS 时接管成一次平滑的大滚动（落点让开吸顶页头）。
- **上方小箭头**：`position: sticky; top: 页头高 + 0.5rem` 而且 `height: 0` ——
  不占任何排版空间，只在卡片区还在屏幕里的时候浮在顶上（封面那一屏看不到它）。
  点它滚回 0，回到欣赏页。
- 状态（该显示小字还是箭头）由 body 上的 `is-cover` / `is-cards` 两个类控制，
  按"封面滚掉了多少"切换；`prefers-reduced-motion` 时滚动改成瞬移。
  箭头默认是**藏着**的（CSS 里就藏着），进了卡片区才亮 —— 这样脚本还没跑到那一瞬间不会闪一下；
  没 JS 时"进去"那一步照样能用（页内锚点），只是不会出现那个箭头。
- 实测（桌面 1440×900）：点小字 → 滚了 **863px**（一屏 900px 的大滚动），两个大板块 + 三张小卡
  **同时都在屏幕里**、小字淡出、箭头亮起；点箭头 → 回到 0、小字回来、箭头藏起、卡片又都在屏幕外。
- 实测（手机 390×844）：点小字 → 滚 **829px**、大板块顶边停在 75px 处、箭头出现；
  点箭头 → 回 0、卡片又都不在屏幕上、小字回来。
- **别的屏幕比例也逐个量过**（不只 1440×900）：1920×1080 / 1600×900 / 1280×800 / 1024×768 /
  1280×620（矮屏）/ 900×900（窄桌面）—— 每一种都是"一进页面卡片全在折线以下"（最近的卡片顶边
  比视口底还低 49~60px），四句对齐要求也都成立，且 0 横向溢出。

### 三张小卡的重排

列定义和大板块那一行**完全一样**（同一个容器宽度 + 同样的 `13%` 列间距），
所以"对齐"是网格自己保证的，不是拿眼睛对：

| 要求（用户原话） | 实测 |
| --- | --- |
| 日历在甬城晴雨下方、和它一样宽、比较扁 | 日历 `206~658`、宽 **452**（= 甬城晴雨 452）；高 **244**，高/宽 = **0.54** |
| 冰室冰山左侧对齐花娅陌域左侧 | 冰室冰山 `x=794`，花娅陌域 `x=794` |
| 每日精华右侧对齐花娅陌域右侧 | 每日精华右边 `1246`，花娅陌域右边 `1246` |
| 冰室冰山和每日精华和日历一样高 | 三张都是 **244px**，顶边都是同一行（405） |

日历从"随宽度长的方块"改成"圆圈直径按屏幕宽度给一个小值"（`--cal-cell`，桌面 26px /
手机 24px）：卡片宽了一倍多，格子再按 `aspect-ratio` 跟着长的话会变成 452×450 的大方块。
三张卡都用 `height: 100%` 撑满同一行，所以"一样高"是网格保证的，不是写死数值。

顺带修掉一个**读不清**的老问题：这三张是深色卡，可文字还在用浅色主题的令牌 ——
每日精华正文实测对比度只有 **1.35:1**（深琥珀压深紫，几乎看不见）、时间/星期/更多 2.34:1。
现在逐个换成深色底上的颜色，实测 14~16:1。

### 日历（在「甬城晴雨」正下方）

最常见的那种月历，但**"今天"和"当前月"一律在浏览器里算** —— 站点是静态的，
构建那天算出来的"今天"过两天就错了。所以格子由页面脚本生成，构建期只把
事件表（`calendar.events`：`日期 -> {title, href, text}`）塞进去。

- 每一天是一枚**小图钉头**，画法和**地图里那两种图钉完全同一套**

  | | 长什么样 | 和地图里对应的 |
  | --- | --- | --- |
  | 普通日 | 粉色渐变（`#ffd9ef→#ff9ad5→#ff4fa3→#a80058`）+ **方头 8px** + 横向格栅 + 粉色投影 | `.pmap__pin--building` |

  特殊日那张的边是暖橙。文案：

  | | 那句话 |
  | --- | --- |
  | 普通日 | 就写这一天：`2026-09-01` |
  | 特殊日 | `{名字} {填的那个日期}`，例如「桑芙的生日 2003-08-30」 |

  ⚠ 以前特殊日写的是「2026-08-30 桑芙的生日（填的是 2003-08-30）」——
  用户原话「太赤裸太丑了」，所以不再把后端那串原样端出来。
  ⚠ 这两条样式必须**整条**写进 `:global(...)`：`.cal__tip` 和 `.cal__day` 都是脚本拼出来的，
  写成 `:global(.cal__day:hover) .cal__tip` 的话后半截仍然被作用域加上属性选择器，一个都命不中
  （表现是"卡片有、皮也对，但怎么指都不出来"——这一轮真踩到了）。

- ⚠ **事件按"月-日"匹配，年份不参与判断**（编辑器「日历」面板里那句提示承诺的就是这个）。

  现在建了一张「月-日 → 事件」的表：同一天有好几条时，优先取"正好写的是今年"的那条。
  实测：数据里只写 `2004-09-20`，今天（2026-09-20）那一格照样亮成区域图钉，
  右下角小框也写「今天是验收用的纪念日」。
- ⚠ **永远按 6 行占位**（`grid-template-rows: repeat(6, var(--cal-cell))`）：

  单条事件还可以用 `text` 完全自定义。
  ⚠ 卡片下边距留 **2.75rem** 就是给这个小框的位（框高约 28px + 离底 0.65rem ≈ 38px）：
  小于它，最后一排图钉会压在框上（实测踩过：下边距 2.1rem 时网格底边比框顶边低 6px）。
- 上/下月的小箭头可以翻月（翻月只是换格子，事件表不变；卡片高度也不变）。
- 复验：`node tools/checks/home-calendar-check.mjs` → **23 项**（含"只写 2004 年那一天也要亮"

### 每日精华

标题「每日精华」本身就是链接（进 `/salon/`），标题下面随机抽一条精华展示：
**成员头像 + 成员 + 时间 + 内容（文字或图片）**。

**整张卡也是一个链接：点它直接跳到冰室精华页里那一条的位置**（用户要求：
「每日精华增加一个跳转功能 点击每日精华就会直接跳转到精华页里这句精华的位置」）。
地址就是 `/salon/#<那条精华的 id>`（精华页每条都带 `id`，那边本来就有 hash 深链接：
`:target` 闪一下高亮 + `scroll-margin-top` 让开吸顶的页头和搜索栏）。
客户端重挑了一条之后，`href` 和 `aria-label` 也跟着换（见组件里那段脚本）。

> ⚠ 这里有个坑：全站 `html { scroll-behavior: smooth }` 对**片段跳转**也生效，
> 而精华页有 30 万像素高 —— 从首页点过来时浏览器会从顶部"平滑"滚过去，
> 实测滚 3 秒还差 **2870px** 没到（等于没跳到）。所以精华页加载完之后会把落点
> **直接做掉**（`scrollIntoView({behavior:'instant'})`，并且字体/图片到位后再钉一次）。
> 实测现在落在那一条上、顶边 147px（视口 900px），`:target` 高亮也在。

"每天一条"是这么做的：构建期按**构建那天**先渲染一条（不跑 JS 也看得见、搜索引擎也抓得到），
页面脚本再用**访问者当天**的日期从 `/salon.json` 里重挑一条 —— 同一天固定不变、隔天自动换，
### 随机精华（2026-09-22 加的）

用户原话：

> 「在首页每日精华旁边加一个按钮 样子是循环符号 右边写"随机精华" 点一下按钮以后会随机抽取
>  一条精华显示 显示规则和每日精华一样 如果当前显示的是随机精华 那么页面上会再多一个按钮
>  样子是左箭头 右边写回到每日精华 也就是随机出来的精华有两个按钮 一个是随机精华
>  可以继续随机 一个是回到每日精华 可以回到今天系统抽取的精华」

「每日精华」那块上面多了一排按钮（两个都在卡片那个 `<a>` **外面** —— 卡片整张是链接，里面不能放按钮）：

| 按钮 | 长得什么样 | 什么时候在 |
| --- | --- | --- |
| **⟳ 随机精华** | 循环符号（带弧线的 SVG）+ 这四个字 | 拿到 `/salon.json` 之后一直在（连点＝接着抽） |
| **← 回到每日精华** | 左箭头（纯直线 SVG）+ 这六个字 | **只在"现在显示的这条不是今天那条"时出现**，点了回到今天系统抽的那条 |

- 抽的是 `/salon.json` 里**全部 784 条**（不是"今天那条"的邻域），显示规则和每日精华**完全一样**：成员头像们 + 名字 + 时间 + 正文（有图就带图），整张卡照样链到 `/salon/#<这一条 id>`；
- 连点会**避开当前这条**（`items[idx].id === curId` 就往后挪一位），所以点一下一定有变化；
- 没有 JS / 拿不到 JSON 时整排按钮**藏着**（`hidden`），不给一个点了没反应的按钮；「回到每日精华」初始也是 `hidden`，由脚本按状态开关；
- **那颗按钮显不显示，看的是"现在显示的是不是今天那条"（比 id），不是"点没点过随机"** ——
  用户后来补的要求：「如果当前显示的已经是每日精华了 就不要显示回到每日精华按钮 只有在显示随机精华的时候需要这个按钮」。
  所以万一随机正好抽到今天那条，按钮也会藏起来（那会儿没什么可"回去"的）；
- 两个按钮都是真 `<button>`（键盘 Tab + 回车能按，图标 `aria-hidden`，名字走 `aria-label`）；
- 这一排按钮让那块卡片在**窄桌面**（900px，卡片只有 150px 宽）上要换两行，所以尺寸按"两行也尽量矮"给（字号 0.7rem、行高 1.35、上下 padding 各 0.1rem）—— 首页那三张卡是"一样高"的，这一块高 9px，日历也跟着高 9px：实测 900×900 下日历 **364×253（69.5%）**，仍在"扁平"那条线（70%）以内。

> **⚠ 交付第一版没生效，原因值得记一笔**：JS 里 `btnBack.hidden = true` 确实设上了，
> 但 CSS 里 `.daily__act { display: inline-flex }` 是**作者样式**，压过浏览器自带的
> `[hidden] { display: none }` —— 属性藏了、按钮还在屏幕上（用户原话：
> 「功能并没有生效 今天的每日精华上方还是有回到每日精华按钮」）。补一条

## 文章封面：点进去之前就看得见

## 图片：一条构建期管线（多尺寸 + AVIF/WebP + 模糊占位）

站点里的图就是 `public/` 下那些原文件。**原图不再直接发给浏览器** ——
构建前会跑一条图像管线（`tools/images/optimize.mjs`，用 sharp），给每张图生成：

- **多尺寸 WebP + AVIF**（400 / 800 / 1200 / 1600 + 原始宽度那档，写到 `public/img/opt/`）；
- **一张 20px 宽的 LQIP**（约 120 字节，inline 成 data URL），当模糊占位；
- 一份 `public/img/opt/manifest.json`，渲染层照着它发 `<picture>` / `srcset`。

渲染层是 `src/components/Img.astro`（`<img>` 的地方）和 `src/utils/images.ts`
里的 `bgStyle()` / `coverUrl()`（`background-image` 的地方）。有几点是刻意的：

- **`width`/`height` 一定带上** —— 浏览器提前把位置留出来，图到之前不跳（CLS）。
- **模糊占位垫在真图下面**（多层的 `background-image`，或 `<img>` 自己的背景），
  图没到时先看到那张糊图，真图一解码完直接盖住它，**全程不需要 JS**。
- **首屏的卡片封面用 `image-set` 按 DPR 挑档**：桌面拿 400 档（约 11KB），
  手机拿 800 档。这条写在 `@supports` 里，认不出 `image-set` 的浏览器
  退回单张的 `--cover`，不会因为一条声明作废而白掉。
- **不带透明通道的图才有 LQIP**：带 alpha 的图（徽记之类）垫糊图会从透明区域透出来。

### 怎么跑

```
pnpm build        # = node tools/images/optimize.mjs && astro build
pnpm images       # 只跑图片管线
node tools/images/optimize.mjs --report   # 只报数：每张原图 → 各档多少 KB
node tools/images/optimize.mjs --force    # 全部重编（改了 CFG 里的质量/档位就该跑一次）
```

管线是**增量**的：清单里记着源文件的大小 + mtime + 配置版本，没变过的图直接跳过。
所以编辑器里「保存并重新构建」通常几十毫秒就过；只有第一次（或改配置、`--force`）才需要重编，27 张图全量约 22 秒（本机实测）。

产物（`public/img/opt/`）**不进仓库**（见 `.gitignore`）：它是构建产物，每张图会多出四五份，提交进去仓库要翻好几倍。CI 上 `pnpm build` 会现生成。

> 🔧 一个已经修掉的坑（2026-09-20，独立验收时量出来的）：`optimizeAll({ only: [...] })`
> —— 编辑器上传图片走的就是它 —— 以前会**无条件**把清单整个换成"这一次编的那几张"。
> 于是「上传一张新头像」会把清单里其余两百多张的记录一次抹掉，后果有两个，都量过：
> 紧接着的那次构建找不到缓存、把那些图全部重编（**45.1s**，正常 **4.6s**）；
> 而且在下次构建跑完之前，那些图因为 manifest 里查不到而退回原图发。
> 现在只编一张时是**合并**（`manifest.items = only ? { ...prevItems, ...next } : next`），
> 只有整库跑（`only === null`）才按盘上现有的文件重建、顺手清掉已删图的记录。
> 回归检查在 `tools/checks/editor-panels-e2e.mjs`（副本里真传两张图，量清单条数）。

## 字体：切成 28 片按需下载

全站用的汉仪文黑子集化之后还有 **1040 KB**，而单页正文其实只用得到几百个字。
`src/styles/fonts.css` 现在把它切成 **28 片**，每片一条 `@font-face` 并带自己的
`unicode-range`，浏览器只会下载页面上真出现过的字所在的那几片：

- 首页 / 归档 / 文章页实测都只下 **3 片（约 113 KB）**，省掉 89%；
- 覆盖没有缩水：所有分片 `unicode-range` 的并集 = 母本的全部 6949 个码位
  （GB2312 全覆盖保留），以后写新字也不会掉回系统字体；
- 分片顺序按**站点真实用字频率**排（第 1 片是最常用的 300 字），
  所以任何一页都必然要第 1 片 —— `BaseLayout.astro` 里 preload 的就是它。

母本 `public/fonts/huajiantang.woff2` 保留在仓库里（不再被页面引用）。
换字体或改分片粒度就重跑 `tools/fonts/slice_font.py`，报数看 `tools/fonts/report.mjs`。

## 音乐：每个网页一个歌单

在编辑器「音乐」面板里给某一页上传音乐，那一页就会自动播它 —— 顺序是**随机轮播**，
另外可以指定一首**「进入这一页一定第一首播」**的歌（不指定就随机起一首）。

### 数据与页面 key

一份数据 `src/data/music.json`：`tracks` 是曲库（`id` / `title` / `src`），
`pages` 把曲库里的 id 按页面分组。页面 key 由地址推导，构建期算一遍（`src/utils/music.ts`）：

| key | 是哪一页 |
| --- | --- |
| `home` | 首页 |
| `list:posts` / `list:notes` / `list:archive` / `list:tags` / `list:friends` / `list:about` | 六个列表页；`/tags/某标签` 也归 `list:tags` |
| `board:<板块地址>` | 大板块树里的页面，例如 `board:yongcheng`、`board:yongcheng/a` |
| `entry:posts:<文件名>` / `entry:notes:<文件名>` | 文章 / 手记详情页 |
| `*` | 所有页面通用歌单（某页自己没有歌单时用它） |

不用逐页传参：`BaseLayout` 拿当前地址去查这张表，查不到就一层层往上退（所以每个标签页
自动用「标签」那条歌单）。整张表也会导出成 `dist/music-pages.json`，编辑器的页面清单
就是照它核对的（两边都是 40 条：通用 1 + 首页 1 + 列表 6 + 板块 24 + 文章 6 + 手记 2）。

音频文件放在 `public/audio/uploads/`（`public/` 会被原样发到线上），编辑器上传时按
`日期-随机-原名` 命名并限制 40MB / 只收 mp3、m4a、aac、ogg、oga、opus、wav、flac。

### 上传的音乐自动压成 128kbps

用户传上来的多半是 320kbps 的原盘：**一首 8MB**。手机上光一首歌就等于把整页图片的流量
再翻一倍，"页面加载很慢"就是这么来的。现在上传时会自动转成 **128kbps**（约 3MB/首）：

| 文件 | 压前 | 压后 | 码率 |
| --- | --- | --- | --- |
| YUNG BAE - Fly With Me | 7.83MB | 3.04MB | 329 → 128kbps |
| 澄净羽之颂 - 李箱被我玩喷了 | 8.29MB | 3.16MB | 336 → 128kbps |
| 澄净羽之颂 - 终焉寻常之人 ～叁 | 7.56MB | 2.87MB | 338 → 128kbps |

三首合计 **23.7MB → 9.1MB**；实测同一页"页面 + 音频"总共只从服务器取 **3.3MB**
（压缩前光音频就 8MB）。压完的时长、采样率、声道数都没变，解码零错误
（187.88→187.92s、199.38→199.42s、206.88→206.90s；RMS 差 5% 以内）。

实现是 `tools/audio/optimize.mjs`（和图片那条管线一个路子）：

- 只用了两个**纯 JS/WASM 小包**（`mpg123-decoder` 解码、`@breezystack/lamejs` 编码，
  一共不到 1MB，`pnpm install` 就能复现，不下载任何平台二进制）。WAV（16bit PCM）
  自己解个 RIFF 头也能压。
- **幂等**：源文件码率已经 ≤150kbps 就跳过 —— 有损格式反复编码只会越来越糊，
  所以重复上传、重复跑脚本都不会二次损伤，也不会白等。
- **只在更小的时候替换**，写临时文件再 `rename`，中途失败不会留下半个坏文件；
  压缩失败也不影响上传（原样保存，提示里说明原因）。
- 编辑器上传完会顺手刷新 `src/data/music.json` 里的 `bytes`，压缩结果直接显示在提示里
  （「已压缩 7.83MB → 3.04MB」）。

```bash
node tools/audio/optimize.mjs            # 扫 public/audio/uploads 全部压一遍（幂等）
node tools/audio/optimize.mjs 某个.mp3   # 只压指定文件
```

> 原始文件是**原地替换**的（仓库历史里还留着压前那份）。你自己电脑上的源文件不受影响；
> 想换档位就改 `tools/audio/optimize.mjs` 顶部的 `TARGET_KBPS`。

### 跨页面：怎么做到「不重头」又「不炸耳朵」

静态站是多页的，`<audio>` 会随页面卸载一起死掉；真正的无缝续播要把整站改成 SPA ——
对这个站来说风险太大。这里走的是**存档 + 淡入淡出**：

1. **点站内链接的那一瞬间**就知道下一站会不会播同一首歌：每页在 `__MUSIC_DATA__` 里
   内联了两张小表（「别的页面各自认领的第一首」+「地址 → 页面 key」，共几 KB），不用发请求。
2. 于是分三种走法（实测值，用真点击量的「点击 → 真正离开」）：

   | 情况 | 处理 | 实测 |
   | --- | --- | --- |
   | 下一站认领的第一首 = 正在播的这首 | **什么都不做**，让浏览器正常跳转，歌一直响 | **12ms** |
   | 下一站认领的是别的歌 | 短淡出 0.26s，到站后新歌淡入 0.75s | **278ms** |
   | 下一站没认领第一首 / 根本没有歌单 | 长淡出到静音 0.9s | **911 / 919ms** |

3. 播放进度写在 `sessionStorage`（只在本标签页有效）。到站后如果**这一页认领的第一首
   正好是刚才那首**，就按存档里的进度接着放，还会补上跳页耗掉的那点时间。
   实测：离开时 `t=5.85s` → 到站后 `t=7.55s`（中间隔了约 1.8s），**没有回到 0**。
4. 音量与静音写在 `localStorage`，换页、刷新都还在（实测拉到 30% 后刷新仍是 30%）。
5. 浏览器的自动播放策略经常拒绝新页面直接出声。被拒就把音量键标成「待启动」，
   在用户第一次按下鼠标 / 键盘时补一次 `play()`。

### 自动播放：浏览器到底允许什么（实测）

**结论先说：`element.click()` / `dispatchEvent()` 这种"合成假点击"没用**，浏览器只认
**真实手势**（真人按下的鼠标/键盘/触摸）。用户提过"进页面时在空白处造一个假点击让它自动播放"，
这条路在浏览器安全模型下是走不通的 —— 下面是这台机器上 Chromium 153 的实测：

| 试法 | 结果 |
| --- | --- |
| 新页面直接 `play()`（有声） | ✗ `NotAllowedError: play() failed because the user didn't interact with the document first` |
| 把它设成 `muted` 再 `play()` | ✗ 同样被拒（新版 Chrome 连静音自动播放也拦） |
| 新建一个 `<audio muted>` 再 `play()` | ✗ 同样被拒（不是元素状态的问题） |
| **`document.body.click()` 之后再 `play()`** | ✗ 依然被拒（假点击拿不到 user activation） |
| **真鼠标点击之后** | ✔ `navigator.userActivation.isActive === true`，`play()` 成功 |

所以播放器能做的是"把真实手势的影响放到最大"，同时**不白白下载**：

1. **点哪儿都能起播**：页面任意位置按下鼠标 / 按键 / 触摸，播放器都补一次 `play()`
   （音量键和音量条当然也算）。滚动、悬停不算手势，浏览器不给放。
2. **按钮自己给指引**：没出声时音量键右下角冒一个 ▶ 并轻轻呼吸，`title` 写成
   「点一下开始播放 · 曲名」。（早先版本还有一条常驻的「♪ 点一下播放」小胶囊，
   按用户要求去掉了 —— 按钮上的角标已经够，不需要更啰嗦。）
3. **缓冲时才提示**：真的在等数据时，音箱按钮**正下方**弹一个白框写「缓冲中…」
   （和音量条同一摞、竖着叠，不会互相压住；出声就收掉）。
4. **能自动就自动**：每次进页面都先试一次带声音的 `play()`；如果你在这个站上点过东西
   （浏览器记的是整个域的交互），后面的页面往往就能自己放起来。某些浏览器允许静音
   自动播放，代码里也留了这条路（先静音放着，你一动手立刻出声）。

### 按需加载：一首歌 8MB → 3MB → **进页面 0KB**

用户反馈"还是要加载很久"。真正的元凶不是码率，而是**一进页面就把整首歌下完了**：
`preload="auto"` 加上浏览器拦掉自动播放之后，实测整首 **3MB 照样被闷头下完**
（页面自己的 HTML/CSS/字体/图加起来才 0.38MB）。网页音乐播放器（网易云那一类）
的做法是**按需 + 边放边下**，这里照做：

| 做法 | 效果（实测 390×844） |
| --- | --- |
| `preload="none"`，进页面不接音频源 | 未点击时音频下载 **0.0KB**，整页合计 **378KB**（改前 3.27MB） |
| 自动播放被拒就 `pause + 清 src + load()` 掐掉这次请求 | 不会替用户白下几 MB |
| 真按下再 `src` 接回去（并回到原定进度）播放 | 实测第一下点音量键即出声（音量 0.7），进度正常 |
| 一首 128kbps（原来是 320kbps 的 8MB） | 单首 3.0~3.2MB，边放边下 |
| 等数据时按钮下方弹「缓冲中…」 | 限速 80KB/s 实测：点击后 0.7s 白框出现、`readyState=0`，4s 后已在播、白框自动收掉 |

> 断过就必须接得回来：`attachSource()` 负责重新设 `src` 并按 `pendingResume` 定位，
> 所以"拒绝自动播放 → 掐掉下载 → 用户点击 → 立刻出声"这条链路是通的
> （实测三下音量键：0.7 → 0 → 0.7；只按音量条也能起播）。


> **顺带修掉的 bug**：以前"第一下点音量键"会把它刚刚起播的音乐**顺手静音**
> （实测点完 `volume=0`、按钮变成"已静音"），用户只会觉得"点了更没声音、坏了"。
> 现在按下去之前如果本来就没在放，这一下点击的语义是"开始播放"，不会再切静音；
> 已经在放时才是静音开关（实测三下：0.7 → 0 → 0.7）。
> 另外只拖音量条也会主动起播，避免"拖了没反应"。

### 右上角那颗音量键

挨着「回到顶部」那颗塔吊键（实测三个按钮 x = 1072 / 1122 / 1172；皮完全一致：
同一个 `.corner__btn`，深色首页 `rgba(38,4,52,.72)`、浅色页 `#fdf7fb`，24px 图标）。
图标就是网页上最常见的那只**音箱**：箱体 + 朝右张开的锥口 + 两条音量弧线
（音量过 55% 两条都亮）+ 静音时划一道斜杠。

> 早先是按用户要求画的一把古筝（筝身 + 四根弦），用户反馈"样式不太对，直接改成音箱吧"，
> 于是换成了通用音箱。`.vol__str`（弦）那条样式也一并删了。

- 点一下静音、再点一下恢复（`aria-pressed` 跟着变，实测音量 0.7 → 0 → 0.7）；
- 鼠标移到按钮上滑出音量条（`--c-accent` 配色的 range），滚轮停在按钮上也能微调；
- `title` 里带着正在播的曲名（例如「音量 70% · 某曲」）；
- **这一页没有歌单时按钮根本不出现**（默认 `hidden`；没有歌单的页面上播放器脚本不输出，
  也就没人摘掉它）；抽屉拉开时和塔吊键一起收起来（音乐照放）。

> 一个踩过的坑：`src/music/player.js` 是被 `?raw` 读成字符串**原样内联**进 `<head>` 的，
> 所以里面**不能出现「闭合 script 标签」那几个字面字符** —— HTML 解析器会在那里提前把
> `<script>` 收掉，后半段代码全变成页面上的文字，控制台只报一个
> `SyntaxError: Invalid or unexpected token`，页面上看起来"音乐就是没反应"。
> `MusicPlayer.astro` 里加了构建期检查，再写就直接构建失败。

## 五、写内容

### 用编辑器（推荐）

双击 `花娅陌质流.cmd`，点 **写文章**，浏览器会打开 `http://localhost:4322`。

### 填日期：直接敲数字，不用点日历

「日历」面板里那些特殊日子、「精华」面板里每条精华的日期，都是**能直接敲数字的文本框**
（和时间轴那套用同一个控件）：

| 你怎么填 | 结果 |
| --- | --- |
| 敲 `20260604` | 边打边补横杠 → `2026-06-04` |
| 敲 / 粘 `2026-6-4`、`2026/6/4`、`2026年6月4日` | 都认，并规范成 `2026-06-04` |
| 敲完按回车或点别处 | 才写进数据；读不出来（比如 `2026-13-45`）会**标红**，不写坏数据 |
| 想翻日历 | 点右边那个 **📅** —— 不点它永远不会弹出来 |

以前这里是系统原生的日期控件，一聚焦就弹日历，一天一天翻很烦（用户原话：
「日历页面的时间可以和时间轴一样直接输入数字 不要展开日历点」）。
时间轴那边的日期框多一个「实时」开关（存哨兵 `today`：永远显示今天、每天自动变），
日历 / 精华是固定日期，所以那两个地方没有这个开关。

一条命令复验（真编辑器 + 真浏览器，跑在**副本**里，不碰工作区数据）：

```
node tools/checks/editor-datefield-check.mjs      # 15 项：敲字自动补横杠、落盘、标红、时间轴那个「实时」开关还在
```

### 怎么往文章里插图片

三种方式，挑顺手的用：

| 怎么做 | 结果 |
| --- | --- |
| **直接拖**一张图到正文区 | 自动上传，在光标处插入图片 |
| 截图后按 **`Ctrl+V`** | 自动上传，以时间戳命名（不会一堆 `image.png` 撞名） |
| 点工具栏的 **🖼** | 打开文件选择器，选完自动上传并插入 |

三种都会把文件存到 `public/img/uploads/`，并在正文里写好 `![说明](/img/uploads/文件名.png)`。

工具栏上还有个 **「网址」** 按钮，用于插入已经在网上的图片，或者站内已有的图片路径
（比如 `/img/a.png`）。

> 单张图片不能超过 10MB，先压一下再传。支持 png / jpeg / gif / webp / svg。

### 手写文件

在 `src/content/posts/` 下新建 `随便什么名字.md`，文件名就是网址。
开头必须有 frontmatter：

```yaml
---
title: 标题            # 必填
date: 2026-09-14       # 必填，也可以写 "2026-09-14 20:30"
tags: [标签一, 标签二]   # 可选
summary: 列表页的摘要    # 可选，不写自动从正文截
cover: /img/uploads/a.png # 可选，封面图
draft: false           # 可选，true = 草稿，不发布
pinned: 0              # 可选，大于 0 会置顶
subs: [huaya-a-1]      # 可选，归到哪个子版块（填 home-boards.json 里的 id）
---
```

手记（`src/content/notes/`）的字段稍有不同，多了 `week`（周次）和 `mood`（心情），
没有 `summary` / `cover` / `pinned`；`subs` 一样有，所以手记顶部也有那条来路。

**`subs` 决定这篇文章归在哪个版块下**，填了之后它会出现在那个版块页的
「这里的文章」里；同时文章顶部会自动出现一条来路面包屑
（`花娅陌域 › 陌质流记忆库 › 测试性流质酶 › 这篇文章`），
点其中任意一级就能跳过去 —— 不用再靠浏览器后退键。
一篇文章可以同时填多个 id，那样顶部会有多条来路，一行一条。
填的 id 在 `home-boards.json` 里不存在时会被忽略（只会少一条面包屑，不会报错）。

版块页之间也一样：每层左上角的「返回」回的是**上一级**（并写出上一级的名字），
只有顶层大板块才回首页。

**字段写错了构建会直接报错**，不会悄悄写坏——这是故意的。

## 七、常见问题

**构建报错说某个字段不对**
按提示改 frontmatter。最常见的是日期格式，或者 `tags` 忘了写方括号。

**图片不显示**
路径要从 `public/` 开始算。`public/img/a.png` 对应的写法是 `/img/a.png`。

**推送失败**
先看是哪种。`花娅陌质流.cmd` 选 **3 发布上线** 时，会先试连 GitHub，连不上会直接提示，不会等 push 到一半才报错。

- **连不上 GitHub**：国内网络直连经常不通，需要开代理。开好 Clash Verge 的「系统代理」后，
  再让 git 也走代理（只需设置一次）：
  ```bash
  git config --global http.proxy http://127.0.0.1:7890
  git config --global https.proxy http://127.0.0.1:7890
  ```
  端口要和 Clash Verge 里「设置 → 端口」一致。取消用 `--unset` 换成同样的键名。
- **提示没登录**：跑一次 `gh auth login` 重新授权。
- **提示 `without workflow scope`**：`gh` 授权时默认不给 `workflow` 权限，而推送
  `.github/workflows/` 下的文件需要它（GitHub 防止代码偷偷改你的 CI）。补权限：
  ```bash
  gh auth refresh -h github.com -s workflow
  ```
  在浏览器里确认后再推。这个设置一次就够了。
- **提示 rejected / non-fast-forward**：远端有本地没有的提交，先 `git pull --rebase` 再推。

> 小提示：`github.com` 打不开时，`api.github.com` 和 `raw.githubusercontent.com` 往往是通的。
> 「网页打不开」不等于完全连不上。

> 另一个提示：走代理访问时偶发 `EOF` 之类的瞬时中断很常见。遇到一次失败**先重试**，
> 不一定是真的坏了——本项目的部署脚本就内置了自动重试。

**想换整体风格，但不想大改 CSS**
主要改 `tokens.css` 里的颜色和字体就够了。想换版式再动 `global.css` 里的【组件样式】区块。

**想删掉「手记」这个栏目**
1. 删掉整个 `src/content/notes/` 目录
2. `src/pages/` 下删掉 `notes/` 目录
3. `src/site.config.ts` 的 `nav` 里删掉手记那一行
4. `src/content.config.ts` 里删掉 `notes` 集合的定义和导出

<summary>站点本身是怎么实现的（想改代码时看）</summary>

- **构建**：Astro 静态生成，输出纯 HTML/CSS，几乎没有 JS。
- **内容**：Astro Content Collections + `glob()` loader，schema 用 Zod 校验。
- **样式**：原生 CSS + CSS 自定义属性，没有引入任何 CSS 框架。
- **前端脚本**：只有两处——① 页头里一小段内联脚本，在页面绘制前把主题定下来（避免闪白）；
  ② 文章页目录的滚动高亮（IntersectionObserver）。除此之外没有客户端 JS。
- **代码高亮**：构建期用 shiki 生成，亮色/暗色两套配色同时输出，切换主题不需要 JS 参与。
- **站点图标 / og 图**：手写的 SVG。
- **编辑器**：零依赖的 Node HTTP 服务（`tools/editor/server.mjs`），只监听 `127.0.0.1`。
