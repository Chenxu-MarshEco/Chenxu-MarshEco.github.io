# 本地内容编辑器

一个跑在自己电脑上的可视化内容编辑器，用来写 `src/content/posts`（文章）和
`src/content/notes`（手记），以及站点里那些**由 JSON 驱动**的内容：
首页大板块（`src/data/home-boards.json`）、导航分类库（`navs.json`）、
时间轴（`timelines.json`）、歌单（`music.json`）、排版微调（`layout.json`）、
首页那四块（`home-widgets.json`：日历 / 关于我 / 冰室冰山 / 每日精华）
和冰室精华（`salon.json`：年代 / 成员 / 精华）。
不用登录、不用联网、不用装任何依赖，本质就是一个很小的本地网页。

## 启动

```bash
pnpm editor          # 等于 node tools/editor/server.mjs
pnpm post            # 等于 node tools/editor/server.mjs --open=new-post，顺手新建一篇
```

或者直接：

```bash
node tools/editor/server.mjs          # 启动，手动打开终端里打印的网址
node tools/editor/server.mjs --open   # 启动后自动打开系统默认浏览器
```

启动后终端会打印完整地址，形如 `http://127.0.0.1:4322/`。

服务只监听 `127.0.0.1`，外网访问不到。端口从 4322 开始，被占用就依次试
4323、4324……直到 4340；实在都被占了会直接报错退出。

## 界面

三栏布局：

- **左栏**：文章 / 手记两个标签页；搜索框（按标题和标签实时过滤）；文档列表
  （标题、日期、草稿标记、标签）。鼠标悬在列表项上会出现删除按钮，删除会二次确认。
  底部是「＋ 新建」。
- **中栏**：frontmatter 表单 + Markdown 正文。标题、日期（可选到分钟）、标签
  （回车或逗号变成 chip）、摘要、封面（可上传本地图片，**也能从 QQ 直接拖进来 /
  Ctrl+V 粘进来** —— 见下面「图片怎么进来」）、草稿开关、置顶（文章）；
  周次、心情（手记）。正文上面是一排 Markdown 工具按钮。
  **封面图文章和手记都能设**（`content.config.ts` 里两边都有 `cover`），
  它就是列表里显示的那张图；正文里插的图片不会被当封面。
- **右栏**：Markdown 实时预览，输入停止 200ms 后刷新。

上传图片时**压缩在服务端做**（`tools/images/optimize.mjs` 里的 `compressUpload()`）：
JPEG 走 mozjpeg q82、长边限 1920、按 EXIF 摆正、去掉元数据；PNG 走最高压缩级别；
webp 重编 q80；gif / svg 原样不动（动图和矢量图不该重编码）。
落盘之后立刻把这张图送进图片管线，生成 WebP/AVIF 多尺寸和模糊占位，
所以**刚传的图当次构建就是优化过的**。压前压后的字节数会回给前端，
提示里报的是真实数字（例如「图片已压缩后上传：4.2MB → 480KB」）。

> 2026-09-18 之前是在浏览器里用 canvas 预压（`shrinkImage()`，转 JPEG q0.82）再上传。
> 那条路去掉了：canvas 的编码器比 mozjpeg 差一截，而且服务端会再压一遍，
> 等于同一张图连压两回 —— 画质掉两回、体积还更大。现在原图直接传
> （localhost 上多传几 MB 无所谓），压缩只在服务端做一次。

其他细节：

- `Ctrl+S` / `Cmd+S` 保存，右上角也有保存按钮，成功后会弹一个小提示。
- 有未保存的修改时，浏览器标题前面会出现 `●`，关页面会提示。
- 表单一变就把草稿写进 `localStorage`；重新打开同一篇时会问要不要恢复。
- 主题跟随系统，也可以在右上角手动切成 浅色 / 深色 / 自动（记在 localStorage）。
- 完全离线：不加载任何外部字体、图片或 CDN。

## 图片怎么进来：拖进来 / 粘进来 / 选文件

**不用先存到电脑再挑文件了。** 从 QQ、微信、截图工具里截一张图，
可以直接 **拖进编辑器**，或者 **Ctrl+V 粘进去**（QQ 截图默认就在系统剪贴板里）。
这三条路（拖 / 粘 / 点按钮选文件）最后都汇到同一个 `uploadImage()`
（`tools/editor/ui/app.js`），上传、压缩、多尺寸变体都只有一份逻辑。

**能在哪儿拖 / 粘：**

| 地方 | 落点 | 一次多张 |
| --- | --- | --- |
| 文章 / 手记的**封面图** | 封面那一整块（缩略图 / 上传按钮 / 地址框） | 只收第一张 |
| 「插入图片」**弹窗** | 「从本地文件上传」那一格 | 只收第一张 |
| 页面里的**地图**换图 | 那一行的缩略图 + 按钮 | 只收第一张 |
| 页面内容里的**图片块** | 那一行的缩略图 + 按钮 | 只收第一张 |
| 页面内容里的**文字块**（Markdown） | 那个文本域 | **全收**，一次插多行 |
| 版块 / 子版块 / 导航 / 页面的**标题图（图标）** | 缩略图 + 按钮 | 只收第一张 |
| **关于我**的圆形头像 | 那一行的缩略图 + 按钮 | 只收第一张 |
| **冰室冰山**的图 | 那一行的缩略图 + 按钮 | 只收第一张 |
| **成员**的头像 | 那个人卡片上的缩略图 + 按钮 | 只收第一张 |
| **精华**一条里的图片 | 「＋ 加图片」那一格 | **全收**，一张一个格子 |
| **正文**（Markdown） | 正文编辑区 | **全收**（本来就是老功能） |

单值的地方一次拖进来多张：**用第一张**，并提示「只收一张图，用了第一张，另外 N 张忽略了」。
多张的地方（正文、文字块）一次全传、依次插进去。

**粘贴给谁 —— 按这个优先级挑**（`resolveImageIntake()`，都在 `app.js` 的
「图片接入口」那一节）：

1. **粘贴时事件 / 焦点落在哪个上传点里**（光标停在「封面图地址」输入框里、
   或者刚点过某一格的「换图片」按钮）→ 给它；
2. 否则看**最近一次点过 / 聚焦过的**那个上传点，只要它所在的面板还开着、还看得见 → 给它；
3. 否则，**当前打开的面板里只有一个可见的上传点** → 给它
   （打开「独立页面」面板直接粘封面走的就是这条）；
4. 焦点在**正文编辑器**里 → 照旧插到光标处（老行为一点没变）；
5. 还是不知道给谁 → 弹一句人话：「先点一下『上传 / 选图片』那个按钮，再按 Ctrl+V」，
   **不会静默吞掉**。

剪贴板里**只有文字 / HTML** 的时候这一层完全不插手（一个字节都不拦），
输入框里粘文字照旧。粘贴进来的图如果叫 `image.png` 这种没营养的名字，
会自动改成 `粘贴-20260920153000.png` 再传。

**拖拽反馈**：拖到能收图的范围上，那一块会亮起虚线框（`.intake--dragover`，
和正文编辑区那个 `editor__area--dragover` 是一套配色），松手前就知道会落到哪儿。

> 别和「按住内容卡片的把手拖着重排」搞混：那是**另一套**（自己写的 pointer 事件，
> 只在卡片头上那个 `⠿` 上生效，不碰 `dataTransfer`）。拖图片进来 = 上传，
> 拖把手 = 换位置，两者互不干扰 —— 见下面「页面」工作台里
> **「内容块：插在指定位置 / 按住把手拖着重排」**那一节。

**从网页 / QQ 窗口拖链接**（兜底）：`dataTransfer` 里没有文件、但有
`text/uri-list` 或 `text/html` 里的图片地址时，就把这个地址**当地址填进去**
（封面地址框 / 弹窗的地址框 / 地图或图片块的 src），不下载、不落盘；
抠不出地址就当没这回事，不硬来。

**提示语在哪儿**：封面那一块和「插入图片」弹窗里，按钮下面有一行小字
「可拖入图片，或 QQ 截图后 Ctrl+V」；页面 / 版块那些小格子地方窄，
只挂在按钮的 `title` 上（鼠标停一下就能看到），不铺满屏幕。

**加一个新上传点**：注册一行就行 ——

```js
attachImageIntake({ el, input, label: '封面图', onFiles: async ([file]) => { … uploadImage(file) … } });
```

`el` 是接入口的范围（拖拽高亮、落点判断都按它算），`input` 是那个兜底的
`<input type=file>`（它的 `change` 由这一层统一接管，点按钮那条路一个字节都没变），
`onFiles` 拿到文件后自己决定往哪个字段写。还有 `multiple`（能不能收多张）、
`onUrl`（拖进来的是链接时怎么办）、`hint` / `title`（提示语）、
`countsForPaste: false`（不参与上面第 3 条兜底 —— 页面里的文字块用它，
否则「面板里只有一个上传点」那条就永远不成立了）。

## 工作面与左上角总入口

编辑器里能整块干活的地方一共十三个：**文章 / 手记、页面、独立页面、子版块、导航、
时间轴、音乐、排版**，加上后加的五块 —— **日历、关于我、冰室冰山、精华、成员**
（见下面「首页那几块 + 冰室精华」）。左上角那个 **「☰ 工作台」** 按钮就是总入口 ——
点开是一张清单，点哪一项就**直接切到那个工作面**（该开的面板打开、该铺的数据铺好），
不用「先关掉这个再打开那个」。顶栏那几个老按钮也走同一条路：切过去之前
会先把别的面板收起来，所以不会再出现两个面板叠着的情况。

每个面板顶上还有一条 **「切换」** 小按钮（十三个工作面 + 「关闭面板」），
所以在独立页面面板里能一步跳到导航或时间轴，反过来也一样，不用先关面板。
面板是从顶栏下面开始铺的 —— **顶栏（含总入口、保存、预览、主题）在面板开着的时候照样点得到**。
后加的五块**没有顶栏按钮**（顶栏已经挤满了），入口就是总入口清单和这条「切换」条。

### 草稿保护：切走再切回来，没保存的改动还在

各工作面的改动都只活在内存草稿里（`boardsDraft` / `timelinesDraft` /
`navsDraft` / `musicDraft` / `pageDraft` / 排版 iframe 的 `state` /
`widgetsDraft` / `salonDraft`）。
**「关面板」和「切面板」都只是 `hidden`，不是销毁**；再打开时读的是草稿而不是盘上的旧值。

- **子版块 / 页面 / 独立页面**共用同一份 `boardsDraft`。以前每开一次「子版块」都会
  重新从盘上读一遍，那一读就把另外两个面板里没保存的改动冲掉了 —— 现在有草稿就不重读。
- **页面 / 独立页面**换页之前会先把当前这页没保存的内容块收进它自己的节点
  （`selectStudioPage()` 里那次 `commitPageBlocks()`）；**重新选中同一页时不会再拿
  `node.page` 重读一遍** —— 重复选中是最容易悄悄丢草稿的地方。所以在 A 页改了块、
  切到 B 页、再切回 A，改动照样在。
- **音乐**面板以前每次打开都重新 GET 一次歌单，排好的顺序和「第一首」会被覆盖；
  现在有草稿就不重拉（真想放弃改动，刷新页面即可）。
- **排版**的改动只活在 iframe 里，而关面板会把 iframe 拆掉。现在关面板 / 换页之前
  会把那一类页面的 `state` 收进 `layoutDrafts`，再打开时重新套用；
  和盘上不一致时状态栏会写「有改动，记得保存」。
- **保存成功之后草稿才算用完**：写完盘、重新构建完，面板里显示的就是保存后的值，
  排版那一份草稿也会被清掉。

下面按工作面逐个说：

**「页面」—— 整页编辑（改页面就用这个）**

像写文章那边一样的三栏：

- **左栏**：整棵版块树上的每一页（缩进 + 地址），带搜索框；点一下切过去。
- **中栏**：这一页的全部可改项 ——
  名称 / 副标题 / 地址 / 版式 / 封面图，然后是「这一页的内容」块列表
  （文字、图片、链接、子页面、分隔线、两栏、视频、文章、目录、地图 十种，
  能加能删能上下移，也能**直接插在某一段后面**、**按住把手拖着换位置** —— 见下一节），
  其中**地图**块可以分页，每页各自钉塔吊图钉、拖**区域划分线**；划分线一条一个颜色 ——
  「在这里放：」那一排末尾有「线色」（取色块 + R/G/B 数字框，双向同步），
  先挑色再拖线，画完还能在下面清单里逐条改（颜色只收 `#rrggbb`，服务端会卡格式）。
  每页还有两个容易搞混的文本框，占位符里已经写明区别：
  **图片说明**（`<img alt>`，页面上不显示）和**简介**（多行，会以小一号的字显示在地图下方）。
  列表后面接着是「这一页的子版块」：改名、传封面、比例、档位、**像素宽高**、上下换顺序，
  以及两个新增按钮 —— **＋ 加子版块**（普通子版块，站里会给它生成一页）
  和 **＋ 加链接版块**（填名字 / 封面 / 网址，点它直接跳走，站里不为它建页面，
  网址也不会显示在页面上）。每一行下面那个「链接」输入框随时能把一项在两种之间切换。
- **右栏**：这一页的真实预览（抓构建产物，同源塞进 srcdoc）。
  底下「保存并重新构建」＝ 写 `home-boards.json` + 跑一次 `astro build` + 刷新预览。

### 内容块：插在指定位置 / 按住把手拖着重排

「这一页的内容」里，一块就是一张卡片。想让新内容出现在**中间某处**，
以前只能点底部那排「＋ 文字 / ＋ 图片 / …」（永远加在最后）再一路点 ↑ 挪上去 ——
内容一多就是几十下。现在两条直路：

**① 指定「插到某一段后面」**

- 每张卡片头部最左边有一个 **`＋`**：点它 = **新块插在这一段后面**。
  点完那张卡下面会画出一条提示条「新内容将插到第 N 段后面」，同时
  **底部那排「添加：」下面也会写一行小字**说明现在会插到哪儿 —— 两处都看得见。
- 然后再点底部那排的 **＋ 文字 / ＋ 图片 / …**，新块就落在那条缝上
  （`pageDraft.splice(i + 1, 0, …)`），不是加到最后。
- **连着插几段都落在同一处后面**：插完一次，落点自动往下移到刚插进去的那一块上，
  所以「第 3 段后面加文字、再加图片、再加文字」是一条顺着来的顺序，不用反复点回。
- 插进去的那一块会**滚进视野并闪一下**，一眼看得见它落在哪儿。
- **不要了就取消**：再点一次那个 `＋`，或者点提示条上的「改回插到最后」。
- **不点任何 `＋` 就是老规矩**：底部那排照样加在最后 —— 老习惯一点没变。

**② 按住把手拖着换位置**

- 每张卡片头部最左边是把手 **`⠿`**（在 `＋` 前面）。**按住它上下拖**，
  卡片跟着变半透明，指针下面有一条落点指示线写着「放到这里（第 N 位）」，
  松手就落到那儿（草稿顺序 + 重画 + 状态栏写「有改动没保存」，和点 ↑ ↓ 一样）。
- 拖到列表**上 / 下边缘会自动滚动**（内容多的时候不滚就永远拖不到头），
  线一直跟着更新。
- **拖到一半按 Esc** 或者拖回原地松手，都当没拖过，顺序一点不动。
- **键盘也能换**：点一下把手（焦点在它身上，点一下不会换位置），
  按 **↑ / ↓** 就把这一块往上 / 往下挪一格。
- 原来的 **↑ / ↓ / 删除** 按钮一个不少，行为不变（现在它们和拖拽走同一条路径
  `movePageDraft()`：改草稿 → 标脏 → 重画）。

**③ 跟「把图片拖进来上传」是怎么分开的**

内容区里「从 QQ / 截图工具拖一张图进来」是要**上传**的（见上面
「图片怎么进来」那一节），所以卡片拖动**不能用 HTML5 拖放**（`dragstart` /
`dataTransfer` 那一套）—— 两套拖拽撞在一起，用户拖张图进来可能变成把卡片挪走。
所以：

- 卡片拖动是**自己写的 pointer 事件**（`pointerdown` / `pointermove` / `pointerup`，
  `startPageBlockDrag()` / `onPageDragMove()` / `onPageDragEnd()` / `stopPageBlockDrag()`），
  全程**不碰 `dataTransfer`**，也不调 `preventDefault` 去挡 `dragover`；
- 只有**把手**这一个按钮上挂了 `pointerdown`（而且立刻 `stopPropagation()`）——
  卡片别处（文字块 / 两栏的输入框、链接、下拉框、别的按钮）**一个监听都不加**，
  在输入框里选字、拖选文字照旧；
- 反过来，「拖图片进来上传」「Ctrl+V 粘图」那条路一个字节没动：
  拖一张 PNG 到内容区（图片块那一行 / 文字块的文本域）仍然走
  `attachImageIntake()` → `uploadImage()`，拖到一半也不会触发拖动。

状态和落点都记在 `app.js` 顶部那几个变量里：
`pageInsertAfterId`（显式指定的落点）、`pageActiveBlockId`（最近点过的"当前这一段"，
**只用来高亮，不参与落点计算** —— 免得"刚才在哪儿点过一下"就偷偷改变新块落点）、
`pageDragId` / `pageDropAt`（拖拽中）。**换页 / 关面板会把这些清掉**
（`resetPageBlockPlacement()`）：上一页的插入点不该漂到下一页去 ——
换回来就是"加在最后"的老规矩。

样式在 `style.css` 的「内容块：插到指定位置 / 按住把手拖着换位置」那一节
（`.pblock-edit__grip` / `.pblock-insmark` / `.pblock-dropline` / `.pblock-add__note`）。
落点线是**绝对定位**的（`position: absolute` + `pointer-events: none`）：
让它占布局的话，线一插进去后面的卡片就往下挪，下一次 `pointermove` 算出来的落点又跳回去，
指示线会在两格之间来回抖。

**「独立页面」—— 不挂板块也能建一页（有它自己的编辑窗）**

以前页面**必须挂在某个板块下**才建得出来（「＋ 加子版块」）。有些东西不适合当文章，
也不适合塞进某个板块的子版块列表 —— 那种就用**独立页面**：

- 数据上它就是 `home-boards.json` 里一个**顶层节点** + `"standalone": true`
  （`{ "id": "about", "title": "关于", "standalone": true, "page": [...] }`），
  别的字段和普通页面一模一样。
- **页面照常生成**：地址还是按 id 推出来的 `/<id>/`（也可以在上面那一行「地址」里
  手写一个覆盖它），`/about/` 能直接打开。
- **它不被任何列表收录**：首页那两张板块卡片、右上角目录树、任何页面的「子版块」列表、
  `sitemap.xml` 里都没有它。换句话说**没有任何地方会自动链到它** ——
  只能靠你在别处挂的链接点进来：正文里的 Markdown 链接、**地图图钉**、
  **时间轴的「跳转地址」**、子版块的「链接版块」……都行。
顶栏「独立页面」（或总入口清单里那一项）打开的是**它自己的编辑窗**，三栏：

- **左栏**：独立页面清单 —— 可滚动，标题栏上有**条目数**（`12 个`）和一个
  **搜索框**（按标题 / 地址 / id 实时筛，带 120ms 防抖），每行显示名字 +
  现在的站内地址 + 有几个内容块。点一行就是选中它。行尾「删除」删掉这一条
  （带子版块时二次确认）。上面是「＋ 新建」：填个名字回车就建一条，
  建完立刻选中、名字框是选中的，接着敲字就是改名。
  id 自动生成、**全文件唯一**：名字是英文/数字就直接拿来当 id（填 `about` →
  地址 `/about/`），中文之类留不下就自动给个短 id，之后想换好看的地址在中间栏
  「地址」里手写。**改名不会改 id** —— 地址一变，别处已经粘好的链接就全断了。
- **中栏**：和「页面」工作台**完全同一套控件**（名称 / 副标题 / 地址 / 版式 /
  时间轴 / 封面图，加上「这一页的内容」那十一种内容块和「这一页的子版块」）。
  不是另写了一份，而是同一批 DOM 节点搬过来用的（`mountStudioHost()`）——
  所以两边行为永远一致，`boardsDraft` 也只有一份，在哪边改都一样。
- **右栏**：这一页的真实预览，外加当前的站内地址、「重新构建」「新标签打开」
  和**「复制地址」**（浏览器不给剪贴板权限时会**把地址选中**，按 Ctrl+C 也行）。
- 底下「保存并重新构建」＝ 写 `home-boards.json` + 跑一次 `astro build` + 刷新预览。

「页面」工作台左栏底下原来那一整列独立页面，现在只剩一个入口卡片
（`独立页面 N 个` + 「打开独立页面工作台 ›」）—— 页面一多，一列全是行内输入框
反而更翻不动，编辑都挪进上面的面板里做。

这些页面不会出现在那棵版块树里（它们不在任何板块下）。它们的 id 和板块
共用同一层命名空间。

**「时间轴」—— 编辑右侧那条弧线**

顶栏「时间轴」打开，弹窗是**左边表单、右边实时预览**两列：

- **表单**：选/新建/删除一条轴；名称、左右两侧叫什么历、**默认比例尺**；时间点列表
  （左右 / **时刻·事件·难考据** / 日期（难考据时是位置读数）/ 事件名 / 跳转地址）；时间段列表
  （**挂哪一侧** / 名字 / 起点 / 终点 / 跳转地址）。
  **「默认比例尺」＝ 打开这条轴时一刻度代表多少天**（`tickDays`，1~365，可以填小数）：
  页面上打开时停在滑块正中间，也就是 ≈19 天/格 —— 一条只有两个月跨度的轴用这个值，
  整条轴才一格多高，打开就短得看不清，每次都得自己拖滑块，所以**短跨度的轴记得调小**。
  这一格里：数字框填天数，旁边「天 / 格」；下面那行读数会现算
  「一刻度 ≈ N 天 · 整条轴约几格（跨度 N 天）· 建议 N 天/格」（建议值 = 跨度 ÷ 24，
  让整条轴大约 24 格格完），点「整轴铺满」把建议值填进去、点「默认」清空回到默认。
  **编辑器只做建议，不会自己改你填的值**。**留空 = 不写 `tickDays` = 用默认的 ≈19 天/格**
  （老数据也是这样，过一遍编辑器不会凭空多出这个字段）。填了 1~365 以外的数
  （比如 `0`、`999`）或敲不成数字的，框会**当场标红**并说明「存下去会当作没填」——
  服务端那边是**直接丢掉这个字段**（不是夹到端点：夹了会让人以为填错的值还能用）。
  **时间点分「时刻」「事件」「难考据」三类**：时刻 = 大一些的落日色塔吊 + 大一点的字，
  事件 = 小一号的粉色塔吊 + 小一点的字；这两类功能完全一样（左右、日期、名字、链接都能填），
  只影响页面上的图标和字号。「时刻」是默认值 —— 选它不会往数据里写 `kind` 字段，
  老数据过一遍编辑器也不会多出一堆垃圾。下面三个新增按钮「＋ 加时刻」「＋ 加事件」
  「＋ 加难考据」加出来的就直接是那一类。
  **「难考据」是那种查不到具体日期的往事**（只知道大概发生在哪一段，填不出 `yyyy-mm-dd`）：
  选中它，**日期框、日历按钮、「实时」开关整块收起来**（是没有日期这个选项了，不是禁用），
  那一格换成「位置：62.3%」的读数 + 一个百分数微调框。它的位置存成 `at`
  （0 = 最早、1 = 最晚，落盘时收到 4 位小数），**在右边预览里按住它那个塔吊上下拖就能改**
  （吸附到 1%，拖出边界就停在 0 或 1）；拖出来的塔吊是半透明虚线描边的，
  一眼看出「这个点跟别的不一样」（页面上还会多罩一层电视雪花）。
  切回「时刻 / 事件」时**之前填过的那个日期会还给你**（在内存里记着，不用重填一遍），
  本来没填过就用今天兜底。时间段照样可以拿难考据的点当起点终点。
  数据上：`kind: 'fuzzy'` 的点**没有 `date`**、只有 `at`；别的点只有 `date`、没有 `at`。
  时间段那个「挂哪一侧」有左 / 右 / **两侧都有**三种：同一段年月两边各有各的叫法，
  就加两条、起点终点填一样、各选一侧；两边同名就一条选「两侧都有」。
  时间点和时间段的跳转地址都是可选的，填了页面上那个名字才能点
  （不合规的地址当场标红，服务端也会兜底丢掉）。
- **日期可以直接打数字**：敲 `20230110`，横杠自动补上；`2023/1/10`、
  `2023年1月10日` 粘贴进去也认（全角数字也认）。右边 📅 还是能开系统日历。
  读不出来的写法会把框标红、不写进数据（不会存下 `2023-02-30` 这种）。
- **再右边一个「实时」开关**：打开后这个时间点的日期变成「永远显示今天、每天自动变」
  （存进 `timelines.json` 的是 `today` 这个哨兵值）。开着的时候日期框是禁用的、
  只留一个「每天自动（今天）」的占位；关掉时把你**之前填过的那个日期**还给你，
  本来没填过就用今天兜底 —— 否则这个点会变成「没有日期」，存盘时会被服务端丢掉。
- **保存并重新构建**：存完直接跑一遍构建，不用再去别处点一次。
  存的时候如果服务端丢掉了什么（没名字的点、日期读不出来的点、端点不在了的段 ——
  难考据的点没有日期是正常的，不会被丢），会**明确弹出来告诉你丢了几个** ——
  以前是悄悄少一条，看起来就像「点了一下保存它就没了」。
- **预览**：改任何字段立刻重画 —— 弧线、刻度、时间段带子（带左右偏移和层错开）、
  时刻/事件两种大小的塔吊、哪个点和哪个点会合并成一个塔吊、文字怎么排，一眼看到。
  「难考据」的点按它的 `at` 摆在轴上（不参与「这条轴从哪年到哪年」的范围计算），
  各自一个塔吊、不跟谁合并 —— 每个点都得留着自己的塔吊才拖得动；
  **按住那个塔吊上下拖就改它的位置**（指针事件 + 指针捕获，鼠标和触摸都行，
  拖动时只动这一个点，松手后整块重画一次）。
  同一侧重合的时间段会自动分到不同的层、各用各的颜色（和页面上一致）。
  它按**这条轴自己的默认比例尺**画（`tickDays`，没填就是 ≈19 天/格）——
  改了那个输入框立刻重画，读数也跟着变成「1 格 ≈ N 天」，
  所以作者在编辑器里看到的疏密就是访客打开时看到的；合并和间距跟页面上一致，
  区别只是**一次画完整条轴**（编辑要的是全貌，页面上是滚一屏看一段）。
  带链接的点 / 段在预览里是**虚下划线**，不用挨个翻就知道哪些能点。

**「导航」—— 可复用的分类库**

需要它的理由是用户的原话：「有些条目对应的页面可能既属于 A 大分类又属于 B 大分类」——
A 页的导航可能是「甲 + 乙」、B 页是「甲 + 丙」，甲里那几十条条目只该录一次。
所以这一块和「时间轴」是同一个套路：**先在库里把分类建好，页面里只写引用**。

- 数据在 `src/data/navs.json`，三层：`categories[ 大分类 ] → groups[ 子分类 ] → subgroups[ 细分类 ] → items[ 条目 ]`
  （`_readme` 是那份字段说明，编辑器保存时**原样带过去**）。
  **子分类下面还能再分一层细分类**（比如「友好生物」下面再分「无伤害能力 / 无攻击行为 /
  攻击非玩家 / 条件敌对」，各自挂自己的条目）—— 只做这一层，不再往下嵌；
  一个子分类**可以同时**有直接挂的条目和细分类，两种都会显示
  （页面上先铺直接挂的条目、再铺细分类）。子分类那一行有「＋ 细分类」，
  细分类能改名 / 删 / 上下移，条目编辑和上面完全一样（文字 / 地址 / 图标 / 提示 / 上下移 / 删）。
- 顶栏「导航」打开面板，左中右三栏：
  **左栏**大分类清单（名字 + 条目数 + **被几个页面引用**，能新建 / 改名 / 复制整份 /
  删除 / 上下调序）；**中栏**是选中那个大分类的子分类、细分类和条目 ——
  子分类能新建 / 改名 / 删 / 上下移，条目是「**图标 + 文字 + 地址 + 提示**」，
  图标走 `/api/upload` 传（和封面图同一个控件，只是文案叫图标），
  地址带站内/站外校验（填了个站里没有的 `/xxx` 会标一句「点它会 404」）；
  **右栏**是按页面上的样子画的预览：顶栏分类索引 + 每个大分类一整节（原生 `<details>`，
  可以整节收起/展开）+ 一行一个子分类 + 「图标 + 文字」条目，鼠标停在条目上看得到它要去哪。
- 页面那边：到「页面」工作台的内容块里点 **「＋ 导航」**。块里能**勾选**要用哪几个大分类
  （列的是库里所有分类 + 各自多少条），勾中的按顺序列在下面、可以上下调 ——
  **块里存的只是分类 id 的列表**（`{ type:'nav', cats:[…] }`，外加一个可选的「顶栏文字」），
  **不是条目的拷贝**。
- 所以：**改一次分类，所有引用它的页面一起变**。这也正是「保存并重新构建」放在这个面板里
  的原因 —— 分类库一变，引用了它的那些页面都得重新出一遍。
  页面里的 `cats` 顺序是那一页自己的顺序（同一个分类在 A 页排前面、B 页排后面都行）。
- **删大分类时会先查一遍还有哪些页面在引用它**（按盘上那份 `home-boards.json` 算的），
  把页面名字列出来再确认；删完那几页的导航里就少一节，页面本身不会坏。
- 分类被删掉之后，旧页面里那个 id 会变成悬空引用：编辑器里标红提示，
  但**不会自动删掉**（作者可能先把引用写好、再去库里补分类）；站点那边认不出来就跳过那一节，
  不会因此构建失败。
- **空的分类会原样留着**：先建好大分类 / 子分类、条目以后再慢慢填，这是最正常的工作流 ——
  没有条目、没有子分类都**不算非法**，保存不会把它们清掉。
  真正会被丢的只有**结构非法**的：不是对象、没 `id`、没名字、`id` 撞了
  （另外没文字的条目、不合法的地址也会被丢，保存时会报一句丢了多少）。

**链接可以直接指到页面里的某个标题 / 图片 / 段落**

所有填链接的地方都有一个 **「选位置…」** 按钮（正文的**链接块**、**地图图钉**的地址、
**时间点 / 时间段**的跳转地址、**导航条目**的地址），点开是个小面板：
左边先挑页面（带搜索），右边列出这一页里能跳的位置 —— 标题显示它自己的文字
（比如「桑芙」），内容块显示「（图片）」「（文字）」这种，点一下就自动把地址填成
`/huaya/bingshi/#桑芙` 这种形式，**不用手打中文锚点 id**；面板上还有「清空链接」和「刷新清单」。

- 这份清单是**构建产物** `dist/anchors.json`（站点构建时导出的：标题的 `id` 就是标题文字，
  每个内容块一个 `id="blk-<块id>"`）。所以面板里写着「清单来自上次构建」——
  **刚改过页面内容的话，先「保存并重新构建」再来选**，否则看到的是旧的。
- 没有这个文件（还没构建过）时面板只显示一句提示，不会报错。
- 锚点 id 保存下来就是普通地址的一部分，页面被改过、那个锚点没了也只是跳不到位置，
  不会影响链接本身（站内地址的「点它会 404」检查只看页面路径，不带 `#` 那一段）。

**「排版」—— 微调位置和大小**

点元素选中，**拖动**改位置；拖**右下角的小方块**自由改宽高（左上角不动，像 PS 的变换框）；
下面还有一排数字：**中心点 X / Y（页面像素坐标）、宽、高、缩放**，填了立刻生效，
拖动时数字也会跟着变。

- **每一块版块、每一张子页面卡都能单独选中单独拖**（锚点：`block-<id>`、`kid-<id>`、
  `pg-<块id>`）。以前点两块之间的空白会选到整个网格（`children`），看着就像「全黏在一起」。
- 存下来的是**相对位移（百分比）+ 像素宽高**：位置用百分比，手机上仍按原版式排、不会飞出去；
  宽高用像素，因为「改成 300 像素宽」只有像素说得清，也不像缩放那样把字一起缩小。
- 这里**只能挪和改大小**，加内容要用「页面」。

**「子版块」—— 整棵树的增删改**

大板块自己的名称/副标题/地址；每个版块改名、改地址、`＋下级`、删除、
`移动到…` 换父级（**id 不变**，文章归类靠 id，地址会跟着树变）。
每一行也有个**「链接」**输入框：填了就变成**链接版块**
（卡片照旧，但点它是打开这个网址，站里不再为它生成页面，网址不显示在页面上）——
链接版块是叶子，它的「＋下级」会禁用，「移动到…」里也不会出现它。
每个版块旁边还有**封面图**：传了图，页面上那张卡片就图铺满、微微半透明、名字压在正中；
没传就是一条扁平的名字条，不摆空图位。还有**「版式」下拉**（竖排 / 三列分区）
和**「改这一页」**（直接跳进「页面」工作台）。

**排版微调**（`排版`）：点元素选中，拖动改位置，拖右下角的小方块缩放。
存的是相对偏移和倍数，所以手机上仍是正常布局。
选「大板块页」时会多出一个**「哪个板块」**下拉 —— 板块有很多个（每层版块一页），
得挑一个具体的当样板，否则只调得到第一个大板块。

**「音乐」—— 每个网页一个歌单**

顶栏「音乐」打开一个横过来两栏的面板：**左边是全站页面清单**（按 kind 分组成
通用 / 首页 / 列表页 / 板块页 / 文章 / 手记，带筛选框，有歌单的显示数量徽标），
**右边是选中那一页的歌单**：

- **上传音乐**：`<input type="file" accept="audio/*" multiple>`，逐个流式 POST
  到 `/api/music/upload?key=<页面key>`；每个文件一条提示，失败显示服务端原文。
  上传会**立刻**把文件写进 `public/audio/uploads/` 并记进数据文件，但**要点
  「保存并重新构建」才会出现在网站上**（连续传十几首时不必每首都等一次构建）。
  **服务端会顺手把音频压成 128kbps**（`tools/audio/optimize.mjs`：320kbps 的 8MB
  原盘 → 约 3MB），提示里报的是真实的前后体积；已经压过的会跳过，不会二次损伤音质。
- **歌单行**：标题可就地改；`↑`/`↓` 调顺序；`▶` 用面板底部的试听器放一下；
  「设为第一首」是 radio（外加一个「不指定（随机）」）；「移出本页歌单」。
  这些改动都只改本地草稿，**保存并重新构建**才落盘。
- **曲库**：所有曲目，「加入本页歌单」/「从曲库删除（同时删文件，二次确认）」。

页面 key 由服务端按 `src/utils/music.ts` 那套规则算出来（板块地址照抄
`flattenBoards` 的走法，链接版块跳过）—— 40 条：通用 1 + 首页 1 + 列表 6 +
板块 24 + 文章 6 + 手记 2，和站点自己导出的 `dist/music-pages.json` 逐条一致。
`first` 是「进入这一页一定第一首播」；`list` 里的顺序不是播放顺序，站上是**随机轮播**。

## 首页那几块 + 冰室精华（五个面板：日历 / 关于我 / 冰室冰山 / 精华 / 成员）

站点那边首页新增的那一屏（日历、冰室冰山、每日精华）+ 页头的小圆片 + 三个新页面
（`/about-me/`、`/iceberg/`、`/salon/`）都读**两份 JSON**。这五个面板就是改那两份数据的，
入口只有两个：左上角 **「☰ 工作台」** 和每个面板顶上那条 **「切换」**。

数据分成两组，一组一个文件、一组一份草稿：

| 面板 | 改哪一份数据里的哪一块 | 页面上在哪儿看得到 |
| --- | --- | --- |
| 日历 | `src/data/home-widgets.json` → `calendar` | 首页的日历（在「甬城晴雨」下面） |
| 关于我 | `home-widgets.json` → `about` | 页头左上角的小圆片 + `/about-me/` |
| 冰室冰山 | `home-widgets.json` → `iceberg` | 首页中间那块 + `/iceberg/` |
| 精华 | `src/data/salon.json` → `essences` | `/salon/` 的 735 条 + 首页「每日精华」 |
| 成员 | `salon.json` → `members` | 上面两处显示的名字和头像 |

**改完一定要点「保存并重新构建」。** 数据落盘只是第一步 —— 首页、`/salon/`、
`/about-me/`、`/iceberg/` 都是**构建期**读这两份 JSON 的（`astro build`），
不重新构建的话页面上还是旧的。每个面板底部的「保存并重新构建」＝
写数据文件（先备份 `.bak`）+ 跑一次 `astro build`，和「导航 / 音乐」一个规矩。
构建失败**不算保存失败**：数据已经写下去了，状态栏会写明构建没成功。

### 「日历」—— `home-widgets.json` 的 `calendar`

- **特殊日子表**：一天一张小卡片 —— 日期（原生 `<input type="date">`）、
  **是什么日子**（`title`，如「篠雨的生日」）、**跳去哪**（`href`，可以直接填，
  也可以用「选位置…」挑一个页面里的锚点）、**自定义文案**（`text`，可选）。
  日期能改（改了就换键）、能删（二次确认）、能加（默认给今天；今天已经被占了就给「今天+N 天」）。
- **`idleText`**：今天没有特殊日子时，右下角那个小框写的话。
- **`specialText`**：有特殊日子时的句式，`{title}` 会被换成那天的名字
  （默认「今天是{title}」→「今天是篠雨的生日」）。某一天自己填了 `text` 就不套这个句式。
- **卡片标题**：`title`，默认「日历」。

⚠ 日历显示的是**访问者当天那个月**（格子和"今天"都在浏览器里用访问者本地的表算，
构建期只把事件表塞进去），匹配只看 `YYYY-MM-DD` —— **年份不参与判断**：
写 `2024-06-04` 就是每年 6 月 4 日都会变色。

### 「关于我」—— `home-widgets.json` 的 `about`

圆形头像（走图片接入口，存 `/img/uploads/xxx`）、标题（页头圆片的提示文字，
也是 `/about-me/` 的大标题，**不能留空**）、正文（Markdown 多行文本域，
和文章正文一个写法）、跳转地址（页头那个圆片点一下去哪，默认 `/about-me/`）。
没传头像时页面上画一个带塔吊的占位圆。

### 「冰室冰山」—— `home-widgets.json` 的 `iceberg`

一张图（走图片接入口）、标题（**不能留空**）、一句话介绍（纯文本，不支持 Markdown）、
跳转地址（留空则整块不可点，页面上会写「链接留空，去编辑器里填」）。

### 「精华」—— `salon.json` 的 `essences`

一条精华 = **成员（可以好几个）+ 日期时间 + 正文 / 图片 + 种类**。

数据字段（`src/data/salon.json`）：

| 字段 | 含义 |
| --- | --- |
| `id` | `e0001` 这样的短 id，全文件唯一。时间轴上的 `#e0046` 锚点就是它，**不能乱改** |
| `memberIds` | **成员 id 数组**，顺序 = 对话里出现的顺序。可以是空数组（这条挂不到人，站点显示「未知成员」）。老数据的单个 `memberId` 编辑器也认，保存时归一到数组 |
| `kind` | `text` / `perfect` / `ai`（文字 / 完美对话 / AI 创作）。**只给编辑器看**，站点页面不按它分组 |
| `date` `time` | `YYYY-MM-DD` 和 `HH:MM`（完美对话常常只有日期，`time` 空着） |
| `text` | 正文（纯文本，站点不做 Markdown 渲染） |
| `images` | 图片路径数组（`/img/salon/...` 或 `/img/uploads/...`） |
| `eraId` | 落在哪个年代。**保存时一律按 `date` 重算**，前端填什么都不作数 |
| `ocr` | 「从图片 OCR 出来的」标记。编辑器不显示，但**原样保留** |

- **列表不一次全画出来**：先画 60 行，底下「加载更多（还有 N 条）」一次加 60。
  搜索框按**成员名（任意一个）/ 日期 / 时间 / 正文 / 种类**筛（输入有 120ms 防抖），
  右上角写着「命中 N / 共 M 条」和**三种 kind 的条数分布**（加起来 = 总数，
  一眼能对上「一条都没丢」）。每一行显示：`日期 时间`、成员头像叠着排 + 名字用「、」连、
  正文前 60 字、图片张数 + 落在哪个年代 + 种类小标签，右边是「编辑 / 删除」。
  行里**不放输入框** —— 一行一个输入框不但挤，还会让"每敲一个字就重画整张列表"变成灾难。
- **新增**：勾成员（**可多选**，勾选顺序就是 `memberIds` 的顺序）、日期、时间、正文、
  若干图片（走图片接入口，上传后把 `/img/uploads/...` 追加进 `images`，一张一个格子）、
  种类。新 id 按现有风格生成（`e0001…` 往后接着编）；`eraId` **按日期自动落段**，
  表单上会实时写「落在年代：xxx」。**一个成员都不选也能存**（站点上显示「未知成员」）。
- **编辑 / 删除**任意一条（删除二次确认）。编辑改的是**一份副本**，
  点「取消」不会把那条改脏；成员那格用勾选清单 + 「把已选的排到前面」。
- **`updated` 在保存时更新成今天**。
- **保存时字段白名单**：`id / memberIds / kind / date / time / text / images / eraId / ocr`，
  但**盘上原有的、编辑器不认识的字段会原样带回去**（站点那边以后加字段，
  用户点一次保存不会被洗掉）。顺序也**按原来那份走**，不在这里重排
  （站点 `src/utils/salon.ts` 自己会按日期排）。

### 「成员」—— `salon.json` 的 `members`

17 个人，一人一张卡片：头像（走图片接入口，可清空；留空时页面上画一个带首字的占位圆）、
名字、头像地址、**介绍页**、删除（**会先告诉你有多少条精华会变成「未知成员」**）、
底部「＋ 新增成员」（新 id 照 `mNN-xxxx` 的风格生成，不会和现有的撞）。

**「介绍页」这一栏是"全站自动链接"的地址**（2026-09 加的）：

- 填了之后，构建期会把**全站正文里**出现的这个人名包成一个小块：鼠标悬停浮出
  **头像 + 名字**的名片，点一下跳到你填的地址；留空就只有名片、点不动
  （页面还没做好时就是这个状态 —— 先把名字认出来，链接以后再补）；
- 只填三种值：站内路径（`/members/xxx/`）、`http(s)://` 外链、页内锚点（`#xxx`）。
  别的（`javascript:` 之类）存盘时会被**挡成空串**（这个值最终会写进全站正文的
  `<a href>`，不能从数据这一侧就把可执行协议带进来）；
- **只链成员表里写的名字**：所以旧名（比如「花花」）不在表里，正文里出现多少次都
  不会被链 —— 这正是要的效果。真想链旧名，就在数据里给那个成员加一条
  `aliases: ["花花"]`（面板里没有这一栏，直接在 JSON 里加；会一起被链）；
- **「卡片特效」+「放大图」**（同一张卡上，都是可选的）：
  - **落日**：勾上之后名片上半会画一轮蒸汽波落日（半圆 + 横条 + 粉地平线）；
  - **称号**：名字下面那行小字，例如 Raw 的「冰室之主」；
  - **放大图**：鼠标移到名片头**像上**时，头像会放大成一个方形框显示**整张图**
    （`contain`，不裁）。留空 = 就用头像那张；填了 = 固定显示那张
    （Raw 填的是 `/img/members/raw-zoom.png`，走的是同一个图片接入口，能直接上传）；
- **本地「看效果」也要能看见这个功能**：启动器按 2 跑的是 `pnpm dev`（astro dev），
  而 dev 是按请求即时渲染的、不走构建钩子 —— 所以 `tools/memlink` 除了
  `astro:build:done` 之外还挂了 `astro:server:setup` 的中间件，dev 下也照样链。
  ⚠ 改完 `tools/memlink/` 或 `astro.config.mjs` 要**重启一次「看效果」**才生效；
- **冰室精华页（`/salon/`）整页跳过** —— 那里的名字又多又碎，链上只会碍事；
- 细节（跳过哪些标签、英文名的词边界、怎么关掉）：`tools/memlink/index.mjs` 的头注释；
  验收：`node tools/checks/member-link-check.mjs`。

**成员和精华是"只靠 id 绑定"的 —— 这是这一块最关键的一条：**

- 精华里**只存成员 id（`memberIds` 数组）**，名字和头像只在 `members` 表里存一份；
- 编辑成员时**只改 `members`**、编辑精华时**只写 id**，
  两边都不在精华里冗余名字 / 头像（服务端写回时也是按字段白名单挑的，
  前端就算多传一个 `name` 上来也不会写进 `essences`）；
- 站点渲染时是**现查成员表**的（`src/utils/salon.ts` 的 `memberName()` /
  `memberAvatar()`），所以在这里给某个人**改个名字 / 换张头像，他名下所有的精华
  ——包括首页那条「每日精华」—— 全都跟着变**，一条都不用改；
- **「名下 N 条精华」是按 `memberIds` 里包含这个人算的**，不是相等判断 ——
  一条精华挂两个人，两个人名下都算这一条。所以面板顶上写着
  「名下条数合计 X 次（一条精华挂 N 个人就算 N 次）· 至少挂到一个成员的精华 Y / 共 Z 条」：
  第一行用来核"没丢东西"（X = 所有人的挂载次数之和），第二行是去重后的条数；
- **改了要保存 + 重新构建才看得到**（页面是构建期渲染的）。保存之后
  「精华」面板里那一行的成员（名字 + 头像）会**就地**跟着刷新，不会把你的滚动位置和
  "加载到第几条"重置掉；
- 成员被删掉时，引用他的精华在站点上显示成**「未知成员」**（精华本身不会消失）——
  所以删除前的确认框里会写清「影响 N 条」。

控制台里还有两个验收用的把手：`window.__openWs(id)` / `window.__activeWs()`
（模块作用域里的 `openWorkspace()` 从外面叫不到，自动化测试要用）。

## 依赖说明

服务端主体是零依赖的，只用 Node 内置模块（`node:http` / `node:fs/promises` /
`node:path` / `node:url` / `node:crypto` / `node:child_process`），Node 20 以上都能跑。
唯一的例外是**音乐压缩**：上传音频时会动态 `import` 两个纯 JS/WASM 小包
（`mpg123-decoder` 解码、`@breezystack/lamejs` 编码，见 `tools/audio/optimize.mjs`）——
用的是动态 import + try/catch，所以没装（或没网装）也不会影响编辑器其它功能，
只是上传的音频不压缩，提示里会写明原因。

Markdown 预览用的是项目里的 `marked`（如果装了的话）。装了就用，没装也不会报错——
预览区会显示「未安装 marked，预览不可用」，编辑和保存一切照常。想要预览就：

```bash
pnpm add -D marked
```

## 文件与接口

- 文章目录：`src/content/posts/*.md`，对应集合 `posts`
- 手记目录：`src/content/notes/*.md`，对应集合 `notes`
- 上传的图片：`public/img/uploads/`，页面里引用 `/img/uploads/xxx.png`

接口都返回 JSON：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/bootstrap` | 站点信息 + 内容类型列表 |
| GET | `/api/list?type=posts` | 该类型的文件列表，按日期倒序 |
| GET | `/api/item?type=posts&file=x.md` | 单个文件的 frontmatter 与正文 |
| POST | `/api/save` | `{ type, file, frontmatter, body }`，`file` 为空则按标题生成文件名 |
| POST | `/api/delete` | `{ type, file }` |
| GET | `/api/boards` | 整棵版块树（`src/data/home-boards.json`） |
| POST | `/api/boards` | 写回整棵树（字段白名单收一遍，先备份 `.bak`） |
| GET | `/api/layout` | 排版微调数据（`src/data/layout.json`） |
| POST | `/api/layout` | 合并写入排版微调数据 |
| GET | `/api/preview?path=/huaya/` | 代理本地预览服务（4321），绕开跨源 |
| POST | `/api/build` | 跑一次 `astro build`（同时只跑一个，返回耗时和日志尾巴） |
| POST | `/api/upload` | `{ name, dataUrl }`，返回 `/img/uploads/...` |
| GET | `/api/music` | 歌单数据 + 全站页面清单（`pages[]`）+ 单首上限 |
| POST | `/api/music` | `{ music }`：清洗后写回 `src/data/music.json` 并构建；返回 `dropped` |
| POST | `/api/music/upload?name=&key=` | 请求体是**原始音频字节**，边收边写盘（超 40MB 中止并删半截文件） |
| POST | `/api/music/remove` | `{ id, deleteFile }`：从曲库和所有歌单移除，可选删文件 |
| GET | `/api/widgets` | 首页四块数据（`src/data/home-widgets.json`，含 `_readme`） |
| POST | `/api/widgets` | `{ about?, calendar?, iceberg?, daily? }`：**逐块 merge**（没带的块原样保留），写回并构建；返回 `dropped.events` |
| GET | `/api/salon` | 冰室精华（`src/data/salon.json`：`title/updated/note/eras/members/essences`） |
| POST | `/api/salon` | `{ members?, essences? }`：**逐块 merge**，写回并构建；`updated` 刷成今天；`eraId` 一律按日期重算；返回 `counts` 和 `dropped` |
| GET | `/vendor/marked.js` | 转发 `node_modules/marked/lib/marked.esm.js`，没装则 404 |

## 安全边界

虽然只是本地工具，该拦的还是拦：

- `type` 只接受 `posts` / `notes`；`file` 只接受纯文件名（`basename`），出现
  `..`、路径分隔符、绝对路径、控制字符一律 400；解析出的绝对路径必须落在对应内容目录内。
- 保存新文件时如果按标题生成的文件名已存在，返回 **409**，不会静默覆盖已有文章，
  同时给出一个可用的替代文件名（`xxx-2.md`）由前端确认。已有文章（`file` 指向的
  就是它自己）照常可以覆盖保存。
- 上传只接受 `image/png`、`image/jpeg`、`image/gif`、`image/webp`、`image/svg+xml`，
  单张上限 10MB；请求体上限 12MB，超了返回 413。
- 音频只接受 mp3 / m4a / aac / ogg / oga / opus / wav / flac，单首上限 40MB
  （流式写入，超限会把半截文件删掉）；落盘名是 `日期-随机-清洗过的原名`，
  路径分隔符、`..`、控制字符都会被清掉；歌单里的 `src` 只收 `/audio/uploads/...`
  这种站内路径。静态放行也只开 `public/audio/` 下 `uploads` 这一层、只放行音频扩展名。
  mp3 / wav 落盘后会压成 128kbps（压不动就原样留着，不影响上传）。
- 静态资源是白名单映射，不做目录遍历。

## 目录结构

```
tools/editor/
├── server.mjs      # HTTP 服务端：API + 静态资源 + 端口探测（零依赖）
├── ui/
│   ├── index.html  # 三栏界面结构
│   ├── app.js      # 前端逻辑（无构建步骤，浏览器直接跑 ES 模块）
│   └── style.css   # 样式，颜色集中在 CSS 变量里
└── README.md
```

改完 `ui/` 里的东西，刷新浏览器即可生效（服务端对这些文件禁用了缓存）。
改 `server.mjs` 需要 `Ctrl+C` 后重新启动。
